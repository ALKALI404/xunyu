# 来源标注改「按令牌判定」——设计稿（2026-10-25，未动代码）

> 目标：`〔来源：主人亲发〕/〔来源：本体代传〕` 不能由调用方自报，只能由**它拿的是什么凭据**决定。
> 本文只出设计，不含实现；实施要重启桥接（明天窗口批）。

---

## 一、现在为什么能伪造

桥接 `/api/dsh/say` 里这一行：

```js
const sourceTag = body.origin === 'relay' ? '〔来源：主人亲发〕' : '〔来源：本体代传〕';
```

`origin` 是**请求体字段**，谁调谁填。中继（窗口）填 `relay`，QQ 侧 MCP 不填——这是约定，不是校验。
所以本体只要在调用时带 `origin:'relay'`，就能让自己被标成「主人亲发」。

**已经做到的**：正文里出现的 `〔来源：…〕` 字样会被转义（`〔来源(已转义)：…〕`），所以本体不能在正文里"写"一条假标注。
**没做到的**：`origin` 字段本身。

---

## 二、方案：两个令牌，二选一

| 凭据 | 谁能拿到 | 判定 |
|---|---|---|
| **relay 令牌**（新） | 只有中继进程（读本地 `state/relay-origin.token`） | `〔来源：主人亲发〕` |
| **agent 令牌**（现有 `x-agent-token`） | 本体 / 任何二代会话 | `〔来源：本体代传〕` |

判定顺序：**先看 relay 令牌，命中即亲发；否则一律代传**（默认最保守，没令牌 = 代传）。

```js
// 桥接 /api/dsh/say
const relayOk = tokenEq(req.headers['x-origin-token'], await readRelayOriginToken());
const sourceTag = relayOk ? '〔来源：主人亲发〕' : '〔来源：本体代传〕';
// body.origin 不再参与判定；为了兼容保留字段但忽略
```

中继侧只需在 `/chat` 那条投递上加一个 header（`relay.mjs` 的 `bridge()` 封装里加即可，约 5 行）。

## 三、密钥存哪？（这是要主人拍板的点）

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A. `state/relay-origin.token`，桥接启动时生成，relay 读文件**（推荐） | 和 `console-token` 同一套路；轮换随桥接重启；relay 已有「被拒后重读令牌」的逻辑 | 桥接重启后 relay 第一次请求会 401 再重试一次 |
| B. 写进 `config.json` 固定值 | 简单、不随重启变 | config 会被频繁改，值容易泄漏到备份/日志；且本体能读 config（它本来就能读） |
| C. 复用现有 console-token | 不用新文件 | console-token 权限面更大（能调控制台 API），混用等于给 relay 开更大的口子 |

**推荐 A**：文件权限 0600（Windows 上用 ACL 限到当前用户），桥接每次重启轮换，relay 每请求读一次（relay 的 `readTokens()` 已经是每请求模式）。

⚠️ 关键约束：**本体能读到这个文件吗？** 如果本体和桥接跑在同一个 Windows 用户下，它能读——那就等于没设防。
真正要防的是「本体被诱导去冒充主人」，不是「本体有恶意」。所以这一步只抬高门槛（需要主动去读那个文件并带上 header），配合审计日志（记录每次 relay 令牌的使用）就够；要做到密码学级别，需要一个本体拿不到的通道（例如只在窗口进程内存里持有的令牌），那是另一个量级的改造。

| 项 | 落点 | 说明 |
|---|---|---|
| 令牌生成 | `bridge.js` `loadOrCreateRelayOriginToken()` | 读/生成 `state/relay-origin.token`（64 hex），启动时生成、不随重启轮换（读得到就沿用） |
| 判定函数 | `bridge.js` `isRelayOrigin(req, body)` | 只认请求头 `x-origin-token`（也接受 body.originToken 兜底）；比较用 `crypto.timingSafeEqual` |

| 开窗 | `/api/dsh/delegation-window` | `grantRole` 与 `delegateGrant.by` 改用令牌判定 |
| 批审批 | `/api/dsh/approve` | `approveRole` 与 `fromWindow` 改用令牌判定 |
| 中继侧 | `relay.mjs` `bridge()` | 每个请求读一次 `state/relay-origin.token`，带 `x-origin-token`；读不到就不带（最坏退化成代传，不会错标亲发） |
