## 二、怎么重新启用（哪天要「外部禁止提权」）

1. `config.json` → `dshShout.delegateGate` 改成 `"on"`；
2. 重启桥接（杀进程，`start.bat` 5 秒内拉起）；
3. 用 owner 码的入口：窗口 `source=window` 或控制台带 `x-delegate-code`（`state\delegate-owner.code` 里的值）；
4. 想连「agent 代批」一起收紧：`/api/dsh/approve` 会重新要求「owner 授权 + 代批票据」两把钥匙，票据在 `GET /api/dsh/pending` 的 `grant.id`。

回退（恢复放开）：`delegateGate` 改回 `"off"` + 重启桥接，或直接换回备份里的 `bridge.js`/`config.json`。

## 三、能力边界（必须照实说，别当认证）

| 冒充者 | 能不能伪造「主人亲发」 | 原因 |
|---|---|---|
| QQ 群友 / 陌生人 | **不能** | 他们只能发文本；标注由桥接按入口通道生成，正文里的同名标注会被转义成 `〔来源(已转义)：…〕` |
| 本体通过 `qq_dsh_say` 工具 | **不能** | 该工具没有 `origin` 参数，走 MCP 通道恒为「本体代传」 |
| 本体用 shell 直接 curl 桥接 | **能** | `origin` 目前是**请求体字段**，拿到 agent token 就能自称 `relay` |
| 本机任意同用户进程 | **能** | 令牌文件在盘上（同用户可读） |

**要真正堵住后两行**，需要（本次未做）：
1. 给 relay 发**独立令牌**，桥接按令牌判来源，彻底不再读 `origin`；
2. 或者把「谁点的通过」做成 OS 层证据（独立 Windows 用户 / 窗口签名）。

结论一句话：**这套是「按通道标来源 + 挡文本冒充」，不是身份认证。**
