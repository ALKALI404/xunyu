## 〇、注入规则：只放"不读就会白干"的

**每轮被自动注入（或开工前 30 秒必读）的只有 `规则速查.md`；本文是判例集，按需查。**
- 速查里只许放：**不做就白干**的铁律 + **节号指针**；教程、判据细节、事故经过一律不进速查；
- 速查每条后面标 `[闸]`（有脚本/闸门拦）/ `[查]`（有体检或命令能查）/ `[文]`（仅文字，靠人记）——`[文]` 占比目标 ≤30%；

## 一、红线

1. **证据要指针**：「日志第 3 行 / pid 35616 / 18:25:06 回来」。拿不出就说「改了，没验」。
2. **危险操作先问主人**：删数据、杀进程树、改权限、动钱和家里人（走 §二十七 申请单）。
3. **换代线**：工作组 **70 万**（提醒 50 万）/ 本体 **95 万**（提醒 80 万），阈值在 `state\context-budget.json`。
4. **有活就干，干完就歇**：台账里有 `queued` 就不算空闲（先 `node scripts\worklist.mjs list` 领下一件）；队列空了、手上交完可以休息，**不许自己造活刷存在感**。
5. **改上游模块（`qq-bridge`）必须先有基线**：见 `state\bridge-魔改清单.md`，没记录在案的改动算隐患。
6. **守护/看门狗不许挂在会话的后台 job 里**（会话无法归档，且随会话生死）。
7. **负载闸不是万能钥匙**（2026-10-29 主人拍板，D92 落地）：派单前读目标 `contextPressure.pressureTokens`——**≥ handoff−5 万（工作组 65 万）硬拒，`--force` 也拒**，先换代；**90%·handoff（63 万）~ 硬线之间只允许 `--force`**，且必须进审计（`logs\dispatch.jsonl` 带 `code`）。`--force` 只该用在「接近线但现在不换」的场合，不是绕过硬线的通道；auto-relay 走同一道闸。

## 二、省钱与查东西（省 token 的两组习惯）

**省钱三杠杆**（详见 `省钱清单.md`）：①大输出先落盘再切片（`scripts\peek.mjs`）；②别动前缀（改早期内容 / 切模型 / 重开会话会让缓存作废）；③少写废话（输出占账单近一半）。**不省**：验证、思考等级、原文。

**查东西的姿势**：①先 `node scripts\find.mjs <关键词>`（只给路径）；②再按 `state\map.json` 的锚点精确翻，**不要通篇 grep 全仓**；③大返回用 `peek`；查完把结论写成一行，别贴原文。

## 三、文档纪律与留痕

**文档纪律**：①一页原则（能写一页不写三页，能并进现有文档就不新建）；②交接内容单独放 `docs\交接流程.md`；③写完先问「这条以后谁会看」，没人看就删；④新增文档必须挂进 `工作组必读.md` 清单，否则不算存在。

**留痕**：动过系统（改配置 / 加服务 / 重启 / 验证链路）→ `records\工作日志.md` 顶部补一条，六字段。

## 四、汇报链、通信分级与状态栏

**汇报链**：工号**不直接找本体**，交活给 01 三样——①交付物路径 ②自测命令 + 输出 + 退出码 ③卡在哪。01 每 **12:00 / 18:00 主动收作业**（逐个问「当前任务 / 交付物 / 卡点」后汇总一条发本体；超 2 小时没回执要点名）。本体只验收 + 拍板。
> 为什么：工号的回复只落在自己会话里，本体没有任何订阅——不经过 01，回执等于「存在但没人收」。

**通信分级**（`sessions.prompt` 每投一次＝一轮对话，排队又烧钱）：

| 通道 | 用什么 | 适合什么 |
|---|---|---|
| **邮件池**（默认） | `node scripts\mail.mjs post/read/tail` | 通知、汇报、状态同步、交接说明、催一下 |
| **DSH 喊话**（少用） | `sessions.prompt` | 要它**立刻**起一轮干活，或必须它亲自改代码/跑命令 |

规矩：能写邮件就不喊话，喊话必须说明「为什么现在就要动」；收件人下次运行时读、读完标记水位，**不要为了通知去唤醒一个空闲会话**；邮件池在 `E:\DeepFish\Xunyu\memory\mail\mailbox.jsonl`，是**通道不是账本**（真结论仍要落 `records\交付\` 与工作日志）。

**状态栏**（DSH 侧栏那行「正在做什么」）：只写 `⏵ 动词 + 对象`（如 `⏵ 查 8788 健康`），**≤20 字**；禁止「搞定啦」「一次过」「这波不亏」这类卖萌/口头禅——这行也是输出 token，而且是主人天天看的地方。

## 五、分工与越界（谁干什么、谁不许干什么）

**本体单线程：只调度，不执行。** 本体只做三件事——拆活（写任务书）、派活、验收抽查；**不写代码、不改配置、不做素材、不动数据**。可分解就拆成 N 张单并行派；唯一例外是 `bridge.js` 这类无人可派的上游魔改，且必须登记 `state\本体越界台账.md`。
**判断口令**：*这活有人吗？有 → 派；没有 → 才轮到我。*

| 事项 | 对口 |
|---|---|
| 开发文档 / 架构梳理 / 归属演进 | **05** |
| 插件（DSH / bridge / MCP）、插件清单、升级适配 | **02** |
| 代码实现、脚本、工具 | **04** |
| 守护、进程、计划任务、端口 | **03** |
| 名册、台账、换代、日结 | **00** |
| 调度、收作业、对账 | **01** |
| 企微 / 桥接这类上游魔改 | 本体（无人可派时才上，登记越界台账） |

**三组边界口诀（细节见判例归档 P10）**：
- **04 vs 06**：**有人盯着屏幕点的 → 06；自己在后台跑、自己坏的 → 04。**
- **06 vs 07**：**06 管「看得见的东西长什么样」，07 管「装在什么壳里、怎么起进程」。**
- **契约方向**：04 定义接口与版本、06 消费；07 定义 `window.host.*`、06 消费。**改契约先更新对应分册 §5 并通知消费方 + 05。**
- **三条硬规矩**：①状态机语义不许 06 改，要改走 04 的单；②归属不清由 05 判定写进分册 §8，01 排期，本体拍板；③两人不许互相改对方文件。

## 六、建单与派单

**派单四要素**（缺一不许派，`dispatch` 直接 409）：做什么（一句话可执行）/ 什么算过（能逐条判）/ 能碰哪些文件（边界）/ 怎么回滚。落点 `state\tasks\<单号>.md`；prompt 必须附任务书路径 + note 全文，**不许只发标题**。

**派单 vs 公告（唯一判据）**：
- **要对方动手 = 派单** → 必须真唤醒（`dispatch` / `sessions.prompt` 投递），成本记在"起一轮"；
- **只是让对方知道 = 公告** → 只落邮件池/台账，**不唤醒、不回执**；
- 拿不准就问一句"这条不做会卡住谁"——卡住别人 → 派单；不卡 → 公告。
- **为什么写这条**：把公告当派单是白烧钱，把派单当公告是活进黑洞（两边都在等且无报错）。

**单号**：建单必须给 `--ticket`，**且必须唯一**（重复 → 拒绝并列出占用者）；`dispatch` 遇空 ticket 直接 `409 no-ticket`；交付文件名用同一个单号；01 周对账时扫「有交付文件但票还开着」的，按交付把票关掉。新单号规则见 §二十六。

**测试夹具**：`worklist.mjs add --test`（id 前缀 `T-`，状态 `fixture`），**永不派给真实工号**，自动接力跳过，页面单独一栏。
**工号有权拒活**：接到没有四要素的单，写明搜过哪里、缺什么，交「未开工说明」，不算失职。

**依赖链**：任务可声明 `blockedBy: [W-xxx]`；前置未 `done` → `blocked`；`dispatch` 遇 `blocked` 拒绝（409），自动接力跳过；前置转 `done` 自动回 `queued` 并发邮件「可以开工」；链最长三段，超过说明拆单没拆好；CLI `worklist.mjs dep W-046 --on W-045` / `--off` / `list --blocked`。

**功能域拆分**：项目（对外产品）→ **功能域**（项目内可独立交付的一块，`features[].domain`）→ 单（`tickets[]`）。
并行规则：①**同域内串行**（一个人手上不叠活）；②**跨域可并行**（不同工号同时开工）；③**跨域契约**由域负责人定义并写进分册 §5；④**跨域依赖必须写 `blockedBy`**，不许口头约。
**判断口令**：*这活能拆成两块同时干吗？能 → 拆单并行；不能 → 串行，别硬并。*

## 七、交付：类型、命名、预检门

**第一行必须写类型**：`方案 / 实现 / 修复 / 文档`；没写 → 01 直接 reject。

| 类型 | 验什么 | 通过后状态 |
|---|---|---|
| **方案** | 可行性、影响面、迁移步骤、风险 | **`planned`**（不是 done），**必须派生 `-impl` 实现单** |
| **实现** | 可复跑自测（命令+输出+退出码）、边界、与文档一致 | `done` |
| **修复** | 复现步骤 + 修前/修后对比 + 回归 | `done` |
| **文档** | 分册与代码一致、§8 演进写清 | `done` |

**01 的对账义务**：工单要「实现」而交付是「设计稿」时不许标 done——要么 reject，要么转 `planned` 并立刻建实现单。本体抽查看到 done 里混着「只出方案」的，视为验收事故。

**命名与落点**：`records\交付\<工号>-<YYYYMMDD>-<单号>.md`；**文件名不符 / 放错目录 = 视同未交**。验收人断言「未交」前必须先重扫一遍目录并把扫描时间写进结论。回执类文档也算交付，但要同时放一份到 `records\交付\`。

**临时放行**（明知不达标但挡关键路径）：note 写死格式 `临时放行：缺 <什么>，已挂 <单号> 补，放行人 <谁>`；登记 `state\release-log.md`（时间/单号/缺什么/补单号/放行人）；盘点时对账，连续两轮没闭环升级给主人；**只有「挡关键路径 / 挡住别人开工」才算理由**。一句话：**放行可以，失忆不行。**

**预检门（`check-delivery.mjs`）必须比验收线松**：①**两级**——硬性（FAIL）＝无类型行 / 无四段式 / 文件名与目录不符；软性（WARN）＝缺 exit 码 / 缺代码块 / 缺回滚 / 缺「已读规则」行，**WARN 仍进 `submitted` 由 01 判**；②门不许自己发明标准，只能实现第八节已写的判定；③门拒绝要说明（邮件写清缺哪几条、可用什么替代证据）；④门坏了要能旁路（`precheck.enabled=false`）。

## 八、验收（01 全权）

**01 是唯一验收人**，本体只做抽查（每周随手抽 2 条看 01 判得准不准）。01 判定标准：

1. 交付文件在 `records\交付\`、文件名合规、四段式齐全；
2. 有自测：命令 + 输出 + 退出码三样齐；
3. 没越界：只改了自己该改的文件（对照工单「边界」）；
4. 高风险项（`bridge.js`、记忆、状态机、守护）必须带「改前/改后」证据，缺就 reject；
5. **与开发文档对得上**：拿 `docs\projects\<项目>.md` 逐节核 §3 架构 / §5 接口 / §6 状态机 / §8 演进；交付文件必须写明「影响了哪份分册、哪几节」；不一致 → reject 并写「文档不符：§5 说 X，实际 Y」；新模块或归属变化必须 05 先更新分册；
6. **做没做要可观察证据**（命令与输出、端口在听、日志一行、文件 sha/mtime、页面片段或截图）——只有「已完成」三个字的一律 reject；
7. **做成什么效果**：把工单「验收标准」逐条抄下，一条一行写 `通过/不通过 + 证据指针`；工单没写标准的，先补一句「本条以什么为准」再判；
8. **符不符合规划**：对照 `工作日志.md` 与分册 §8——偏离要写明原因且规划同步更新，**没更新规划就偏离 = reject**。

**三条通用判据（判"到底做成没有"时逐条问）**：

| # | 别信 | 要信 |
|---|---|---|
| 1 | **"程序说成功"** | 外部事实变了没有：hash、HTTP 200、页面上有没有新东西、文件 mtime |
| 2 | **"看起来像"** | **指向对不对**：路径必 `Test-Path`，端口必真连一次，会话必认 id 不认标题 |
| 3 | **"做了改动"** | **生效了没有**：先问"这改动是热更还是要重启"，再问"我验的是不是那条链路" |

**反例验收（A5）**：校验/体检/自证类工具，**必须能证明"该失败时会失败"**——把被核对象排除在比对集合外、带一个**应当失败的反例**、结论能说出**差异集合**（不是只给一个 0）。只给"全部通过"的自证 = 假证，reject。

**触发方式（2026-10-29 UG-005 改，以此为准，旧「满 7 条即验」作废）**：①`submitted ≥ 2` → **立刻**给 01 发**一条摘要**（`待验收 3 张：WG-901(05) / …`，清单变了才再发，5 分钟冷却）；②单张挂了 **≥4 小时**未动 → 报本体一封（一封列齐，不逐条刷）；③每天 **12:30 / 18:30** 各推一次当前清单，**0 张就不发**；④**禁止攒批**：不许再以"等凑够一批"为理由拖延，工具层也不按条数卡（`scripts\acceptance-watch.mjs` + 计划任务 `Xunyu-AcceptanceWatch` 每 5 分钟跑一轮）。

**失职线**：`submitted ≥ 2` 且 01 空闲却没验（≥4 小时）＝ 由 `acceptance-watch` 报本体；批量判可以，但**每条必须有自己的 note 理由**（不许「一并通过」）。

**收工前自检**：说"收工"之前必跑 `node scripts\worklist.mjs list --state submitted`——**输出不是空就不许说收工**，把输出贴进结论；`submitted ≥ 1` 且 01 空闲超 10 分钟 → workdesk 自动发 `level=活` 催一次（每天≤5）；**谁的活谁盯**：提交后 30 分钟没人验收，交付方有权提醒 01（不许默默等）。

**四级判定（每级都要人签）**：

| 级别 | 事实来源 | 判定人 | 状态词 |
|---|---|---|---|
| 单 | 台账 `done` | 01（accept 时才 done） | 已完成 / 有问题（reject） |
| **功能域** | 该域所有票 `done` | 01 签 `feature-approved` | `待验收(功能域)` → 已完成 |
| **项目** | 所有功能域签收 | 01 签 `project-approved` | `待验收(项目)` → 已完成 |
| 项目暂停 | — | 主人 / 本体 | `paused` |

规矩：票全 done 但没签收的功能域，页面显示 **`待验收`**，**不许显示已完成**；签收必须带 `--note` 结论并写进台账；**脚本只提供候选，签字权在 01**；03/04/06 无权把自己那摊标成「功能域已完成」。

**台账不许说谎**：①一个工号同一时间只能 1 张 `doing`（第二张留 `queued`，`--force` 要写审计）；②`reject` 回 `queued`（不是 doing），由自动接力重派；③允许 `doing → queued`（备注必填：打回/误派/放弃）；④`list` 对同工号多张 doing 标 `⚠ 多张在做`。

## 九、方案审核与驳回

**哪些算方案**：第一行标 `类型: 方案`；凡「先出设计再动代码」「可行性/迁移/架构调整」类工单都必须标，没标直接 reject。

**两级审核 + 拍板**：一审 **01**（可行性、影响面、迁移、回滚、四段式，4 小时）→ 二审 **05**（与分册冲突、§8 归属、重复建设，8 小时）→ 拍板 **主人**（改架构/归属/花钱路径的）。
**进度要看得见**：`planState = 待审 | 01审中 | 转05 | 待人工 | 通过 | 驳回`，带 `reviewer / reviewedAt / planNote`，页面「方案审核」一栏显示卡在谁那、等了多久。
**过了** → `plan-approved` + **自动派生 `-impl` 实现单排队**（不是直接开工）。**没过** → 写清 `planNote`、状态 `plan-rejected`、进「人工待审核箱」、**自动邮件给提交工号 + 01**「这条被驳，原因 X，该工作尚未开始」，页面标红直到处理。
**底线**：方案通过 ≠ 活干完；方案驳回 = 明确告知没做，不许静默躺在 done 里。

**被驳之后的处置**：24 小时内出 **r2**（`…-<单号>-r2.md`，第一行仍写类型，正文首行写「修正：<被驳点>」）→ 01 复审**只核被驳那几点**（不许顺手挑新毛病）→ 通过后：实现未开始则派生 `-impl`；**实现已先行则标「与实现一致」不再派生**；超 24 小时 01 报本体决定改/作废/换人。

## 三十一、视觉证据标准：要"对比"，不要"单张"（2026-10-29 22:45 本体定，来自 AV-008 驳回）

1. **凡是"开关/前后/AB"类改动，证据必须是同一区域的并排或成对截图**（开态一张、关态一张，**同尺寸同滚动位置**），单张"看起来差不多"不算证据；

3. **"不可辨认"要说明成因**：放大图证明"字看不清"时，必须补一张**只关不透明层、保留模糊**的对照，证明是磨砂造成的，而不是被不透明底色挡住；
4. **数据不能替代画面**：`data-*` 属性、自报计数只能作辅助，**不能单独作为视觉效果的证据**；
5. 交付里每张图写一句"这张图证明什么"——**写不出就不该引**。
