# 设计：关系分区与亲属模型（2026-11-05 主人定）

> 主人原话：「删掉个人信息栏的本人是谁这一栏，父母和配偶信息分开放，配偶栏位一个（允许编辑修改），子女不设置数量限制，父母栏位默认两个，但是可以继续添加，比如父母离婚继父继母这种情况」

---

## 一、数据结构（关键改动）

**不再用「household.members 扁平列表 + relation 字段」表达亲属**，改成**以「人」为中心**：

```json
{
  "id": "人-0002",
  "name": "李宏烨",
  "relations": {
    "spouse": [{"personId": "人-0004"}],
    "parents": [
      {"personId": "人-0001", "kind": "mother",       "confirmed": true},
      {"personId": "人-0005", "kind": "father",       "confirmed": false, "derived": true},
      {"personId": "人-0007", "kind": "stepfather",   "confirmed": true}
    ],
    "children": [
      {"personId": "人-0006", "kind": "child", "confirmed": true}
    ]
  }
}
```

**规则**：
| 字段 | 基数 | 说明 |
|---|---|---|
| `spouse` | **0 或 1** | **只允许一个**；换人就是改这条（旧的自动归档到 `spouseHistory`，不删） |
| `parents` | **默认两格（父亲/母亲），可加** | `kind`：`father`/`mother`/`stepfather`/`stepmother`/`guardian`/`unspecified` |
| `children` | **不设上限** | 加几条都行 |
| `others` | 任意 | 兄弟姐妹、朋友、同事等，不参与推定 |

**对称**：A 的 `parents` 里有 B ⇒ B 的 `children` 里应有 A（**写入时双向补**，标 `derived`）。

## 二、界面怎么排（个人信息栏）

```
┌ 李宏烨 ────────────────────────────┐
│ 出生 2001-11-19 ｜ 证件 5001****2615 │   ← "本人是谁"这一栏删掉
├ 配偶 ──────────────────────────────┤
│ [ 无 ] 或 [ 王五 ]  ✎编辑  ✕清除   │   ← 只一个位
├ 父母 ──────────────────────────────┤
│ 母亲：陈凤           ✓已确认        │   ← 默认两格
│ 父亲：李健（推定）    ✎确认/更正    │
│ ＋ 添加（继父 / 继母 / 其他监护人） │
├ 子女 ──────────────────────────────┤
│ ＋ 添加（不限数量）                 │
└────────────────────────────────────┘
```

**要点**：
1. **「本人」那一行直接删掉**（谁是谁由标题和人名表达，不需要"本人"）；
2. **配偶、父母、子女三块分开**，不要混在一张表里；
3. **父母默认显示两格**（父亲、母亲），空着就写「暂无相关信息」；
4. **「＋ 添加」** 可以加继父/继母/监护人；**加进来的要选类型**；
5. **推定的人**（如李健）显示"（推定）"+「确认/更正」，**确认后才算事实**。

## 三、推定与冲突

- **推定规则**：A 的母亲=C，C 的配偶=D ⇒ A 的父亲 = D（**仅当 A 没有已确认的父亲**）；
- **不做性别假设**：D 的性别未知时，显示「C 的伴侣（推定：父亲/母亲，待定）」，**由人指定**；
- **多来源冲突**（两个人都被推成父亲）→ **不写，标「冲突待定」**，红字提示。

## 四、验收口径

1. 李宏烨页**没有"本人"这一栏**；
2. **配偶、父母、子女分三块**；
3. 配偶**只能一个**，能编辑、能清除；
4. **子女能加第 2、第 3 个**，不报错、不乱序；
5. **父母默认两格**，点"添加"能加第三格（继父），类型可选；
6. 推定的人带「（推定）」且必须先确认。


## 五、空槽文案（2026-11-05 主人定）

**没填的栏位一律写「暂无相关信息」**，不写「无」「待补充」——写"无"不礼貌。


## 六、条款按需解析（2026-11-05 主人定）

**录入时默认不解析条款**，只读关键页（保单资料页 / 缴费表 / 现金价值表）。
**条款全文几十页，一次性读完阅读量太大**；只有被问到具体条款时才解析那几页，落索引后复用。


## 七、录入与解释解耦（2026-11-05 主人定）

| | 录入 | 解释 |
|---|---|---|
| 触发 | 客户/主人丢文件 | **主人下指令**（"解释这张单""看看免责"） |
| 产出 | 字段、人、关系、草稿、入档 | 带出处的结论（第X条/第Y段） |
| 是否自动 | **是**（丢进来就录） | **否**（不问不做） |
| 边界 | **不评价、不建议** | **不改档案、不建人** |

**为什么解耦**：录入要快（几十秒），解释要准（几十页 + 出处）；**混在一起就两头都做不好**。
条款索引（`档案\条款\`）**保留**——它是解释的底座，做完就放着，**不占用录入时间**。
