# 规则：人物识别与重名（2026-11-05 主人定）

> 用途：保单助理录入客户时必须照此执行；**宁可标「待补充」，不许猜。**

---

## 一、认人的优先级（从强到弱）

| 优先级 | 凭据 | 置信度 | 处置 |
|---|---|---|---|
| **1** | **身份证号（18 位，校验通过）** | `high` | 直接认人，唯一锚点 |
| **2** | **姓名 + 出生日期（到日）** | `medium` | 可建人，**检索时仍需确认** |
| **3** | **姓名 + 手机号** | `medium` | 同上 |
| **4** | **姓名 + 关联保单号**（如"某单的配偶"） | `medium` | 同上 |
| **5** | **只有姓名 + 关系** | `low` | **建「临时人」**，标 `pending`，页面打黄标 |

**建人门槛**：**至少两个字段**（姓名 + 生日／手机／保单号 之一）。
**只有姓名的，一律建临时人**，不许直接当正式档案。

---

## 二、身份证号的正确用法（重要）

**身份证号里已经包含**：前 6 位＝户籍行政区划码（**首次申报地，迁户口不换**）；7–14 位＝出生日期；17 位＝性别；18 位＝校验码。

**因此：**

| 能做 | 不能做 |
|---|---|
| ✅ **校验**：号码与生日/性别是否自洽、有没有打错一位 | ❌ **不能**用"生日+户籍地"反推出完整身份证（缺 3 位顺序码） |
| ✅ **候选排序**：重名时按「生日命中 + 户籍地命中 + 性别一致」打分，把最像的排前面 | ❌ **不能**据此自动判定"这两个是同一人" |
| ✅ **发现矛盾**：拿到的号与档案里的生日对不上 → 报警 | ❌ 不能忽略行政区划代码的时间（撤县设区会变） |

**行政区划码要记版本时间**：`idRegionHint` 旁边存 `regionCodeYear`，别拿 2026 年的码去校验 1990 年的号。

---

## 三、重名怎么办（核心：不合并）

1. **允许重名**：每人一个唯一 `id`，**名字可以一样**；
2. **靠线索区分显示**：`李四（1979-05-12）`／`李四（尾号4699）`／`李四（陈凤的配偶）`；
3. **检索到多个 → 必须反问，不许猜**：
   > "你说的李四，是哪一个？①1979-05-12 ②手机尾号4699 ③陈凤的配偶"
4. **合并只能在拿到身份证号之后做**，且：
   - 留审计（谁在什么时候合并了哪两个 id）；
   - **不删原记录**，只标 `mergedInto`；
   - 合并后保留冲突字段清单（如两个生日不一致 → 挂起待人确认）。

## 四、字段长什么样

```json
{
  "id": "人-0003",
  "name": "李四",
  "birthDate": "1979-05-12",
  "gender": "男",
  "idNoMasked": null,
  "idRegionHint": "500107",
  "regionCodeYear": 1990,
  "phonesMasked": [],
  "pending": ["身份证号", "手机号"],
  "matchHints": ["生日命中", "性别一致"],
  "confidence": "medium",
  "sourceFile": "单-0002 投保申请书照片",
  "updatedAt": "2026-11-05"
}
```

## 五、验收口径

- 给一份只有「姓名+生日」的保单，保单助理必须建出 `confidence: medium` 的人，并在 `pending` 里写清缺什么；
- 给两个「李四」且线索不同，检索时**必须弹出选择**，不许自动选第一个；
- 给一个**校验码错一位**的身份证号，必须报「号码与生日/校验不符」，不许静默接受；
- 合并两个人后，旧 id 仍在文件里，带 `mergedInto`。

## 六、性别（2026-11-05 22:10 补）

**主人原话**：「性别要写，一般保单信息包含被保险人的性别。」

- **gender 是必录字段**（男/女），不是可选备注；
- **来源优先级**：保单页/投保单上的性别 > 人工告知 > 留空 pending；
- **能从保单抽到的必须填**（保单几乎都带被保险人性别、年龄）；
- **抽不到就留空并标 yellow**，**绝不许按名字猜**（李健≠男）；
- 页面上：性别空的人，卡片右上角打「性别待补」黄标。

## 七、同名新建 / 匹配后才合并（2026-11-05 22:15 主人定）

**主人原话**：「在陈凤的配偶栏填写李健，自动给李健的配偶匹配陈凤；如果有已经存在的可能重名的李健，先新建一个李健的卡片，如果和之前录入信息的李健出生年月、户籍或者身份证号匹配再合并。」

### 7.1 填关系时（双向自动）

- 在**陈凤的配偶栏**写「李健」→ **自动在李健的 `spouse` 里补上陈凤**（双向；关系本身算已确认，因为是人工填的）；
- 反向同理：谁先填都一样。

### 7.2 同名怎么办（不自动匹配）

**发现已有同名的人，仍然先新建一张卡**（`confidence: low`，`pending` 写「可能是同一人」），**不直接挂到旧卡上**。

### 7.3 什么时候才合并

| 匹配到的信息 | 判定 | 动作 |
|---|---|---|
| **身份证号完全一致** | `high` | **可合并**（仍需点一次确认） |
| **出生年月 + 户籍地**都一致 | `medium` | **提示"可能是同一人"，等人确认** |
| **只有姓名相同** | —— | **不合并，两张卡并存** |
| 生日不一致 / 户籍不一致 | —— | **禁止合并**，标「冲突」 |

### 7.4 合并怎么做

1. 保留**较早**那张卡的 id 作主 id，另一张标 `mergedInto`（**不删**）；
2. 关系、保单、原件**迁到主卡**，冲突字段列清单挂起；
3. 写审计：谁、何时、依据哪条匹配（身份证 / 生日+户籍）；
4. 合并后**两个名字都进 `aliases`**，以后搜哪个都能找到。

### 7.5 验收

- 陈凤配偶填「李健」→ 打开李健卡，配偶栏自动是「陈凤」；
- 再填一个同名「李健」→ **系统新建第二张卡**，不报错、不覆盖；
- 给两张卡填同一个身份证号 → **提示合并**；填不同生日 → **禁止合并并报冲突**；
- 合并后旧 id 仍在文件里，带 `mergedInto`。
