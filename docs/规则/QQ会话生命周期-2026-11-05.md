# 规则：QQ 会话生命周期（2026-11-05 定）

> 背景：QQ 会话「每次开新的、旧的没关」。今天查出根因：**桥不肯归档旧的，也没有“按标题找回”的能力**——所以只能越堆越多。
> 事实依据：`bridge.js` 只有一个建口 `ensureSession`、一个退口 `retireSession`，**另有 6 处手写删映射**；退役后不归档（11-04 改的），显式 reset 仍归档。

## 一、六条规矩（主人已确认）

| # | 规矩 |
|---|---|
| **1** | **开新会话只有三种情况**：① 首次见到这个群/人；② 旧会话**确实死了**（DSH 列表里没有）；③ 主人手动“重来”。**其余一律先按标题找回。** |
| **2** | **每次换掉会话后 10 分钟内，旧会话必须归档**（不等每日任务）。 |
| **3** | **重启优先保号**：能沿用原会话 id 就沿用；实在找不回才新建，并把旧会话**最后 20 条消息摘要**贴进新会话开头。 |
| **4** | **一个群/人最多 2 个会话并存**（当前 + 正在归档中的）；超过就**立即归档最老的那个**。 |
| **5** | **桥自己收旧会话**（运行中顺手做）；外部定时任务（`qq-session-gc`）只作兜底。 |
| **6** | **会话被外部（主人/DSH）归档时，桥必须“说一句”**（日志 + QQ 里提示“这个群的会话被归档了，我重开了一个”），**不许静默新建**。 |

## 二、配套（第二轮追加，待实现）

**把 6 处手写删映射收口到一个函数**：`retireSession`。
以后禁止在别处直接 `delete state.sessions[key]`——**规矩写在文档里挡不住手写代码，只能靠“只有一个门”**。

## 三、怎么验

1. 重启桥 3 次 → `sessions.json` 里三个 key 的 id **不变**（保号）；
2. 手动归档一个群会话 → QQ 里出现提示，且 10 分钟内旧会话归档、新会话可用；
3. `DSH 列表` 里同一个群最多同时 2 个未归档会话；
4. 全库搜 `delete state.sessions` → 只剩 `retireSession` 一处。
