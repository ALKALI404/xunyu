# 规则 · 模块化开发：接口先补齐，管线最后装（2026-11-07 主人定）

> 主人原话：「接微信的工作属于独立模块，按照我之前要求的接口加函数的开发模式，就应该是如果停了就把配套功能完成接口留着，最后函数管线搭起来了接管测试」

---

## 一、核心

**一个模块被暂停时，不是"停手"，而是"停在这条线的可交付边界上"：**

```
① 接口与函数：全部写完、全部单测过（不依赖外部在线）
② 管线装配：等重启后再接（不提前接，免得半成品）
③ 接管测试：管线接好后，最后一次真机联调（这一步才需要外部在线）
```

**暂停 ≠ 留半截。暂停 = 停在「②之前」，把①做完整。**

## 二、为什么这样分

| 阶段 | 依赖 | 暂停时能不能做 |
|---|---|---|
| **① 接口与函数** | **只依赖我们自己**（本地文件、单测、假数据） | ✅ **能，必须做完** |
| **② 管线装配** | 依赖外部（微信客户端登录、桥在线） | ❌ 重启后再接 |
| **③ 接管测试** | 依赖 ② 已完成 + 真机在线 | ❌ 最后做 |

**好处**：**重启时不用再"从零开始想"**——接口在、函数在、单测在，**只差接线和联调**。

## 三、落到票上怎么写

每张模块票必须**拆成三段**，并标明哪段做完了：

```
## 阶段
- [x] P1 接口与函数（含单测）：GET/POST …，函数 …（暂停期间完成）
- [ ] P2 管线装配：接到 X（重启后）
- [ ] P3 接管测试：真机联调（P2 之后）
```

**暂停的票只允许 P1 标 x，P2/P3 必须空着。**

## 四、暂停期间**禁止**做的事

1. ❌ 不许就"外部依赖没就绪"发起提问（微信没登录、桥没起——**这些不是我们的问题**）；
2. ❌ 不许为了"看起来能跑"而造假数据蒙混（**假数据只能用在单测里**）；
3. ❌ 不许提前接管线（半接的管线比不接更糟：会误判"坏了"）。
