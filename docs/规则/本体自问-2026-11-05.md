# 规则：接活先自问（grill-me 自用）2026-11-05 主人定

> 主人原话：**「以后有任务你自己对自己使用 grill me」**

## 一、什么时候自问

**接到任何任务（派单、需求、改造、验收安排）之前**，先对自己用一遍 `grilling`，**不跳过**。

## 二、自问三问（最少这三条）

| # | 问什么 | 不问清的后果 |
|---|---|---|
| **1** | **要的到底是什么**（一句话复述，含"不要什么"） | 干偏了，返工 |
| **2** | **边界在哪**（谁做、做多少、什么不做） | 越界或被卡 |
| **3** | **怎么算做完**（可验的判据，谁验） | 交完没人认 |

**外加一问（视情况）**：**最可能出错的地方是哪**，先想好怎么发现。

## 三、自问的结果落在哪

**写进任务书**（`state\tasks\<票>.md`）的头部，三行即可：

```
## 自问
- 要什么：<一句话>
- 不要什么：<一句话>
- 算做完：<判据 1/2/3，谁验>
```

**没这三行的票，不许派。**

## 四、边界

- **自问是"问自己"，不是问你**：能自己查的事实自己查（可派子智能体），**只有决策才拿来问你**；
- **不许把自问写成一篇作文**：三行，多了就是废话；
- **复杂任务（跨 3 张票以上、或要改系统结构）**：自问要过**两轮**（第二轮问"如果第一轮答案是错的，会怎样"）。

## 五、为什么

**今晚的教训**：把"验收"写成"01 复跑判据"（第 1 问没问清"要什么"），把"换代"做成"造出一个鲟鱼—本体"（第 2 问没问清"边界"），把"最小验证"做成了自己下场写代码（第 3 问没问清"怎么算做完"）。
