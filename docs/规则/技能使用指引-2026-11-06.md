# 技能使用指引（2026-11-06 主人要求：按需用起来）

> 技能装在 `C:\Users\<用户>\.dsh\skills\`（39 个），**不用背，按场景查这张表**。
> 用法：说一句"用 `tdd` 做这个"即可；**不是每个活都要用，用了要说明用在哪一步**。

---

## 一、按场景对表

| 你要干的活 | 用哪个 | 一句话怎么用 |
|---|---|---|
| **写新功能、修 bug（要测试）** | **`tdd`** | 先定 seam → 写失败测试 → 再写实现 |
| **交付前自检** | **`code-review`** | 两轴：①符不符合规矩 ②有没有做到需求 |
| **卡住/复现不了的 bug** | **`diagnosing-bugs`** | **先造一个一键复现的回路**，再改代码 |
| **定模块边界、接口该多深** | `codebase-design` | 先画 seam，再写 |
| **术语乱、命名不统一** | `domain-modeling` | 写 `GLOSSARY.md` + ADR |
| **写任务书/规则给别的 agent 看** | **`writing-for-agents`** | 指针 + 分支，别写散文 |
| **方案拍脑袋、要挑毛病** | **`grilling`** | 让对方（或自己）问到没话说 |
| **拆活** | `to-tickets` | 每张票能独立跑通一条端到端 |
| **压交接稿** | `handoff` | 六字段 + 下一棒入口 |
| **查资料** | `research` | 带出处，不许凭印象 |
| **做界面原型** | `prototype` | 先做能看的最小页面 |
| **复盘一次活** | `retro` | 三个问题：哪错了、为什么、怎么防 |
| **一个会话装不下的大活** | `wayfinder` | 画决策地图再动手 |

---

## 二、三条纪律

1. **用之前说一句**：「这一步用 `tdd`」——**别默默用，也别默默不用**；
2. **交付里写一句**：`用了 <skill>，在 <哪一步>`（例：`用了 tdd，先写了 3 个失败测试`）；
3. **不硬套**：**活太小（改一行文案）就别用**；**用了还没省事，就写下来别再用**。
