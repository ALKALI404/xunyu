# 开发规范（2026-11-07 v1）

> 主人定：**「接口加函数的开发模式」**——**先定接口与函数，再接线，最后联调**。
> 配套：`docs\规则\模块化暂停-接口先补齐-2026-11-07.md`、`docs\规则\开源优先-2026-11-07.md`、`docs\规则\架构先行-2026-11-06.md`

---

## 一、每张票必须是三段式（P1/P2/P3）

```markdown
## 阶段
- [ ] P1 接口与函数（含单测）—— 只依赖我们自己
- [ ] P2 管线装配 —— 依赖外部/其他模块就绪
- [ ] P3 接管测试 —— 真机/联调
```

| 阶段 | 允许依赖 | 完成标准 |
|---|---|---|
| **P1** | **只依赖本仓库**（本地文件、假数据、单测） | **接口能调、函数有单测** |
| **P2** | 其他服务/外部系统就绪 | **接线跑通，一次真实调用成功** |
| **P3** | 真机/真人/真数据 | **端到端走一遍并留证据** |

**规矩**：
- **P1 没做完，不许进 P2**（半接的管线比不接更糟）；
- **暂停的票只允许 P1 打勾**，P2/P3 必须空着；
- **交票时在 `submitted` 前自查**：三段分别到哪了，写清。

## 二、接口契约（每票必写，缺了预检会拦）

必须包含：
1. **HTTP 路由或函数签名**（含入参/出参 schema）；
2. **错误码**（每个失败分支对应什么状态/什么话）；
3. **红线**（不许做什么：越权路径、明文令牌、公网端口……）。

## 三、函数优先于流程

**能写成纯函数的一律纯函数**（可单测、无 IO）：
- 判定、解析、归一化、排序、差分 → **纯函数 + 单测**；
- 落盘、HTTP、调外部 → **薄壳**（一行调用纯函数）。

**标准**：**每个纯函数至少 1 个正例 + 1 个反例单测**（反例更重要）。

## 四、失败必须显式

1. **不许用 200 包错误**（桥就栽在这：`200 + {ok:false}` 让调用方以为成功）；
2. **错误信息必须人话 + 可定位**（哪个文件/哪个字段/为什么）；
3. **超时要有兜底**（回一句人话，不静默）。

## 五、自查清单（交票前逐条打勾）

```markdown
## 自查
- [ ] P1 接口全在、单测全过（贴命令与结果）
- [ ] 错误分支都有明确返回（不是 200 + ok:false）
- [ ] 没有明文令牌/Key 出现在代码、日志、返回体
- [ ] 路径只允许白名单（收件箱/输出/study 目录）
- [ ] 改动可回滚（.bak-<票号> 或新增文件）
- [ ] 交付带证据（截图/json/命令输出）
```

## 六、模块边界

| 规则 | 说明 |
|---|---|
| **一个模块一套接口** | 微信/QQ/窗口 都是「渠道适配器」，同一套 `inbound/outbound` 形状 |
| **不许跨模块直连内部函数** | 只能走对方接口（否则改一处炸一片） |
| **共享逻辑进 `lib\`** | 探活、退避、日志尾读、路径白名单——**每个只写一次** |

## 八、"写"类功能的验收纪律（2026-11-07 补，因本体踩坑）

**起因**：验收笔记编辑器（ST-127）时，本体用 `POST /note/save` **构造了一段新正文**做测试，**把主人第 1 章 2404 字的真实笔记覆盖成 82 字节**（后从 `.bak-st127` 还原）。

**从此验收任何"写/存/改"类功能，必须四步**：

1. **先确认有备份**（`.bak-<票号>` 或先手动复制一份）；
2. **用"读原文 + 追加标记"的方式写**——**绝对不许构造新正文**；
3. **验完立刻还原**（复制回备份，或删掉标记）；
4. **还原后核对三样**：**文件大小、首行、无残留标记**。

**另外两条**：
- **测试数据不许留进真实数据**（测试卡、测试笔记、测试票都要清）；
- **写类接口的验收至少要覆盖一次失败路径**（基线过旧 409 / 缺参数 400），**不能只验happy path**。
