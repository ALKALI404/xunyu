## 二、为什么这样裁不算乱来（法律口径）

**AGPL 的义务主要在「分发」和「作为网络服务提供给别人用」时触发**：

| 用法 | 义务 |
|---|---|
| **本机跑、自己用** | **几乎无义务**（不分发就不用开源你的改动） |
| 改代码 + 分发给别人 | ❗ 必须按 AGPL 开源你的改动 |
| 改代码 + 做成 SaaS 给别人用 | ❗ 必须提供源码 |

**所以**：**内部自用 + 不分发 = 风险可控**。**这条写下来，是为了以后有人翻规矩时不困惑。**

## 三、红线（这单仍要守）

1. **不许把它的代码复制进我们自己的业务代码里**（那就成了"我们的代码被 AGPL 传染"）；
2. **不许对外分发/售卖**；
3. **如果真的改了它的代码，改动要留档**（万一以后要开源，或者要换方案，能说清改了啥）；
4. **一旦对外提供服务（比如给客户用），立刻回到"不可用"状态**，重新评估。

## 四、部署形态（建议）

```
whale_girl（独立安装，独立 data 目录）
   ↓ 它自带桥接
我们的中继（relay）→ 工作台 → 保险助理
```

**关键**：**把它当"第三方黑盒服务"接进来**（进程隔离、目录隔离），**不把它的代码合进来**——**这样既满足你的"直接用"，也满足"我们的代码干净"。**
