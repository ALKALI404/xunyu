# 规则：家庭称谓 / 家主 / 亲属推导 / 首字母检索（2026-11-05 主人定）

> 主人原话：「家庭分类下可以指定一个人作为描述的家主，但是关系一栏不强调附属关系；比如李宏烨的本人一栏填写的是陈凤；另外做一个按照名字首字母检索的个人保单信息入口；李宏烨的父母一栏母亲填写陈凤，陈凤伴侣自动归列为李宏烨的父亲能实现吗」

---

## 一、家主（household.head）

- 每个家庭**指定一人为「家主」**（`headPersonId`），页面用它描述这个家：**「陈凤家」**；
- **家主不是"主人"，只是命名与展示的锚点**，没有权限含义。

## 二、关系栏怎么填（改口）

| 旧写法 | 新写法 |
|---|---|
| 成员关系写 **「本人」** | **不写「本人」**；写**相对家主的称谓**：`家主`／`子女`／`配偶`／`父母`／`其他` |
| 李宏烨那张卡上写"本人" | **写「陈凤」**（表示他属于陈凤家），并在下方列"与家主关系：子女" |

**原则：关系只描述"是什么"，不强调"归谁所有"。**

## 三、亲属推导（可做，但必须标"推定"）

**能做到**：
- 李宏烨 → 母亲：陈凤（保单里有/人工确认过）
- 陈凤 → 伴侣：某人（有）
- ⇒ 推导：**李宏烨的父亲 = 陈凤的伴侣**，**标为「推定」**

**三条限制**：
1. **推定不等于确认**：显示为「父亲（推定）」，并留「确认/更正」按钮；
2. **同一人被推成两个角色**（如既是父亲又是叔叔）→ **不自动写，挂冲突**；
3. **同性伴侣/继父母/单亲**：**不做性别假设**，只写「陈凤的伴侣」，**不自动写"父亲/母亲"**——**除非家主动手动指定**。

## 四、按首字母检索

- 入口：页面顶部一个搜索框，**输入 `lhy` 命中「李宏烨」**；
- 数据：`people.json` 每人加 `py`（全拼）与 `pyInitials`（首字母），**没有就现场生成提示，可手改**；
- **重名 + 同首字母**：结果列表全部列出，**带线索区分**（生日/手机尾号/家主），**点谁看谁**；
- 找不到时提示："没找到 lhy，试试全名或拼音全拼"。

## 五、验收口径

- 首页搜 `cf` → 出「陈凤」；搜 `lhy` → 出「李宏烨」；
- 李宏烨页上**不出现"本人"**，而是「陈凤家 · 子女」；
- 陈凤的伴侣若已填，李宏烨页**出现「父亲（推定）」+ 确认按钮**；
- 未经确认的推定**不写进 `people.json` 的正式关系**，只在展示层出现。

## 六、家庭保单总数怎么算（2026-11-05 主人定）

**主人原话**：「家庭保单总数现在只算了户主，应该是户主及其配偶作为保险人和被保险人的情况；子女要是有配偶除了父母联系以外也要单独建立一个家庭卡片。」

### 6.1 统计口径

**一张保单算进本家庭，当且仅当：投保人或被保险人 ∈ {户主, 户主的配偶}。**

| 情形 | 算不算本家 |
|---|---|
| 户主投保、户主被保 | ✅ |
| **户主配偶投保/被保** | ✅ **（原来漏了）** |
| 户主给子女投保（子女未婚，同户） | ✅（因为投保人是户主） |
| 子女自己投保、且子女已另立家庭 | ❌ 算**子女那家**，不算本家 |
| 保单只写孙子 | ❌ 不算 |

**去重**：同一保单号只算一次（夫妻互为投保/被保也只算 1 张）。

### 6.2 子女成家 → 另立家庭卡片

**触发**：子女有了配偶（`relations.spouse` 有值）→ **自动建一张新家庭卡**：
- `households.json` 新增：`{id, name: "<子女名>家", headPersonId: 子女, members:[{子女, 本人→写"家主"}, {配偶, 配偶}]}`；
- **父母关系不搬走**：子女的 `parents` 仍指向原家庭的人，**两张卡并存**（一张原生家庭、一张自己家）；
- 页面显示两行：**「所属：陈凤家（儿子）」+「自己的家：李宏烨家」**；
- **保单归到哪家**：按 6.1 判定（谁的保单算谁家）；**同一张保单不会同时算两家**。

### 6.3 边界

- 子女未婚 → **不建新卡**（仍算原生家庭）；
- 子女配偶未知 → **不猜**，标「待补充」；
- 离婚/再婚 → **旧家庭卡不删**，标 `status: "历史"` + 时间线。
### 6.4 人卡共享、保单数各算各的（2026-11-05 00:05 主人定）

**主人原话**：「子女家和父母家各自显示保险人和被保险人的保险单数字，只是两个家庭关系的同一人指向同一份卡片。」

| 概念 | 规则 |
|---|---|
| **人（person）** | **全局唯一一张卡**（`people.json` 一个 id）；不因搬家/结婚复制；从哪个家庭点进去都是**同一张卡** |
| **家庭（household）** | **只是关系视图**：谁属于哪家、在家里的称谓 |
| **家庭保单数** | **各家按各家口径算**：父母家 = {户主, 户主配偶}；子女家 = {子女, 子女配偶}；**互不相加** |
| **同一张保单** | 只归**一个**家庭（按 6.1：投保人或被保险人在谁家）；**不会因为人在两家就重复计入** |

**例子**：陈凤给李宏烨买的那张（投保人陈凤、被保人李宏烨）→ **计入陈凤家**；李宏烨自己买的 → **计入李宏烨家**。
李宏烨的人卡只有一张：在陈凤家显示「儿子」，在李宏烨家显示「家主」，**点开是同一份档案**。

## 七、按亲缘关系图建家庭卡（2026-11-06 00:10 主人定）

**主人原话**：「按照亲缘关系图来，比如现有档案有子女彭艳，袁宗树是彭艳的母亲，而李铁军是继父，那么优先按照已有档案者的直系亲属建立家庭卡片，该规则下户主写成袁宗树。把这个也写成自动程序，在录入个人信息后自动生成。」

### 7.1 建卡优先级

1. **已有档案者的直系亲属优先**：录入一个新人时，先看他和**已有档案的人**是什么关系；
2. 例：已有「彭艳（子女）」→ 录入「袁宗树（母亲）」「李铁军（继父）」→ **建一张家庭卡，把三人放进去**；
3. **户主写袁宗树**（长辈 / 该家的主要来源人）；
4. 家名 = `<户主名>家`。

### 7.2 户主怎么定（没有人工指定时）

按顺序取第一个满足的：
1. 家庭里**父母辈**（`parents` 为空且 `children` 有值）中最年长者；
2. 该家庭**名下保单最多的投保人**；
3. **最早建人**的那个（`createdAt` 最小）；
4. 都没有 → **暂定第一个录入的人**，并标 `headAssumed:true`（页面提示"户主待确认"）。

### 7.3 自动建卡的判定（录入后自动跑）

| 这个人的情况 | 动作 |
|---|---|
| **是投保人**（名下有保单，`holders` 含他） | **建卡**（若还没有归属） |
| **有配偶或有子女**，且**没有家庭归属** | **建卡** |
| **只是被保险人** + 身份**仅为子女** + **无配偶无子女** | **归入父母家庭**，**暂不建新卡** |
| 无配偶、无子女、无保单、也找不到父母 | **不建卡**，留 `pending:["家庭归属"]` |

### 7.4 不猜

- 关系不确定（只有名字）→ 不建卡，标「待补充」；
- 继父/继母要**用 `kind` 区分**（`stepfather`/`stepmother`），**不冒充生父生母**；
- 同一人**只能有一个主家庭**（`primaryHouseholdId`），其余是关系（可以多）。
