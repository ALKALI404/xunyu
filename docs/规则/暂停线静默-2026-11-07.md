# 规则 · 暂停的线静默（2026-11-07 主人定）

> 主人原话：「加进去吧」（指「暂停的线不许发起决策提问」这条）

---

## 一、一句话

> **暂停/挂起的线，一律静默：不派单、不推进、不向主人提问。**

## 二、什么算「暂停的线」

| 情形 | 例子 |
|---|---|
| 主人口头叫停 | 「鲟鱼本身暂时先不做微信的部分」→ **微信相关全套（IN-044、WS-018~026）** |
| 票上标了 ⏸ / 「留档不派单」 | 任务书第一行就写着 |
| 项目整体暂停 | 「企业微信项目暂停」 |

## 三、暂停期间**不许**做的事

1. ❌ **不许就这条线向主人发起决策提问**（`ask_user_question`、窗口弹问、邮件问）；
2. ❌ **不许派单、不许催办**；
3. ❌ **不许"顺手改一点"**（半成品比没做更糟）；
4. ❌ **不许在汇报里把它当"进行中"**（要写"暂停中"）。

## 四、允许做的

1. ✅ **留档**：任务书、方案、证据都留着，**写明"暂停原因 + 重启条件"**；
2. ✅ **写清楚重启需要什么**（谁点头、缺什么数据）；
3. ✅ 主线无关的**技术沉淀**（比如它带来的通用教训）——但**不要借机推进那条线**。

## 五、重启怎么走

**只有主人说「开」**（例如「开微信」）才恢复；恢复时：

1. 先把票的 ⏸ 标记去掉；
2. 用**一张总票**理清当前进度（哪几张做完了、哪几张没做）；
3. 再继续派单。

## 六、为什么定这条

**今天两次踩到**（2026-11-07）：
- 04 在微信暂停后，还拿「微信怎么接 / 收件箱怎么命名」来问主人；
- 工人把我早先的验收结论搅混。

**代价**：**主人被暂停的事占用注意力**，**而真正在跑的线没人问**。**这比做慢一点糟糕得多。**

## 七、怎么落实

| 位置 | 落实方式 |
|---|---|
| **派单** | 暂停票的目标工号一律不改、不进队列（`priority-list` 里移除） |
| **任务书** | 第一行写 `> ⏸ 暂停（原因 + 重启条件）` |
| **worker 提示** | 派任何相关活时，开头一句「**这条线暂停，不许就它发起提问**」 |
| **本体** | 汇报时明确写「暂停中」，**不混进进行中** |
