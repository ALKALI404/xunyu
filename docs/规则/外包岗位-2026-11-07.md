# 规则 · 外包岗位（临时工人）（2026-11-07 主人提出）

> 主人原话：「以后工作组设置外包岗位吧，员工线程忙不过来就申请开外包干活，干完就关那种」

---

## 一、什么是外包岗

**不是新员工**，是**临时工位**：

```
固定工（00–08）长期在线，接主线活
外包岗（OUT-1、OUT-2…）按票开、交付即关
```

**一句话**：**固定工是常设编制，外包是"临时加一张桌子，活干完桌子撤走"。**

## 二、谁可以申请

| 申请方 | 怎么申请 |
|---|---|
| **固定工自己** | 在自己那张票卡住时，向本体的邮箱发一封：`请开外包：<票号> + 为什么要开 + 预计多久` |
| **本体** | 看队列积压（同工号 queued ≥ 5 且都在等）→ **直接开** |
| **主人** | 说一句「开外包」 |

## 三、开的条件（不是想开就开）

1. **本人工号手上已有 doing 票**（真忙，不是躲活）；
2. **待派票 ≥ 3 张**且**没有别的空闲工号**能吃；
3. **票能被切成"独立一段"**（外包只做这一段，**不许把半张票丢给外包**）；
4. **同时在线外包 ≤ 2 个**（再多就失控了，token 也烧不起）。

## 四、外包岗的权限（给得少一点）

| 项 | 固定工 | 外包岗 |
|---|---|---|
| 任务书 | 全部 | **只给这一张票的任务书**（不给历史、不给全库） |
| 目录 | 项目根 | **只给票里写的目录** |
| 派单/改台账 | ✅ | ❌ **不许碰 worklist** |
| 验收 | 提交待验 | 交付后**由本体或原工号验收** |
| 生命周期 | 长期 | **交付后 24 小时内关闭**（或主人叫停立即关） |

## 五、生命周期（四步，缺一不可）

```
① 开：hire-outsource.mjs hire <票号>  → 建会话 + 注入任务书 + 名册记 OUT-n
② 干：外包只做票里那一段（P1 或指定阶段）
③ 交：交付写 records\交付\OUT-<n>-<票号>.md，推 submitted
④ 关：hire-outsource.mjs fire <OUT-n> → 归档会话 + 名册标记 retired
```

**24 小时没交付 → 自动提醒；48 小时没交付 → 自动关闭并回收票**（防止僵尸工位）。

## 六、成本纪律

- **外包岗不许长时间空转**（开了就必须有票在做）；
- **一次只给一张票**（做完再给下一张，或直接关）；
- **上下文从零开始**——**不许把历史塞给它**（费钱且误判）；
- **每天最多开 4 次**（防止"一有活就开人"）。

## 七、和现有工号的关系

| 工号 | 类型 | 说明 |
|---|---|---|
| **00–07** | 固定 | 常设 |
| **08** | 固定（二线代码） | 今天临时加的，**转正**（长期用） |
| **OUT-1…** | 外包 | 按票开、交付即关 |
| **P0x** | 项目专属 | 保险项目（P01/P05），不属工作组编制 |

## 八、工具

```powershell
node scripts\hire-outsource.mjs hire ST-128 --why "04 排到 5 张，128 能独立做"
node scripts\hire-outsource.mjs list
node scripts\hire-outsource.mjs fire OUT-1
```

**名册**：`state\outsource.json`（谁、干什么票、什么时候开、什么时候关）。
