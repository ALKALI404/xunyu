# L2 阶段需求与定制化参数（本体提给 05，2026-11-05）

> 用途：**05 按这份建 L2 项目树与逻辑关系**。参数是硬约束，树是结构；**两者一起交**。

---

## 一、L2 要解决什么（三句话）

1. **看得懂**：把条款拆到「**第 X 条 / 第 Y 段**」，每条能指回原文与页码；
2. **说得清**：任何解读结论**必须带出处**，没出处不出结论；
3. **留得住**：录入保单时先出**草稿**（存盘、可续），确认后才入正式档案，并**自动生成一份初步建议文件**。

---

## 二、逻辑关系（05 要建的树）

```
L2 看得懂
├─ A 条款索引（数据底座）
│   ├─ A1 条款解析：第X条 锚点切分 → 段号从 1
│   ├─ A2 页码回填（抽不到写 null，不许编）
│   └─ A3 索引落盘：档案\条款\<hash>.json
├─ B 查询与展示
│   ├─ B1 GET /api/clause?q= → 命中片段带 no/para/原文
│   └─ B2 页面：保单详情里可展开"条款原文"
├─ C 解读（必须带出处）
│   ├─ C1 结论模板：结论 + 「第X条 第Y段」+ 原文摘录
│   ├─ C2 无出处 → 拒答（不许"大概是这样"）
│   └─ C3 风险点清单（免责/等待期/拒赔情形）
└─ D 录入与草稿
    ├─ D1 个人页底部「＋ 录入保单」入口
    ├─ D2 上传 → 草稿（存盘可续，档案\草稿\*.json）
    ├─ D3 草稿确认 → 写 policies.jsonl（保单号唯一、人必须存在）
    └─ D4 确认后自动生成「初步保单建议文件」（输出\，md 或 docx）
```

**依赖**：A → B → C；D 与 A 并行（D 不依赖条款解析，但 D4 的建议文件要用 C 的格式）。

---

## 三、定制化参数（硬约束）

| # | 参数 | 值 |
|---|---|---|
| 1 | **切分锚点** | 正则认 `第[一二三四五六七八九十百零〇\d]+条`；带空格（`第 3 条`）也要认 |
| 2 | **段号** | 每条内自然段，**从 1 起**；空段跳过 |
| 3 | **条标题** | 该条首段前 20 字；无标题就写 `null`（**不许编**） |
| 4 | **页码** | PDF 抽得到才写；抽不到 `null`；**永不估算** |
| 5 | **索引文件** | `档案\条款\<sha256前16>.json`，UTF-8，不 BOM |
| 6 | **查询上限** | 一次最多返回 **20** 个命中片段，按条号升序 |
| 7 | **出处格式** | 固定 `第{no}条 第{para}段`（中文条号原样保留，如「第三条第2段」） |
| 8 | **无出处行为** | **拒答**，返回 `{"error":"no-source"}`，页面提示"这条我找不到出处，先不下结论" |
| 9 | **草稿存放** | `档案\草稿\<时间戳>-<hash前8>.json`；**保留 7 天**后归档到 `档案\_备份\草稿` |
| 10 | **草稿状态机** | `draft` → `confirmed`（写库）/ `discarded`（人放弃）；**不许直接写库** |
| 11 | **保单号唯一** | 已存在同号：**默认拦下**，提示"已有这张单"，允许 `force` 覆盖并写审计 |
| 12 | **投保人/被保险人** | 必须是 `people.json` 里已存在的 id；不存在 → 提示"先建人"，**不许自动建** |
| 13 | **建议文件名** | `输出\保单建议-<被保险人姓名>-<保单号后6位>-<YYYYMMDD>.md`（**docx 另存一份**） |
| 14 | **建议文件必含** | 保单速览表 / 三档价值（保证/非保证/总） / 3 个优势 / 3 个风险 / 3 个待确认问题 / 免责声明（"AI 辅助，不构成投保建议"） |
| 15 | **禁止项** | 不许编保额/不许编分红/不许编条款页码/不许给"应该买什么"的结论 |

---

## 四、验收（05 建树时要写进每张票）

1. **A**：一份真条款 → `档案\条款\*.json`，贴「第三条几段、第 2 段原文前 50 字」；
2. **B**：`/api/clause?q=免责` 返回 ≥1 条，带 `no/para/原文`；
3. **C**：问一个条款外的问题 → **返回 `no-source`**（证明它不会瞎编）；
4. **D**：个人页点「＋录入保单」→ 传一份 → **刷新后草稿还在** → 确认 → `policies.jsonl` +1 → **`输出\` 多一份建议文件**。

## 五、05 要交什么

1. **L2 项目树**（写进 `项目树.md`，与 L1 并列，**不要另起一份**）；
2. **逻辑关系图**（上面 A/B/C/D 的可执行版本：票号、依赖、谁做）；
3. **每张票的契约**（照第三节参数写，**不许漏参数**）；
