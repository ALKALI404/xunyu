# 独立后台管理进程 · harbor（中文「港湾」）— 2026-11-07

> 主人原话：「我需要的是独立于现有窗口进程的独立后台管理进程，名字暂时没想好，放在 DeepFish 下的子目录，后续 SnowLuma 和 QQbridge 从属于该后台管理程序」

---

## 一、为什么必须独立

现在的守护（`services-guard`）是**计划任务每 5 分钟拍一下就退出**——**它没有"活着"的状态**，也没法持有 SnowLuma 与 QQ 桥的生命周期。

**新进程要常驻**，并且：

```
harbor（常驻、独立进程、独立目录）
├ 拥有 SnowLuma 的生命周期（启动 / 扫码等待 / 断线重连 / 优雅停止）
├ 拥有 QQ 桥的生命周期（登录后拉起 / 崩溃拉起 / 令牌刷新 / 优雅停止）
├ 看护其他服务（工作台 / 引擎 / 学习区 / 保险 / relay）
├ 暴露 HTTP API（给工作台页面用）
└ 自己由 Windows 服务或计划任务保住（单实例锁）
```

**关键**：**它不是窗口进程的子进程**，**窗口关了、它还在**。

## 二、目录与名字

**目录**：`E:\DeepFish\harbor\`（**定名 harbor，中文显示「港湾」**；改名只改目录与快捷方式）

```
E:\DeepFish\harbor\
├ harbor.mjs          主进程（巡检 + 生命周期 + HTTP）
├ services.json        服务注册表（唯一真相，含 SnowLuma / QQ 桥）
├ lib\                 模块（探活、启停、退避、日志尾读）
├ logs\                自己与服务日志（滚动）
├ state\               单实例锁、事件流水（jsonl）
└ README.md            怎么起、怎么停、怎么排障
```

## 三、进程模型

| 项 | 约定 |
|---|---|
| **端口** | **`127.1.1.7:9850`**（不走窗口进程的 9340） |
| **宿主机** | 只绑 `127.x`，不对外 |
| **单实例** | `state\harbor.lock`（PID + 启动时间），**第二份启动直接退出并打印已有 PID** |
| **自愈** | 由计划任务每分钟拉一次（幂等，有锁） |
| **优雅停止** | `POST /api/shutdown`（只停自己，不杀别人的服务） |
| **日志** | `logs\harbor.log` + `state\events.jsonl`（结构化事件） |

## 四、从属关系（谁管谁）

```
harbor（唯一发包方）
 ├ SnowLuma     ← 由它启动、由它判定在线、由它重连
 ├ QQ 桥        ← 等 SnowLuma 登录后再起；崩溃由它拉起
 └ 其他服务      ← 只在挂了时拉起（不主动重启健康的）
```

**红线**：
1. **别的进程不许直接起停 SnowLuma/QQ 桥**——**必须通过 harbor 的 API**（否则会打架）；
2. **harbor 不写 SnowLuma / QQ 桥的配置文件**（只起停 + 读状态）；
3. **harbor 挂了不影响已起来的服务**（服务是独立进程，不随 steward 死）。

## 五、API（工作台页面来调）

```
GET  /api/status                      服务红黄绿（含 snowluma / qqbridge / 学习区 / 保险 / relay / 工作台）
GET  /api/events?limit=50             结构化事件（谁挂了、拉起了几次、为什么）
POST /api/restart      { id }         单个重启（走退避规则）
POST /api/snowluma/start|stop|reconnect
GET  /api/snowluma/status             running / qrWindowVisible / loggedIn
GET  /api/qqbridge/status             桥心跳 / 绑定 / 队列 / 错误数
POST /api/qqbridge/restart            等价于 restart {id:"qqbridge"}
GET  /api/logs/tail?src=…&lines=…
GET  /api/selftest                    8 项自检
```

**跨域**：工作台（9340）页面直接 fetch `127.1.1.7:9850` → **steward 要放 CORS 给 `127.x`**。

## 七、验收

- ① `127.1.1.7:9850/api/status` 返回全部服务（贴 JSON）；
- ② **杀掉 steward → 计划任务 1 分钟内拉起**（贴两个 PID）；
- ③ **杀 SnowLuma → steward 重连**（贴事件）；
- ④ **杀 QQ 桥 → steward 拉起**（贴事件）；
- ⑤ **第二份 steward 启动 → 直接退出**（贴提示）；
- ⑥ **关掉窗口进程 → steward 与各服务仍在**（贴端口）。
