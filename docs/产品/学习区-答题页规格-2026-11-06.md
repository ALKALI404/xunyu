# 学习区 · 答题页规格（2026-11-06 主人定）

> 主人原话：「这个形式可以，能不能做成专门的网页里面有每道题的答题区批改和错题集和分析」
> 定位：学习区 ST 线的**核心交互**——读完一章不是终点，**答题批改 + 错题重考**才是。

---

## 一、页面结构（单页，`?view=quiz`）

```
┌ 顶栏：[个人][家庭][学习区]   🔍 搜索            ┐
├──────────────────────────────────────────────┤
│ 逻辑学导论 · 第1章 · 第2/3题        [上一题][下一题] │
│ ─────────────────────────────────────────── │
│ 【题干】乙「因为耶和华变乱言语，所以那城名叫巴别。」  │
│        问：这是论证还是说明？判据是什么？          │
│ ─────────────────────────────────────────── │
│ 【你的答案】                                    │
│ ┌────────────────────────────────────────┐  │
│ │ （textarea，自动保存草稿）                 │  │
│ └────────────────────────────────────────┘  │
│ [提交批改]  [我要提示]  [跳过]                  │
│ ─────────────────────────────────────────── │
│ 【批改结果】✅对 / 🟡半对 / ❌错                  │
│  要点：……                                      │
│  你漏了：……                                    │
│  你混了：有效 ≠ 可靠（p50）                      │
│ [加入错题集]  [重答]                             │
└──────────────────────────────────────────────┘
```

## 二、三种题型的批改口径

| 题型 | 判分标准 | 展示 |
|---|---|---|
| **知识点题** | 对照 `keyPoints[]`，**命中 ≥2/3 算对，1 算半对** | 逐条打勾：命中了哪几条、漏了哪条 |
| **边界题** | **判据必须出现**（例："Q 还需不需要被确立"）；判据缺 → 半对 | 明确写"判据缺失" |
| **费曼题** | 三步：①术语要配人话 ②**我扮小白追问 2 轮不倒** ③小白能复述 | 追问对话留在页面里，可回看 |

**禁令**：不给"参考答案全文"当奖励——**只给"要点 + 你漏了什么"**（给了全文你就会背，不会想）。

## 三、错题集（`?view=wrong`）

**入集条件**：❌错 或 🟡半对 或 **要过提示**（要提示 = 没独立答出来，也进错题集）。

每条记录：
```json
{ "id":"q-ch01-02", "book":"逻辑学导论", "chapter":1, "kind":"boundary",
  "question":"……", "myAnswer":"……", "verdict":"half",
  "missing":["判据缺失"], "confusedWith":"论证 vs 说明",
  "addedAt":"2026-11-06", "nextDue":"2026-11-08", "attempts":2 }
```

**重考节奏**：**1 天 → 3 天 → 7 天 → 15 天**；**连过两次**才移出（`retired:true`）。

## 四、分析（`?view=analysis`）

三块，都只统计不含糊：

1. **错误类型分布**（柱状）：有效/可靠混淆、判据缺失、只到现象层、术语糊过去……**按类型计数**；
2. **章节掌握度**：每章 `题数 / 过 / 半 / 错`；
3. **趋势**：最近 14 天「首次答对率」曲线（**这是唯一能看出进步的东西**）。

**一句话结论**：分析页顶部固定一行——**"你现在最常犯的错是：把'前提假'当成'推理无效'"**（近期最高频类型）。

## 五、接口（`127.0.0.1:9351` 扩展）

| # | 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|---|
| 17 | 取题 | `GET /quiz` | `bookId, chapter?` | `{questions:[{id,kind,stem,keyPoints,source}]}` |
| 18 | 提交批改 | `POST /quiz/grade` | `{questionId, answer, usedHint}` | `{verdict:"pass"\|"half"\|"fail", hit[], missing[], confusedWith, feedback}` |
| 19 | 错题集 | `GET /quiz/wrong` | `due?` | `{items:[{...nextDue}]}` |
| 20 | 分析 | `GET /quiz/stats` | `days=14` | `{byType, byChapter, trend}` |

**判分谁做**：**S03 考官**（LLM 判定 + `keyPoints` 对照），**不是正则匹配**；判定必须给 `missing[]`（漏了什么），否则视为无效判定。

## 六、硬约束

- **草稿自动存**（关掉网页不丢）；
- **不许显示"参考答案全文"**，只显示要点；
- **每次批改都写** `review-log.jsonl`（题号/答案/判定/耗时/是否用提示）；
- **错题集是主入口**——首页除了进度条，给一个「今日错题 N」的红点。

## 七、验收

- ① 答对一题：显示判定 + 命中要点（截图）；
- ② 答半对一题：显示"你漏了什么"（截图）；
- ③ 错题自动进集、第二天到期出现在列表（截图 + `jsonl` 片段）；
- ④ 分析页三块都有数据（截图）；
- ⑤ 草稿：填一半关页面再开，内容还在（截图）。
