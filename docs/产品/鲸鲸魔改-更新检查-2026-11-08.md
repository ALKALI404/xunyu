# 鲸鲸魔改 · 更新检查的处理（2026-11-08 实测结论）

> 主人：「删掉检查更新的部分」｜现状：**内核（Node）里没有更新代码；更新检查在 `WhaleLauncher.exe`（闭源 .NET）里**

## 一、实测到的事实

```
src\ 全目录（含 bridge）：搜 github / release-manifest / checkUpdate / latest.json → 0 命中
WhaleLauncher.exe（1.6 MB，闭源）：
   含 'releases' × 5 ｜ '更新' × 14 ｜ 'latest' × 6
   → 更新检查、下载、覆盖安装都在这个 exe 里
```

**结论**：**内核（真正干活的 server.js + bridge）本身不会去检查更新**；**会联网、会覆盖文件的只有启动器**。

## 二、所以我们怎么做（三步，已执行第一步）

| 步骤 | 做法 | 状态 |
|---|---|---|
| **① 不用启动器** | 直接 `node server.js` 起内核、`python start_bridge.py` 起桥（我已在用） | ✅ **已执行** |
| **② 给 exe 改名/挪走** | 把 `WhaleLauncher.exe` 改名为 `WhaleLauncher.exe.disabled`（万一误点也不会更新） | ⬜ 待做 |
| **③ 防火墙挡它的更新域名** | 如果它仍被调起，出站域名不在白名单 | ⬜ 可选 |

## 三、② 的风险与建议

**改名是安全的**：
- 我们**不需要启动器**（内核和桥都能单独起，已验证）；
- 唯一损失：**鲸鲸自己的托盘图标、语音页、设置向导**（这些我们本来也不用）；
- **好处**：**它再也不会自动下载新版本覆盖我们的 config**。

**但有一个前提**：**以后要改它的配置，只能手改 `config.json`**（这正是我们已经在做的）。

## 四、执行清单（②③）

- [ ] `WhaleLauncher.exe` → `WhaleLauncher.exe.disabled`
- [ ] 起服务改用两个脚本（已写好）：`start-kernel-hidden.vbs` / `start-bridge-hidden.vbs`
- [ ] 把这条写进港湾的 services.json（以后由港湾代理起停）

## 五、留档

**证据**：`WhaleLauncher.exe` 的字符串扫描结果（上面第一节）、`src\` 全目录 0 命中。
**回滚**：改名回 `.exe` 即可恢复启动器。
