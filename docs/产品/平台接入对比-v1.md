# 平台接入对比 v1（企微 / 淘宝天猫 / 京东）

> 2026-10-29 本体整理｜用途：对外方案附录，说明"我们的能力不止企微"
> 结论先行：**技术上三家都能做；门槛不在技术，在平台审核与数据合规；商业上必须区分"自研自用"与"做 ISV 卖"**

## 一、能力对照

| | **企业微信** | **淘宝/天猫（千牛·旺旺）** | **京东（咚东/咚咚）** |
|---|---|---|---|
| 官方消息接口 | 应用回调（仅单聊）、会话内容存档（全量，付费） | 有：旺旺聊天窗、消息查询等开放接口 | 有：宙斯开放平台客服接口包、咚咚消息协议 |
| **收消息** | 群消息只能靠「会话存档」（900 元/年，客户自付） | 有对应消息接口（需权限包） | 有对应消息接口（需权限包） |
| **发消息** | **官方无会话式发送**（只有限频群发）→ 我们走客户端助手发送 | **官方有发送接口** | **官方有发送接口** |
| 接入门槛 | **低**：企业自己开通即可 | **中高**：阿里开放平台应用审核（资质/类目/安全合规） | **中高**：宙斯应用审核 + 权限包申请 |
| 数据合规 | 中（存档需员工告知） | **高**：聊天内容与买家信息不得出平台，导流话术受限 | **高**：同淘宝，且第三方客服管控更紧 |
| 官方已有智能客服 | 一般 | 千牛智能客服（成熟） | 京东 AI 客服（成熟） |

## 二、两条商业路径（决定成本与周期）

| 路径 | 含义 | 审核难度 | 周期 | 适合 |
|---|---|---|---|---|
| **商家自研应用** | 客户自己开店，系统只给自己店铺用 | 低 | 约 1 周 | 单客户买断交付（我们这种） |
| **ISV / 服务商** | 系统卖给多家商户 | 高（企业资质、类目、保证金、合规审计） | 2–3 个月 | 要做 SaaS 规模化 |

**我们的 8000 买断模式，必须绑「商家自研应用」**——否则资质成本摊不进单套报价。

## 三、产品定位建议

1. **差异化不在"接得上"，在"统一工作台 + 私有化 AI"**：三家平台的官方智能客服已经很成熟，同质化没有空间；
2. **统一工作台**：同一套界面里同时看企微、淘宝、京东的会话，客服不用开三个客户端；
3. **私有化 AI**：客户自配 token，数据不出客户机器——这是平台官方客服给不了的；
4. **先企微**（门槛最低、已跑通），淘宝/京东列 P2，按客户需求逐个接。

## 四、对甲方的三句话

- 能力：企微、淘宝/天猫、京东，三家平台的客服会话**都能接进同一套工作台**；
- 前提：电商平台需以**商家自研应用**方式申请，约一周；若要多商户售卖则需服务商资质，周期 2–3 个月；
- 边界：平台侧的数据合规要求我们严格遵守（聊天数据不出平台允许范围），这也是我们不做"数据二道贩子"的原因。
