# 企微聊天组件 · Demo 规格（v0.1）

> 2026-10-30 00:30 主人定义：
> 「把企业微信的聊天拉出来作为 demo，我在哪个聊天框发消息会投射到真实的微信消息发送里面，然后读取下来的上下文在本地窗口可以阅览发了什么收了什么，做一个类似于现有窗口聊天功能的独立组件来承载它」

## 一、Demo 的目标（只做这三件事）

1. **看得见**：本地窗口里有一个「企微」聊天组件，能浏览**会话列表 + 消息流**（收到的 + 我们发出的）；
2. **发得出**：在本地组件里输入 → **真的**从 VM 里的企微发出去（号主身份）；
3. **是独立组件**：像现有「聊天」页签一样是一个独立视图，**数据只走 HTTP**，不直接读文件、不依赖窗口壳。

## 二、架构（三块，边界清楚）

```
① 入站（读）
   VM 企微窗口 → 截图 → 本地 OCR → 结构化消息
   （后续可换：会话存档 API，同一接口）

② 出站（写）
   本地组件 → POST /api/wecom/send → outbox(JSONL) → VM 发送器 → 真企微
   （VM 发送器 = WC-004，已在做）

③ 展示（本地组件）
   会话列表 / 消息流 / 输入框 / 发送状态（pending|sent|failed + 证据图）
```

**接口（先定死，三块并行不打架）**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/wecom/conversations` | 会话列表 `[{id,name,unread,lastTs,lastText}]` |
| GET | `/api/wecom/messages?conv=<id>&after=<seq>` | 增量消息 `[{seq,conv,dir:in/out,text,ts,evidence}]` |
| POST | `/api/wecom/send` | `{conv,text}` → `{ok,outboxId,state}` |
| GET | `/api/wecom/status` | `{vm:ok, sender:running, ocr:ok, lastSync}` |

## 三、Demo 的验收（主人视角）

1. 打开窗口 → 「企微」页签 → **左侧会话列表有真实会话**（至少 3 个），右侧显示最近消息；
2. 在输入框发一句 → **VM 里企微真的发出去**（证据：截图 + 对方收到）；
3. 对方回一句 → **10 秒内**出现在本地消息流（入站）；
4. 消息带方向标记（我发的/收到的）与时间；发失败要**红字提示 + 原因**。

## 四、明确不做（v0.1 边界）

- 不做群发、不做主动加好友、不做多号；
- 不做历史全量回溯（只拉最近 N 条）；
- 不碰真实客户会话（**测试只用自己人/文件传输助手**）。

## 五、排期（依赖顺序，不许并行抢地基）

1. **WC-004**（04）VM 发送器 → 地基，已在做；
2. **WC-007**（04）后端：三个接口 + outbox + 入站 OCR 骨架；
3. **WC-008**（06）本地组件 UI：会话/消息/输入/状态；
4. **WC-009**（03）入站 OCR 服务：定时截图 + 本地 OCR + 去重增量。

## 六、风险

- **OCR 准确率**（中文气泡、头像遮挡）→ 先只读文本消息，图片/表情跳过；
- **延迟**：截图轮询 2–3 秒 + OCR 0.5–1 秒 → 总 3–5 秒，可接受；
- **VM 必须常驻**（WC-005 在解决）。
