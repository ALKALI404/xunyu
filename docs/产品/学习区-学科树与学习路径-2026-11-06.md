# 学习区 · 目标驱动学习路径 + 学科树（2026-11-06 主人定）

> 主人原话：「讨论下一个学习方向，比如我想学什么，学到什么程度，目前对该专业的理解，然后它去做学习计划，然后出摸底题，最后动态调整……比如我掌握这本入门之后接着想要去看维特根斯坦的逻辑哲学论需要补充哪些过渡读物，哪些核心知识需要通过考试才能解锁下一个阶段，以及学科树系统……这个你看怎么做可视化比较合适」

---

## 一、核心判断：这个功能本质是"倒推"，不是"画图"

**先说结论**：**不要做"全学科知识图谱"**——那东西一画就是几百个节点，看完只会焦虑，不会行动。

**要做的是「目标驱动的倒推链」**：
```
你说：我想读《逻辑哲学论》，读到能跟人讨论的程度
  ↓  系统倒推
需要：命题逻辑 → 谓词逻辑 → 语言与意义（弗雷格/罗素）→ 维特根斯坦前期
  ↓  每段配：过渡读物 + 门槛考试（过了才解锁下一段）
  ↓  出摸底题（看你从哪一段开始，别从零读）
```

**所以可视化只有三种形态，各管一件事**：

| 形态 | 回答什么问题 | 什么时候出现 |
|---|---|---|
| **① 路径链（主线）** | **我下一步该读什么** | 主页/助手常驻，**一条竖线，3–5 个节点** |
| **② 局部星图（±1 跳）** | **这门跟别的什么有关系** | 点开某个节点时才展开，**一圈邻居，不超过 12 个** |
| **③ 门槛锁 + 时间条** | **还差什么、还要多久** | 节点卡片下方，**进度环 + 预计日期** |

**不做全局大图，只做这三种**——这是"能看"和"能吓死人"的分界线。

## 二、数据模型（先定数据，再谈画法）

```json
// 学科\_tree.json
{
  "nodes": [
    { "id": "logic-intro", "name": "逻辑学导论", "kind": "book", "subject": "logic",
      "level": 1, "effortHours": 40, "status": "learning" },
    { "id": "frege-arith", "name": "弗雷格《算术基础》选读", "kind": "book", "level": 3,
      "effortHours": 25, "status": "locked", "gate": "gate-logic-2" },
    { "id": "tractatus", "name": "维特根斯坦《逻辑哲学论》", "kind": "book", "level": 5,
      "effortHours": 60, "status": "locked", "gate": "gate-logic-4" }
  ],
  "edges": [
    { "from": "logic-intro", "to": "frege-arith", "type": "prerequisite", "strength": "must" },
    { "from": "propositional-logic", "to": "tractatus", "type": "supports", "strength": "helpful" }
  ],
  "gates": [
    { "id": "gate-logic-2", "name": "命题逻辑与真值表 · 门槛考", "pass": 0.8,
      "unlocks": ["frege-arith"], "kind": "exam" }
  ]
}
```

**边只有三种，别搞多**：
- **`prerequisite`（必修前置）**：不做完，就不该开始（大学物理 ← 高等数学）
- **`supports`（有用但不是必须）**：有更好（数论 ↔ 逻辑学）
- **`adjacent`（同域邻居）**：只用于"你可能也想看"

**门槛（gate）只有两种**：
- **`exam`（考试解锁）**：过 80% 才解锁；
- **`mastery`（掌握度解锁）**：某学科理解度 ≥4/5。

## 三、可视化怎么做（技术选型）

| 需求 | 方案 | 理由 |
|---|---|---|
| **① 路径链** | **HTML + CSS（竖排卡片 + 连接线用伪元素）** | **不需要任何库**；一条线，滚动就能看 |
| **② 局部星图** | **SVG + 一层环形布局**（自己算角度，20 行代码） | 节点 ≤12，**不需要 d3/cytoscape/echarts** |
| **③ 门槛锁/时间条** | **SVG 环形进度 + 横向甘特条** | 同上，纯 SVG |
| 备选：文档里贴关系 | **Mermaid `graph LR`** | 写设计稿/聊天时用，**不进产品** |

**明确不装**：`d3`（重）、`echarts`（重且丑）、`cytoscape`（杀鸡用牛刀）。
**理由**：**我们要的是"看得懂下一步"，不是"炫"**；**几十个节点，SVG 手绘足够，且加载 0ms。**

## 四、助手新功能：学习方向对话（`?view=plan`）

**四步走，每步都要你点头**：

```
① 摸底对话（3 问）
   你想学什么？→ 学到什么程度算够？→ 你自认为现在什么水平？
        ↓
② 系统倒推路径（显示：起点→过渡→目标，标出必须过的门槛）
        ↓  你确认/删改
③ 出摸底题（5–8 题，按倒推结果抽；答完决定"你从哪一段开始"）
        ↓
④ 生成计划（按每天可投入时间排期）+ 动态调整
   · 每章读完 → 重算剩余天数
   · 摸底题答得好 → 跳过某些前置
   · 连续三天没动 → 提醒并问"要不要降难度/换节奏"
```

**输出物**：`学科\<学科>\计划-<目标>.md`（含倒推链、门槛、排期表、预测完成日期）。

## 七、学习地图按「学科」划分（2026-11-07 00:00 主人定）

**主人原话**：「学习地图按照学科划分，比如物理学，逻辑学哲学数学之类」

### 7.1 顶层不是"目标"，是"学科"

```
学习地图
├ 数学          （档位 4 · 基础可跳）
├ 逻辑学        （在学 · 第1章）
├ 哲学          （含罗素/尼采/维特根斯坦三条目标线）
├ 物理          （档位 3.5 · 补定义卡）
├ 化学          （档位 3 · 补机制链）
├ 生物          （档位 3.5 · 补1节）
└ 计算机科学    （档位 2 · 真空白，加前置节点）
```

**每个学科内部**才是"书/专题节点 + 依赖 + 门槛"。**跨学科依赖单独画**（少量，别画成蜘蛛网）。

### 7.2 数据结构加一层 `subjects`

```json
{
  "subjects": [
    { "id": "physics", "name": "物理学", "level": 3.5,
      "status": "needs-patch", "note": "机制懂、定义松；补 3 张定义卡",
      "nodes": ["phys-mechanics", "..."], "crossDeps": ["math-calculus"] }
  ],
  "nodes": [ { "id": "phys-mechanics", "subject": "physics", ... } ],
  "edges": [ ... ],
  "gates": [ ... ]
}
```

**硬规矩**：
- **每个 node 必须属于且仅属于一个 subject**（`subject` 字段）；
- **跨学科依赖用 `crossDeps` 而不是普通 edge**（渲染成灰色虚线，一眼区分"本学科内"和"跨学科"）；
- **学科档位来自摸底结论**（`学识档案\2026-11-06-基础摸底.md`），**不许凭感觉写**。

### 7.3 地图怎么画（沿用三种形态）

| 层 | 画法 |
|---|---|
| **地图首页** | **学科分区卡片**（7 张，各带档位 + 进度 + 待办数） |
| **点进学科** | **路径链（竖线）**：该学科内的节点按 level 排 |
| **跨学科** | 只画**当前学科指向别的学科**的那几条虚线（如"物理 ← 微积分"） |

**不做**：全学科一屏大图（节点一多就糊）。

### 7.4 摸底结论怎么落进来

| 学科 | 档位 | 落法 |
|---|---|---|
| 数学 | 4 | `status:"mastered-basics"`，**节点默认折叠**，只显示"可跳" |
| 生物 | 3.5 | `status:"needs-patch"`，`patch:["转录翻译"]` |
| 物理 | 3.5 | `patch:["能量定义卡","熵定义卡","守恒的用处"]` |
| 化学 | 3 | `patch:["氢键→分层","活化能→加速"]` |
| 计算机 | 2 | **加两个前置节点**：`cs-complexity`、`cs-engineering`；`status:"gap"` |
