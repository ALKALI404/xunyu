## 三、接口契约

```http
GET /api/console        → 四栏一次给全（**3–5 秒缓存**，不许每次打 8 个后端）
{
  ok:true, at, cached:true|false, degraded:true|false,
  services:[{id,name,port,up,restartsLastHour,lastAction}],           // 透传 supervisor
  channels:{
    qq:{ state:"ok|unreachable", online, lastAt, sentToday, recvToday, detail },
    relay:{ state:"ok|unreachable", bound, total:2, lastAt, detail },
    files:{ state:"not-implemented", detail:"未接入（网关有能力，本地没实现）" }
  },
  brain:{
    persona:{ file, mtime, chars, hasFrontMatter },
    memory:{ files, lines, bytes },
    model:{ available:false, note:"经 DSH，无本地读数" }
  },
  cost:{ today, turns, tokens },                                      // 透传 /api/cost
  tickets:{ queued, doing, submitted }, agents:[...]                  // 透传
}

POST /api/console/restart { id }   → 复用 POST /api/supervisor/restart（不另写）

GET  /api/console/selftest         → { at, summary:{pass,fail,skipped}, checks:[{name,state:"pass|fail|skipped", detail}] }
                                     （不吃缓存，5 秒限频）
```

**错误语义（按《开发规范》§四，不许 200 包错误）**

| 情况 | HTTP | body |
|---|---|---|
| 正常（哪怕有渠道不可用） | **200** | `ok:true` + 各栏 `state` 如实报（`degraded:true`） |
| **supervisor 不可用**（页面骨架没了） | **503** | `{ok:false, error:"supervisor-unreachable", detail}` |
| 参数错（如 restart 缺 id） | **400** | `{ok:false, error:"bad-request", detail}` |
| 内部异常 | **500** | `{ok:false, error:"internal", detail}` |

> **"被观测对象挂了"不是接口失败**：QQ 桥挂了，是 console **成功报告了"QQ 不可用"**——那是数据，不是错误，所以 200 + `state:"unreachable"`。
> **"console 自己挂了"才是错误**：503/500。**别用 `200 + ok:false`**，那是桥栽过的坑。
> `selftest` 同理：它是**报表**，200 + `summary`；只有"自检根本跑不起来"才 503。

## 四、自检 8 条（QQ 版）

|---|---|---|---|
| 1 | `services` | supervisor 里全部 `up` | "N 个服务没起：…" |

## 六、风险

1. **不准把"没有"画成"离线/正常"**：QQ 文件未接入必须显式"未接入"；数据读不到必须"读不到 + 原因"。绿灯骗人比红灯更糟。
2. **key 永远不出**：本轮我们本来就没有 key 可显示；将来接进 DSH 的 key，也只允许掩码，任何接口不许回显明文（WS-019 §五红线）。
3. **聚合别变 N+1**：3–5 秒缓存；`selftest` 例外（要当下）+5 秒限频。
4. **别重做 WS-017 的页面**：①④两栏已在做，WS-019 只加两栏——重做等于让 06 交两遍。
