# 小红书客服 · 策划案 v0.1

> 2026-10-31 18:40 本体起草｜状态：待主人拍板｜产品线：鲟鱼 × 小红书
> **一句话定位**：不做"无人值守的私信机器人"，做一个**懂话术、会质检、能兜底**的客服助手；把它接进小红书之前，先把"人怎么用"设计清楚。

---

## 一、先看真实案例：有人真的把账号交给 DSH 了

**`Ez4p1xEL/deepseek-instagram`**（MIT，GitHub）——**这就是"用户把个人账号交给 DSH"的现成案例**：

| 它的做法 | 对我们的价值 |
|---|---|
| 一份 **Markdown 人格卡** + 最多 60 条记忆，发帖/回私信语气一致 | **客服话术也应该是人格卡，不是 if-else** |
| **只有主人账号的 1:1 私信能下指令**（数字 user id 绑定，昵称冒充无效） | **控制面只认主人**，这是安全底线 |
| 有副作用的动作**要回一句确认** | **发消息/改价格必须二次确认** |
| 安全阀：暂停开关、按类型日上限、最小间隔、安静时段、失败冷却、补发窗口 | **客服侧同样要这些**，否则会被风控 |
| 本机渲染 1080×1920 卡片（Pillow），不走云端 | 素材/凭证不出本机 |
| **明确不做**：官方 API、多账号、Reels/视频、自动点赞关注 | **划清边界反而更容易过审** |

**另有商业侧案例**：**有赞智能体·小红书账号托管**——商家把小红书账号授权给服务商做托管（走服务商通道，要资质）。
**反面案例**：平台服务商滥用授权资质做"代运营"，商家被坑（华声调查报道）——**授权链条一定要自己掌握**。

## 二、三条路径（必须先选一条，否则技术方案无从谈起）

| 路径 | 走什么 | 门槛 | 风险 | 我的建议 |
|---|---|---|---|---|
| **A. 企业号 + 授权服务商**（HollyCRM / Live800 / 有赞这类） | 官方通道，服务商提供私信 API + 会话分配 | **企业资质 + 付费** | 低（合规） | **唯一能长期跑的路** |
| **B. 桌面自动化**（截图 + 点击，像企微那套） | 本机模拟人操作 | 无（但要 Windows + 常开） | **高**：违反平台规则可封号 | **只在"试探需求"阶段用，且只读为主** |
| **C. 内容侧助手**（不碰私信） | 评论话术、FAQ、质检、素材 | 无 | 极低 | **立刻能做，先跑这个** |

**我的建议顺序**：**C（今天就能做）→ A（真要做客服才走）→ B 只在有明确授权与风控预案时短用**。

## 三、能力清单（诚实版）

### 能做（安全区）

| 能力 | 具体做什么 | 依赖 |
|---|---|---|
| **话术库 + 分级应答** | 价格/发货/尺码/售后 → 标准答案，一键发送 | 无（先做知识库） |
| **私信草稿建议** | 读对方问题 → 生成回复草稿，**人审后发** | 会话内容可读（A 或 B） |
| **评论批量回复** | 固定句式公开评论，**不导流、不留联系方式** | A 或 B |
| **质检（最值钱）** | 扫历史会话：**违禁词、导流话术、承诺过头** | 只读，风险最低 |
| **工单与知识沉淀** | 反复问的整理成 FAQ，减少重复劳动 | 无 |
| **多平台话术一致性** | 和企微/QQ 共用一套人格卡与话术 | 已有基础设施 |

### 不能做（红线）

1. **自动批量私信 / 自动加微** → 必封；
2. **引导站外**（微信号、电话、二维码）→ 2025-03 新规明令，可**永久封号**；
3. **无人值守全自动回复**（出错没人接管）；
4. **伪造身份**（冒充真人、冒充官方）。

## 四、MVP 分三期

### 一期（1 周，零风险，可立刻做）

- **话术知识库**：把常见问题整理成 `话术库.md`（分类 + 标准答 + 禁用说法）；
- **质检脚本**：输入导出的会话文本 → 输出"违禁/导流/超范围承诺"清单；
- **交付物**：`话术库 v1` + `质检报告`（拿历史会话跑一遍就能出数）。

### 二期（2–3 周，需授权）

- 走 **A 路径**打通一个企业号私信；
- 做**草稿模式**：AI 出草稿 → 人点发送（**不做全自动**）；
- 指标：**首次响应时长**、**人工节省比例**、**质检拦截数**。

### 三期（视一期二期数据再定）

- 会话分配（多客服）、知识库自动更新、跨平台同步；
- **此时再讨论**要不要"半自动直发"。

## 五、指标（怎么算"这件事成了"）

| 指标 | 目标（一期） |
|---|---|
| 常见问题覆盖率 | ≥ 80% 的会话能命中标准答 |
| 草稿采纳率 | ≥ 60%（人愿意用） |
| 质检拦截 | 历史会话里**至少找出 3 类高危话术** |
| 人工节省 | 单会话处理时间 ↓ 30% |

## 七、待你拍板（四个问题）

1. **账号性质**：个人号 / 企业号 / 专业号？（决定能不能走 A）
2. **业务类型**：卖货 / 咨询 / 内容号？（决定话术复杂度）
3. **能不能授权**：你愿意把账号凭证放本机（像 IG 那个案例的 sessionid）还是完全不给？
4. **底线**：全自动 vs 草稿模式，你能接受哪种？

---

## 八、风险与兜底

| 风险 | 兜底 |
|---|---|
| 平台风控封号 | **只读优先**、限速、安静时段、异常即停 |
| 授权被滥用 | 控制面只认主人账号 id（照抄 IG 案例）；凭证本机加密 |
| 话术越权承诺 | 话术库带**禁用词表**，质检脚本先跑一遍 |
| 服务商跑路/资质滥用 | **不把账号密码交服务商**，只给必要授权 |
