# 条款自动获取与匹配（2026-11-06 主人定）

> 主人原话：「上传保单后去相关官网下载对应条款库到本地，如果两个保单产品相同则不用重复下载，或者像阳光等主要的保险公司就下载近 5 年的各类型产品条款解释，上传保单后自动匹配，网页每个保单下方连接到产品对应的保险解释条款文件（连接到本地或后续服务器的库里面可以打开预览和下载）」

---

## 一、要做成什么（四件事）

| # | 功能 | 说明 |
|---|---|---|
| **1** | **上传即取条款** | 保单入库后，**按公司 + 产品名 + 生效日**去官网抓对应条款 PDF → 存本地 `档案\条款库\<公司代码>\` |
| **2** | **同产品不重复下载** | 去重键 = `公司代码 + 产品名 + 版本期`；**已有就复用，不重抓** |
| **3** | **主要公司预抓近 5 年全产品** | 阳光等主力公司：**批量抓近 5 年所有产品条款**，建成"条款解释库"（离线可查） |
| **4** | **页面可点开** | 每张保单下方一行链接：「本单条款：<产品名>（<版本>）→ 预览 / 下载」；**预览走本地文件，后续可换服务器** |

## 二、匹配键（三级，逐级降级）

```
① 产品名 + 生效日在版本期内   ← 最准
② 产品名（模糊：去掉"（2021版）"这类尾缀）
③ 公司 + 险种类别（意外/重疾/寿险）  ← 兜底，必须标"匹配不确定"
```

**硬规矩**：
- **每条匹配结果必须带 `matchReason`**（命中的是哪一级）；
- **版本未知就写"版本未确认"，不许默认最新版**；
- **匹配不到 → 状态 `missing`，页面写"暂无本单条款（待补充）"，不许拿别的产品条款顶**。

## 三、抓取规矩（先小人后君子）

1. **只抓公开页面**（官网产品条款栏、行业协会产品库），**不绕反爬、不破验证码**；
2 **限速**：同域 **≤1 请求/秒**，**并发 ≤2**；
3. **记录来源 URL + 抓取时间 + 文件 sha256**（以后核对"这份条款哪来的"）；
4. **抓不到就标 `download-failed` + 原因**，**不静默重试到被封**；
5. **PDF 必须落地**（本地留原件），**解析失败不影响原件可用**。

## 四、去重与更新

| 情形 | 动作 |
|---|---|
| 同 `公司+产品+版本` 已有 | **复用**，不重抓（记录 `reusedFrom`） |
| 该公司出了新版条款 | **新增一条**，旧版标 `supersededBy`（**不删旧版**——老保单要用老版） |
| 同一产品同一版本抓到两份 | 按 sha256 判同，**保留一份** |

## 五、页面（06）

保单详情页底部固定一块：

```
📄 本单条款
   太平久久保意外伤害（2016 版）
   [预览]  [下载 PDF]      来源：太平官网 · 抓取于 2026-11-06
```

- **预览**：本地 PDF 用系统默认阅读器打开（或页面内嵌 iframe）；
- **下载**：直链本地文件；
- **没有条款时**：显示「暂无本单条款（待补充）」+ 「去官网找」按钮（打开搜索页，**不假装自动**）。

## 六、要 05 grill 的六个点（架构阶段必须问清）

1. **站点清单**：8 家公司（太平/友邦/百年/富德/阳光/横琴/华贵/中保）官网条款栏的具体 URL 规则是什么？哪些公司**没有公开条款页**？
2. **预抓范围**：阳光这类"近 5 年全产品"到底是什么量级（估计多少份 PDF、多少 GB）？**先抓一类还是全抓**？
3. **产品名归一化**：保单上的产品名和官网标题常常不一样（带"（分红型）""2021版"），**归一到什么程度**？谁维护别名表？
4. **失败处理**：抓不到时，**页面/后台怎么标**？是否进"待人工下载"清单给 P01？
5. **存储与体积**：条款 PDF 长期会到多大？**放本机哪个盘、要不要压缩/去重**？
6. **合规**：只抓公开信息是否够？**要不要在文件里写"来源与抓取时间"的头部元数据**（我建议要）？

## 七、追加（主人 2026-11-06 20:00 定）

1. **中保先不管**：`no-adapter` → 状态 `missing`，页面「暂无本单条款（待补充）」，**不进抓取队列**；
2. **横琴先试**：抓一次，**失败就按中保处理**（标 `missing`，不反复重试、不换歪门渠道）；
3. **所有自动填写的字段必须标「待人工校验」**：
   - 抓来的条款、匹配结果、自动抽取的字段，**一律不得直接视为已确认**；
   - 页面上用标记区分：`✓ 已人工确认` / `⏳ 待校验（机器填）`；
   - **入档（正式档案）前必须有人确认过**；未校验的只进"草稿/待核"区。
