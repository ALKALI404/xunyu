## P1 · D14 被误标「完成」（原 §11 开头事故段）
**现场**：D14 工单写「先出设计再动」，04 交了设计稿、一行代码没改，我按「完成」验收 → 活消失了。
**根因**：验收只看「有没有文件」，没看「交付的是什么类型的活」。
**→ 现归**：§七「交付：类型、命名、预检门」（类型四值 + 表的通过后状态 + `planned` 必须挂实现单）。

## P2 · A4 夹具被当真活派给 02（原 §15 事故段）
**现场**：02 收到一条只有标题的「A4」，搜了 35 处都是误伤——那其实是 04 做 D30 时造的测试夹具，没有任务书、没有四要素。
**→ 现归**：§六「建单与派单」（四要素 + 夹具 `--test` + 工号有权拒活）。

## P3 · C1/D1 单号为空，交付认领永远对不上（原 §17 事故段）
**现场**：W-042(C1)/W-043(D1) 建单时 `ticket` 为空，交付文件叫 `03-20261028-D1.md`，自动认领按单号匹配**永远对不上**——活早交了、票还挂着「在做/排队」，主人以为 03 磨洋工。
**→ 现归**：§六（建单必须给单号且唯一、`dispatch` 拒空单号、周对账）。

## P4 · 预检门挡住 47/74 份好活（原 §22 之三 事故段）
**现场**：D57 的 `check-delivery.mjs` 要求「修复类必须有 exit 码」，而验收标准只要求可观察证据。结果 74 份交付里 **47 份 FAIL**，`D59`/`D60` 干完了却卡在 `doing`。
**后来又踩一次**：2026-10-28 20:2x，`D30`/`D31`/`D44`/`D54` 同样卡住（缺 exit 码 / 缺类型行），项目视图一直显示「在做」。
**教训**：门比验收线更严 = 自己制造积压；WARN 必须能进待验收。
**→ 现归**：§七「预检门必须比验收线松」（两级 + 不许加码 + 可旁路），速查第 18 条。
