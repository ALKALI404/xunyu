# 坑清单（踩过的，别再踩）

> 交接必读。**每条四段**：现象 · 证据（实测数字）· 缓解（正确做法）· 怎么验。
> 分级：**S = 会丢东西 / 不可逆** ｜ **A = 卡成长或误导决策** ｜ **B = 知识性（设计如此/预期行为）**。
> 状态：`待办` / `已修` / `挂起`。⛔ **别当已修**——修了也要在"怎么验"里给出复验命令，否则保持"待办"。
> 新坑往这儿加：**补不出实测数字就先写「待补测」**，不许编。

## S 级 · 会丢东西 / 不可逆

### S1 · 会话建在工作区外 → 侧栏看不到、归档漏掉
- **现象**：新会话能建，但侧栏不显示，`workspace.json` 的 sessionIds 里也没有它。
- **证据（实测数字）**：2026-10-28 一次事件里 **2 个工号（03/04）各踩一次**，都导致**重建会话**（旧 sessionId 作废）；`session/create` 同时给 `{cwd, workspaceId}` 直接报错 `accepts workspaceId or cwd, not both`。
- **缓解**：**只给 `{workspaceId}`**（cwd 由工作区带）；或直接走 `handoff.mjs new`。
- **怎么验**：建完立刻核两处——侧栏能看到 + `workspace.json` 的 sessionIds 含它；缺一即视为失败。

### S2 · 方案 ≠ 做完，交个设计稿就被标 done → 活消失
- **现象**：只交了设计稿的工单被验收成 done，后续没人做实现。
- **证据（实测数字）**：2026-10-28 **1 次**（D14：工单写"先出设计再动"，交设计稿、**0 行代码**，被按"完成"验收）；此后该类单统一要求 `-impl` 派生。
- **缓解**：交付第一行写类型；**方案通过记 `planned` 并必须派生 `-impl` 实现单**；01 对账义务（要"实现"收到"设计稿"须 reject 或转 `planned`）。
- **怎么验**：`worklist.mjs list --state planned` 里每张都必须有对应的 `-impl` 票；没有 = 漏派生。

## A 级 · 卡成长 / 误导决策

### A1 · 账本 `cacheHit` 是"读到多少"，不是"新增多少" → 花费虚高
- **现象**：按行相加算花费，一天能算成 ¥430（实际 ¥30 级）。
- **证据（实测数字）**：**虚高约 13 倍**（D44 实测并修复）；修后按 `(sessionId, turn)` 分组、`cacheHit` 取 max 才对得上官方。
- **缓解**：计价只走 `scripts\cost-core.mjs`（口径锁）；`cacheMiss/output` 累加、**`cacheHit` 取 max**；口径改动必须升版本号。
- **怎么验**：`node scripts\token-report.mjs --days 1` 与官方 CSV 同日对账，金额误差 <3%、命中率误差 <2%（`cost-regress` 会自动跑）。

### A2 · 用数组下标当游标 → 同一批回执循环
- **现象**：QQ 侧反复收到"同一批回执"，一条回执循环四五遍。
- **证据（实测数字）**：缓冲上限 **50 条**，`shift()` 一次就让所有客户端游标错位；表现为**同一条回执循环 4–5 遍**（10-28 修）。
- **缓解**：游标改成**单调序号**（`relayReplySeq`）；窗口侧 `lineSeq` 同理落盘、跨重启只增不减。
- **怎么验**：把缓冲塞满 50 条再取一次增量——`after=<旧seq>` 返回空而不是旧回执；日志里不出现同一 seq 两次投递。

### A3 · `paused` 有两份，改错那份不生效
- **现象**：`config.json` 里写了 `socialV2.paused=true`，QQ 照旧接话。
- **证据（实测数字）**：运行态在 **`state\social-v2.json`**（启动时从它读）；`config.json` 那份改了 **0 效果**。
- **缓解**：改 `state\social-v2.json` 的 `paused`，再重启桥接。
- **怎么验**：改完 `curl 3100/api/socialV2/state`，返回的 `paused` 与文件一致；发一条群消息确认不回声。

### A4 · JSON 带 BOM，`require()` 直接炸
- **现象**：`SyntaxError: Unexpected token '﻿'`，脚本起不来。
- **证据（实测数字）**：PowerShell 5.1 的 `Out-File -Encoding UTF8` **会加 BOM**；已一次性清掉 `state\` 下 **26 个带 BOM 的 json**。
- **缓解**：写 JSON 一律用 node（`fs.writeFileSync(p, JSON.stringify(x))`）；读时 `replace(/^\uFEFF/,'')`。
- **怎么验**：`Get-Content <file> -Encoding Byte -TotalCount 3` 前 3 字节不是 `EF BB BF`；`node -e "require('./<file>')"` 不抛错。

### A5 · 交付文件名对不上票号 → 视同未交
- **现象**：01 收作业说"找不到能对上的交付"，文件其实在，只是名字不对。
- **证据（实测数字）**：自动认领靠**文件名里的单号**匹配；不符的那份会被标 `unlinked`（页面黄条），**1 次即整单重交**。
- **缓解**：`records\交付\<工号>-<YYYYMMDD>-<单号>.md`；名字不符或放错目录 = 视同未交。
- **怎么验**：落盘后看 `logs\workdesk.run.log` 有无 `[scan] <文件名> → <票号> submitted`；或 `curl 9340/api/worklist` 的 `unlinked` 里没有它。

### A6 · PowerShell 改 UTF-8 脚本把中文读成乱码
- **现象**：`Get-Content -Raw | Set-Content` 之后脚本语法报错，中文全成乱码。
- **证据（实测数字）**：PS 5.1 默认按 ANSI 读；**1 次**即需整文件重写（当日多份脚本受影响）。
- **缓解**：改脚本用 write 工具整体重写；或显式 `Get-Content -Encoding UTF8`。
- **怎么验**：改完 `node --check <脚本>` 通过，且 `Select-String` 能搜到中文关键字（不是问号）。

## B 级 · 知识性（设计如此 / 预期行为）

### B1 · 状态机不许 `queued → submitted`
- **现象**：放个交付文件，任务没被认领，日志写「不允许 queued → submitted」。
- **证据（实测数字）**：设计如此——`TRANSITIONS.queued = ['doing','dropped']`，**0 例外**。
- **缓解**：先派活（成 `doing`）再交文件；`queued` 阶段放文件会被标 unlinked。
- **怎么验**：`node scripts\worklist.mjs state W-xxx submitted` 从 `queued` 调 → 报「不允许」；从 `doing` 调 → 通过。

### B2 · 目标在跑时派活会 409
- **现象**：`dispatch` 报 `409 target-busy`。
- **证据（实测数字）**：防堆积，故意拒绝；**每工号同时只许 1 张 doing**。
- **缓解**：等它 `running=false` 再派（自动接力会自己补上）；**不许绕过去硬塞**。
- **怎么验**：看 `curl 9340/api/agents` 里该工号 `running=true`；等它空闲后重派成功。
