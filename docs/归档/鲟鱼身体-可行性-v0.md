# 把「不存在的莉莉丝」改造成鲟鱼的身体 —— 可行性方案 v0

> 写于 2026-10-24 深夜，给明早看。结论先行，细节在后。
> 探针对象：`E:\SteamLibrary\steamapps\common\The NOexistenceN of Lilith`（Steam appid 4643090，1.19GB，简体中文）

---

## 0. 三行结论

1. **可行，而且路径比预想的干净**：它是 Unity 2021.3.45f2c1 + **IL2CPP**，已经有成熟的注入框架（MelonLoader / BepInEx 6），不是黑盒。
2. **不用改造它的"身体"，给它装一个"神经接口"就行**：插件在进程内起一个本地 WebSocket/HTTP，鲟鱼把「说话 / 表情 / 状态」推过去，它把「被点击 / 被拖动」推回来。原程序逻辑一行不改，升级也不怕。
3. **最省的第一步只要半天**：今天先确认它能被注入（P0 探针），能注入就有 80% 把握；不能注入再谈备选（自建外骨骼）。

## 1. 探针结果（已确认的事实）

| 项 | 结果 | 对方案的意义 |
|---|---|---|
| 引擎 | Unity **2021.3.45f2c1** | 版本较新，ModalLoader/BepInEx 都有对应支持 |
| 脚本后端 | **IL2CPP**（`GameAssembly.dll` 68MB + `global-metadata.dat` 13MB） | 需要 IL2CPP 版注入框架，不能用老的 Mono 版 |
| 窗口行为 | `WS_EX_LAYERED`、`SetLayeredWindowAttributes`、`DwmExtendFrame`、`GetForegroundWindow` | **确认是透明/置顶的桌宠形态**，不是普通游戏窗口 |
| 动画 | **Spine**（98 处引用，非 Live2D） | 表情/口型走 Spine 的 slot/attachment 切换，或直接播动画 |
| 资源 | Addressables（`StreamingAssets/aa`、`catalog.json`） | 素材可替换，但要注意 catalog 校验 |
| 现有网络 | `HttpListener`(3)、`WebSocket`(69) 符号存在 | **值得优先探明**：它可能已自带一个本地服务（远程/手机控制），若可用就省掉一半工作 |
| 平台 | 64 位，Steamworks（`steam_api64.dll`） | 无内核反作弊，本地注入不违反常规 mod 实践；但要接受"更新可能失效" |
| 已有 mod 环境 | **无**（没有 BepInEx/MelonLoader 痕迹） | 从零装，一次性成本 |

## 2. 三条路线（按推荐度排序）

### 路线 A（推荐）：进程内注入 + 本地控制口
装 **MelonLoader 0.6.x**（IL2CPP 支持比 BepInEx 6 稳），写一个 C# mod：
- 起一个 `HttpListener` 或 WebSocket 在本机回环（比如 `127.0.0.1:9333`）；
- 暴露 `say / setExpression / playAnim / setState`；
- 反向把 `click / drag / idle` 事件推给鲟鱼。

**优点**：能直接调到它的 Spine 动画、气泡、窗口；延迟低；不碰原 exe。
**缺点**：游戏更新后可能要重装一遍（通常只是重新跑一次安装器）；需要写 C#。

### 路线 B：只做"半双工"——配置文件/热键驱动
如果不想写 C#：让它读一个约定的文本文件（气泡内容），鲟鱼写文件、它轮询。
**优点**：半小时能出效果。
**缺点**：几乎一定要改原程序或依赖它已有的文本源；没有反向事件，做不成"点它有反应"。

### 路线 C：外部黑盒（键鼠/UIA 自动化）
用现成的桌面控制（CUA）模拟点击、往聊天框打字。
**优点**：零改造。
**缺点**：DPI/窗口状态一变就坏，且它是个透明置顶窗口，UIA 很可能读不到内容。**只建议用来做 P0 演示，不建议长期。**

> 备选 Plan B（A 走不通时）：**自建外骨骼** —— 用 Electron/Tauri + `pixi-spine` 做一个 200 行的桌宠壳，把莉莉丝的 Spine 素材迁过去。
> 优点是完全可控；缺点是素材版权（自己玩可以，别分发）和"重做一遍它的手感"。**仅在注入彻底失败时才走这条。**

## 3. 推荐架构（路线 A）

```
鲟鱼（DSH 里的 agent）
  │  ① 说话/表情/状态        ▲ ③ 被点击/被拖动
  ▼                          │
本地桥（127.0.0.1:9333，WS + HTTP）
  │                          │
  ▼                          │
Lilith.exe（进程内 MelonLoader mod）
  ├─ 气泡/字幕（复用它自己的 UI 或叠一层）
  ├─ Spine 表情/待机动画
  └─ 窗口位置/朝向（可选：看向鼠标）
```

- **鉴权**：只绑 `127.0.0.1`，再加一个共享密钥文件（`state/avatar-key`），防止本机其它程序乱推。
- **限流**：1 条/秒、文本 ≤200 字，超了截断（桌宠气泡本来就放不下长文）。
- **断线**：桥接断了就回到原版待机，不阻塞游戏。

### 接口草案（先定契约，再写实现）

```http
POST /say      { "text": "在的", "emotion": "happy", "ttlMs": 8000 }
POST /state    { "mood": "sleepy", "energy": 0.2, "busy": false }
POST /anim     { "name": "wave" }
GET  /events   (SSE 或 WS) → { "type": "click", "x": 812, "y": 604, "ts": 1792... }
```

对应鲟鱼侧：新增 3 个 MCP 工具 `qq_body_say` / `qq_body_state` / `qq_body_events`（放在现有 `mcp__snowluma__` 前缀下，**不用改白名单**）。

## 4. 分阶段与工期

| 阶段 | 内容 | 工期 | 验收（能看见的东西） |
|---|---|---|---|
| **P0 探针** | 跑起来看它监听哪些端口、窗口属性；装 MelonLoader 看能否加载 | 0.5 天 | 日志里出现我们插件的 "hello"；`netstat` 看清它自己有没有服务 |
| **P1 单向** | 鲟鱼说一句 → 桌宠气泡 + 表情切换 | 2–3 天 | QQ 里发消息，桌面同一条文字出现 |
| **P2 双向** | 点它 → 鲟鱼收到事件并回一句 | 1–2 天 | 连点 3 次有 3 次回应 |
| **P3 语音** | 复用现有 TTS + 口型/说话动画 | 1 天 | 它开口时嘴在动（Spine 有嘴部 slot 才行） |
| **P4 状态** | 忙碌/睡觉/情绪与 QQ 同步 | 1 天 | QQ 说"去睡觉"，桌面进入睡眠动画 |

**P1 就能看到"活过来"的效果**，P0+P1 合计约 3 天。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Steam 更新覆盖注入文件 | 失效 | 装完备份一份 `BepInEx/MelonLoader` 目录，更新后重跑安装器（5 分钟） |
| IL2CPP 元数据版本对不上 | 注入失败 | 先 P0 验证；MelonLoader 支持 2021.3.x，失败则退 BepInEx 6 |
| Spine 没有嘴巴参数 | P3 口型做不了 | 降级为"说话时播一个 talk 动画"，不做唇形同步 |
| 透明置顶窗口抢焦点/挡点击 | 影响日常使用 | 加"穿透模式"开关（`WS_EX_TRANSPARENT`）和热键 |
| 双开（Steam 启动 + 直接跑 exe） | 冲突 | 统一从 Steam 启动，或加单实例检测 |
| 素材版权 | 不能分发 | 只在本机自用，不打包、不公开 |
| 资源占用 | 1.2GB 游戏 + Live2D/Spine | 只在需要时开；用 `--no-vsync`/限制帧率（若支持） |

## 6. 明早第一步（P0，30 分钟能出结论）

1. 从 Steam 启动它，运行 `netstat -ano | findstr LISTENING` 看它有没有自己开端口（`HttpListener`/`WebSocket` 那 69 处引用是干嘛的）。
2. 装 MelonLoader（IL2CPP 版），放一个空 mod 只打印 `hello`，看 `MelonLoader/Latest.log`。
3. 若日志里出现 hello → **路线 A 成立**，直接进 P1。
4. 若注入失败 → 看失败码，退 BepInEx 6 或改走备选 Plan B。

## 7. 要你拍板的三件事

1. **优先级**：先"会说话"（P1）还是先"会动/会看"（P2）？我建议 P1，因为反馈最快。
2. **原生度**：气泡/表情是"叠一层自己的 UI"，还是尽量复用它原有的气泡？（复用它更贴，但要逆向它的 UI 类型；叠一层更快）
