# 危险动作申请单（方案 v1）

> 2026-10-28 主人要求：审批弹窗先恢复，同时给一套"申请单"方案——不依赖弹窗、留痕、可批量批。

## 一、什么算"危险动作"（要申请）

| 类别 | 例子 |
|---|---|
| **删除** | 删任何非 `tmp` 的文件/目录；清空目录；删归档 |
| **安装/卸载** | 装软件、装插件、`pnpm add`、卸载运行库 |
| **提权** | 需要 UAC 的操作：改计划任务、改服务、改注册表、`runas` |
| **网络暴露** | 开端口到 `0.0.0.0`、改防火墙、把内网服务映射出去 |
| **凭据** | 写/改/上传任何 token、密钥、密码 |
| **对外** | 往 GitHub / 网盘 / 任何外部服务推送（本仓库白名单内除外） |
| **钱** | 任何会产生费用的开关（云服务器、API 额度、付费服务） |

**不需要申请的**：读写工作目录内的文件、跑脚本、起本地进程、读日志、`git` 本地操作。

## 二、申请单长什么样

落 `state\申请\<日期>-<序号>.md`：

```markdown
# 申请 #20261028-003
- 申请人：04·代码
- 类别：删除
- 目标：E:\DSH_workspace\tmp\drill-sandbox（12.4 MB，可重建）
- 为什么：演练临时目录，已清空演练票
- 不做的后果：占 12 MB，不影响功能
- 可回滚吗：能（重建脚本 scripts\drill.mjs 一键重建）
- 状态：待批
```

台账同步记一行（`op:'approval-request'`），并给**主人 + 本体**各发一封邮件（`level=活`）。

## 三、审批流程

1. **申请**：工号写单 + 记账 + 邮件；
2. **批准**：主人回「批 #20261028-003」或「全批今天 04 的」；本体可代批**非危险类**（删 tmp、装插件），**危险类必须主人**；
3. **执行**：执行方核对申请单状态=`已批` 才动手，**执行后在同单补一行结果**（成功/失败/实际影响）；
4. **复盘**：每日复盘时列出当天所有申请单——**未批的催、已批未执行的问、执行完的归档**。

## 四、安全阀

- **没有批准单就删/装/提权 = 事故**（比不干活严重），记日志并在复盘里点名；
- 申请单**不许在一小时内自己批自己**；
- 单次批量上限：一次最多批 20 项，超了必须分批说明。

## 五、与弹窗的关系

弹窗恢复后，两者并存：
- **弹窗**：临时、即时、易误点 → 适合"顺手一次"的操作；
- **申请单**：留痕、可批量、可复盘 → 适合"计划内的改动"。

**优先级**：申请单优先。弹窗只兜申请单没覆盖到的临时情况。
