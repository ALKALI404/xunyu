# 架构优先级：窗口是一等公民，莉莉丝是可选外设

> 主人 2026-10-27 00:23 定：「应该是本体直接接 avatar 目录下的窗口，莉莉丝是窗口连接的身体模块箱。」
> 立此存照，防止以后又把「外设掉线」当成「对话断了」。

## 一条链，两个等级

`
一等：本体 (DSH 会话)
        ↕  relay:9334  /lines · /chat · /pending
      对话窗 E:\DeepFish\avatar\window\XunyuChatWindow.exe
      这是主人真正读字的界面。它挂了才是真故障。

二等（可选外设）：
      对话窗 → 身体服务 body-service:9335 → 适配器 lilith → 游戏 mod:9333
      作用是让头像说话、做动作、摆表情。**没开就是没开**，不该影响上面那层。
`

## 硬规矩

1. **身体动作失败不得向上冒泡成对话错误**。外设不可用时，身体服务要降级返回 200 {ok:true, degraded:true, spoke:false}，不许吐 502。
2. 判断「降级还是真报错」看适配器健康：dapter.health().ok === false（已知掉线）→ 降级；适配器在线但单次动作失败 → 才允许 502。
3. 日志不许把降级写成「拒绝说话 / 转直连 mod」这种像故障的话；写成 外设不可用（lilith），/say 降级为静默 就行。
4. 窗口和本体**永远不因为莉莉丝没开而报错**。mod 没开是预期状态，不是异常。
