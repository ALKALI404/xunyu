## 四、怎么人为造一条审批（今天挖出来的，很关键）

`sessions/create` 传 `sandboxMode`/`approvalPolicy`/`permissionPreset` **都会被忽略**（试过 5 种参数名，全部 `danger-full-access` + `never`）。正确做法是**建完之后**用命令切权限档：

```js
api.callUnary('commands/execute', { agentId: '<sessionId>', line: '/permission workspace-write', submittedAttachments: [] })
// → preset workspace-write；approval/policy 从 never 变成 ask
// 然后让该会话写"工作区之外"的路径，就会产生 approval/requested，窗口里会弹卡片
```

`/permission` 可用档位：`read-only` / `workspace-write` / `danger-full-access`。

## 六、必须知道的坑（今天新踩的）

1. **桥接不能双开**：两个 `start.bat` 各跑一个 `bridge.js`，会用内存里的旧映射回写 `state/sessions.json` → 唤醒全投给已归档会话，症状是「回合完成但无文本」+ 目标会话 `updatedAt` 不动。改 `state/*.json` 前先数实例；重启要**包装 + node 一起杀**。
2. **`config.json` 不能带 BOM**：PowerShell 的 `Set-Content -Encoding utf8` 会写 BOM，`JSON.parse` 直接抛错（`error-book.mjs` 就因此退回空目录）。写完用 `[IO.File]::WriteAllBytes` 或 `UTF8Encoding($false)`。
3. **`loadConfig()` 是白名单**：往 config.json 加新键，**必须同时在 `loadConfig()` 里接出来**，否则静默失效（`delegateGate` 就这么白放了半年）。
4. **`confirmWakeSafetyV2` 的 stale 判据**：`!confirmedAt || now-confirmedAt > 24h`。任何重置 WakeConfig 的路径都可能把 `confirmedAt` 清成 0 → 下游一直当"未确认"。
5. **`.jsonl.zstd` 是多帧**：`zstdDecompressSync` 整块解只拿到帧头；要自己按 `28 b5 2f fd` 魔数切帧逐帧解（脚本见 `tmp\decode-transcript.mjs`）。
6. **PowerShell 5.1** 不支持 `??`；读 UTF-8 文件要 `-Encoding utf8`。
