## 写分册的硬要求

1. 用 `_模板.md` 的十节，**§8 演进必填**：现在独立还是隶属、将来归谁、迁移动哪些文件；
2. **归属变化是最大的债**：工作台→avatar、桥接守护→疼痛，这类变化必须当天写进对应分册；
3. 分册之间只许互相引用，不许复制内容（复制就会分叉）；
4. 改代码不改分册 = 没交付。

## 项目台账（机器可读，2026-10-28 D42）

`state\projects.json` 是「项目 → 子功能 → 单号」的**唯一真相**，05 维护，工作台项目视图（D43）消费。

**登记规则**：新增项目/子功能**当天**登记；一个分册 = 一个项目；`features[].tickets` 存单号（`D41`/`W1`），不存 `W-xxx`；`state` 只许 `active|planned|paused|done`；**进度不写进 json**（由 worklist 现算）。
**自检**：`node tmp\projects-check.mjs`（查 JSON 合法、单号在台账里查得到、单号不跨 feature 重复、每份分册都有对应项目、doc 路径存在、**功能域与并行标记齐不齐**），退出码 0 才算登记有效。

**并行规则（三条，别自由发挥）**：

1. **同一功能域内的单串行**——一个人手上不叠活，半成品打架比慢更贵；
2. **不同功能域可并行**，前提是 `blockedByDomain` 为空、契约不撞车；
3. **跨域依赖必须写进 `blockedByDomain`**，不许口头约；契约由域负责人定义并写进对应分册 §5，消费方不许各改各的。

**关于 `parallel` 的准确含义**：它标记的是**域与域之间是否解耦**（能不能同时开工），**不是人手够不够**。同一个工号拥有多个域时（例：04 同时是 `workdesk-core`/`cost`/`pain`/`bridge`/`memory` 的默认负责人），这些域**对他本人是串行的**，派单前先看他手上有没有 `doing`。

**当前可并行的一组（2026-10-28 20:12 实况）**：`window-web`(06) + `cost`(04) + `docs`(05)。
依据：①三个域默认负责人不同（06/04/05），不会撞同一个手腕；②三者 `blockedByDomain` 全空，互不为前置；③契约不重叠（`window.host.*` / `token.report.*` / `docs.entry.*`）；④当前在手的单也不重叠——`window-web` 在验 D46/D47/D52/D54，`cost` 在等 D44/D45 验收并排了 W-076 对账，`docs` 就是 D55 本身。
反例：`window-shell` 与 `window-web` 虽然分两个域，但共享 `window.host.*` 契约、且 `win-workspace`（D48/D49）显式 `blockedByDomain: ["window-shell"]`——壳没稳之前页面的工具区不许开工，这就是「不能并行」的样子。

## 项目与功能域分类规范（2026-10-28 D72）

> 判据来源：`docs\规则-开发与维护.md` **§二十四 B**（满足 ≥2 条才升格）。本文是**落地版**：给现有 7 个项目逐个下结论，并给每类例子。
> **一句话口令**：*这活能有自己的文档分册和负责人吗？能 → 项目；只是项目里的一块 → 功能域；一次能干完 → 单。*

### 一、三档判据

| 层级 | 判据（满足 ≥2 条才升格） | 典型票量 | 例子 |
|---|---|---|---|
| **项目** | ①有独立生命周期（会暂停/收尾）②有独立负责人 ③有独立文档分册 ④跨 ≥2 个工号长期协作 | 长期 | 工作台、窗口与身体、疼痛检测 |
| **功能域** | ①项目内可独立交付 ②预计 ≥3 张单 ③有明确契约边界（`window.host.*` 这类） | 3–10 张 | `ws-cost`、`win-workspace` |

### 四、归地方（硬规矩，防漂）

1. **域名不跨项目用**：`workdesk-core` 只出现在 `workdesk` 项目里，`window-shell` 只出现在 `avatar` 里；跨项目拿同一个域名 = 分类失效，05 每次复盘查一遍。
2. **功能域数上限 12**（`tmp\projects-check.mjs` 会拦）；要新建域先合并再新增。
   > 上限从 10 放到 12 的理由（2026-10-29 D90）：新增两条**独立产品线**——`wecom`（企微通道，03/06）与 `wecom-cs`（对外售卖的客服产品，06/04）。它们生命周期、负责人、契约都不同，塞进同一个域会导致"同域串行"，所以必须分开；其余 10 个域未变。
3. **tickets 不许手写**：`features[].tickets` 由 `projects-sync.mjs` 从台账反推（规则 §十），05 只维护 `id/name/domain/owner/summary/doc`。
4. **我的权限**（与规则 §二十四 A 一致）：能自主——归到哪个域、新建功能域、改 `domain/owner`、维护本题库与需求池归类；要确认——立项、暂停/合并/作废项目、改优先级、改规则实质。
5. **需求池状态由落地票推导**（同 D63 三级推导精神）：落地票有 `queued/doing/submitted` → `已派单`；全 `done` → `已完成`；明确不做 → `不做`。禁止写「进行中」这类枚举外状态。
