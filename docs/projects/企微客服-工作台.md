# 项目：企微客服工作台（wecom-cs）

> 状态：**planned → active 立项**（2026-10-29，从 `wecom` 通道里拆出来）｜负责人：06（前端/交互）· 04（后端/数据）｜文档：05
> **一句话**：**对外卖的**客服工作台产品——甲方在自己服务器上跑起来，多客服共用一个企微对外账号接待客户。
> 两份方案稿在 `docs\产品\`：`企微客服工作台-对外方案v1.md`（给甲方看）、`企微客服工作台-开发方案v1.md`（对内骨架）。

## 1. 定位

**产品**，不是内部工具：
- 谁用：企业微信里用**一个对外账号**接客户咨询的小团队（3–10 个客服）；
- 解决什么：消息散在几个人电脑里、谁回过说不清、历史留不住、没有统一看板；
- 卖法：**8,000 元/套买断**（1 账号 + 1 服务器）+ 建议 **1,500 元/年**维护；存档费 900/年、服务器、AI 费用客户自付。

**为什么单独立项**（规则 §二十四 B 逐条对照，命中 4/4）：

| 判据 | 是否命中 | 依据 |
|---|---|---|
| 独立生命周期 | ✅ | 有版本/交付/验收周期，卖出去后要长期维护 |
| 独立负责人 | ✅ | 06 主责（页面/交互），04 后端 —— 与通道侧 03 分开 |
| 独立文档分册 | ✅ | 本册 + `docs\产品\` 两份方案 |
| 跨 ≥2 工号长期协作 | ✅ | 06 + 04 + 05（文档）+ 03（部署形态） |

## 2. 边界

- **属于我**：工作台页面与交互、会话/客户/队列的数据模型、多租户目录、坐席分配、常用语、留档展示、对外交付文档。
- **不碰**：企微回调与隧道（`wecom` 册）、代持发送的**实现**（在 `wecom` 册）、各平台接入（`wecom-platform`）。
- **共享契约**（两边必须同时改）：①**队列契约**（任务/回执字段）②**存档数据格式**（会话内容存档解析后的消息结构）。

## 3. 架构（P0 计划）

```
浏览器（客服）
   │  HTTP（内网）
   ▼
工作台服务（P0 单租户） ── 读 ──▶ 消息库（存档接入落库 + 回调落库）
   │
   └─ 写队列 ─▶ 发送队列表 ─▶ 发送端（可替换，见 §4） ─▶ 回执 ─▶ 队列状态
```

三个组件（客户单台 Windows 服务器）：会话接入（wecom 册）· 客户端助手（wecom 册）· **工作台（本册）**。

## 4. 数据流与三条硬决策

**流**：客户消息 → 存档/回调 → 落库 → 工作台展示 → 客服回复 → 写队列 → 发送端 → 回执 → 状态回写。

| # | 硬决策 | 为什么 | 代价 |
|---|---|---|---|
| 1 | **队列解耦**：工作台不实时点客户端，只写队列等回执 | 多客服并发点击会抢焦点；GUI 自动化会失败；没回执答不了"发出去没有" | 发送延迟 1–3s；需要幂等键 |
| 2 | **多租户目录隔离**：`tenants\<租户id>\`（配置/库/日志/附件全在里面） | 买断意味着客户可能自建、也可能我们代管；一个目录带走全部数据 | 升级要按目录迁移（必须有迁移脚本 + 备份） |
| 3 | **发送端可替换**：`send(target,payload) → {ok,code,detail,msgId}`，三档实现（客户端助手 / 官方群发 / 未来会话式 API） | 官方通道随时会变，这是唯一能对抗"企微策略变更"的设计 | 多一层抽象，早期显得绕 |

## 5. 接口（P0 草案，待 04 评审定稿）

| 接口 | 方法 | 说明 | 花钱 |
|---|---|---|---|
| `/api/sessions` | GET | 会话列表（未读/分配/最后一条） | 否 |
| `/api/messages?session=` | GET | 消息流（分页，默认 200 + 每次 100） | 否 |
| `/api/send` | POST | 写发送队列（返回 taskId，不回传"已发送"） | 否 |
| `/api/queue/:id` | GET | 回执状态（queued/sent/failed+code） | 否 |
| `/api/assign` | POST | 分配/转接坐席 | 否 |

**队列契约**（与 `wecom` 共用，改要两边同步）：`{taskId, tenantId, accountId, target, contentType, payload, idemKey, createdAt}` → 回执 `{taskId, ok, code, detail, msgId, at}`。

## 6. 状态与存储

- **多租户目录**（决策 2）：`tenants\<租户id>\{config.json, db, logs, files}`；
- **P0 单租户**也走同样的目录结构（只是只有一个租户），避免以后迁移；
- **不可逆操作**：清租户目录（等于删客户全部数据）、存档断档（存档停服期间的消息拿不回来）。

## 7. 依赖

- **强依赖 `wecom` 册**：收（存档/回调）、发（代持发送）全靠它；通道挂 → 本产品"能看不能发"或"完全停摆"；
- 依赖企微「会话内容存档」开通（客户付费）；未开通 → 只能人工录入/只发不收；
- 被依赖：无（卖掉才有人用）。

## 8. 演进（归属要说清）

| 阶段 | 内容 | 归属 |
|---|---|---|
| **P0** | 单客户单租户：会话列表 / 聊天 / 发送队列 / 常用语 / 留档 | 本册（06+04） |
| **P1** | 多租户 + 令牌：一套部署服务多个客户，按目录隔离 | 本册（04 数据层）+ `wecom` 册（通道侧租户凭据） |
| **P2** | 智能客服：AI 建议回复/自动首答（AI 费用客户付） | 本册主导；模型接入方式待定 |
| **P3** | 多平台：淘宝/京东走各自「商家自研应用」，见 `docs\产品\平台接入对比-v1.md` | `wecom-platform`（04） |

**归属红线**：本册永远不改 `wecom` 的隧道/回调实现；`wecom` 永远不做页面。共享契约（§5 队列 + 存档格式）改动必须两边同时改。

## 9. 排障（P0 未开工，先列已知失败面）

| 症状 | 先看 | 说明 |
|---|---|---|
| 工作台显示"未发送"一直不退 | 发送队列 + 回执 | 队列积压 = 发送端没在跑（去查 `wecom` 册 §9） |
| 客服 A 发的、客服 B 看不到 | 租户目录 / 账号绑定 | 同一租户内应共享消息库；跨租户看不到是对的 |
| 历史消息缺一段 | 存档是否断档 | 存档停服期间的消息**拿不回来**，只能从开通日往后 |
| 页面打不开 | 工作台服务进程 | P0 单进程；挂了不影响 `wecom` 通道 |
