# ug-gate · 闸门与状态机

> 项目：upgrade ｜ 负责人：**04** ｜ 归档：`_archive/ug-gate/`

## 做什么

**把"规矩"变成"闸门"**：一切都是"该拦的拦住、该放的放行、拦错了能证明"。

- 预检门分级：**硬性 FAIL**（无类型行 / 无四段 / 文件名或目录不符）vs **软性 WARN**（缺 exit 码、缺代码块、缺回滚）——WARN **仍进待验收**，由 01 判；
- 台账状态机：`inbox→proposed→queued→doing→submitted→done/dropped`，禁 `queued→submitted`，允许 `doing→queued`；
- 依赖链：`blockedBy` 未完成 → `blocked` → 派发 409；前置 done 自动解锁 + 邮件；
- 验收自动触发（UG-005 在做）：`submitted ≥2` 摘要提醒、≥7 立即批量、4 小时未验升级；
- 未回执派生态（UG-007 排队）：派出去没人动 → 派生 `unacknowledged`，进"我发出没回"清单。

**不做什么**：
- 不改页面怎么画（06）；不改业务模块本身；不做"派给谁"的决策（01）；
- **不许自己发明判定标准**——门只能实现规则 §七/§八 已写的判定。

## 实现

## 怎么算过

1. **每条闸门都有"应当失败"的反例**：故意造一条不合规数据，闸门必须拦住（只给"全部通过"不算过）；
2. 门变更要带"旧数据不炸"的回归证据（拿历史不合规交付跑一遍，只该 WARN 的不能 FAIL）；
3. 状态机改动必须给出"非法边被拒"的实测输出。
