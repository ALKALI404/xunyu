# 派发送达契约（UG-039）

> 2026-10-30 立｜07 起草｜**先有此契约，再有实现**。
> 病根一句话：**把"我发出了"当成"他收到了"**——`dispatch` 只要 `sessions.prompt` 没抛异常就置 `doing`，
> 而 DSH 可以回 `accepted:false`（或整条 RPC 失败），票却已经在台账里显示"已派"，于是空转。

## 1. 一句话契约

**派发 = 送达才叫派。** `accepted === true` 之前，票**不许**离开 `queued`。

## 2. 接口

### 2.1 `dispatchOne(ticketId) -> { delivered, attempts, lastError? }`

| 字段 | 类型 | 语义 |
|---|---|---|
| `delivered` | boolean | 这次尝试是否**被对方接收**（`accepted === true`） |
| `attempts` | number | 这张票累计尝试次数（含本次；从 `state\delivery-retry.json` 读，不依赖进程内存） |
| `lastError` | string? | 失败原因（`code: error` 摘要），成功时缺省 |

补充字段（实现可见，不属契约核心）：`code`（失败码：`rpc-error` / `rejected` / `no-agent` / `quota` …）、`sessionId`、`ms`。

### 2.2 送达判定（唯一判据）

```
sessions.prompt({sessionId, mode:'queue', content:[{type:'text',text}]})
  → response.result.ok === false            ⇒ 未送达（code=rpc-error）
  → response.result.value.accepted === true ⇒ 送达
  → response.result.value.accepted === false ⇒ 未送达（code=rejected）
```

**不许**用"没有抛异常"当送达证据；**不许**用"审计里记了一行"当送达证据。

### 2.3 失败退避（最多 5 次）

| 次 | 距上次等待 |
|---|---|
| 1（首次） | 0（同步尝试） |
| 2 | 1s |
| 3 | 5s |
| 4 | 30s |
| 5 | 120s |
| （第 6 次不存在） | 300s 仅作为"第 5 次失败后"的收官等待 → 记 `escalated` |

> 实际实现：`BACKOFF_MS = [1000, 5000, 30000, 120000, 300000]`，`attempts` 从 1 起算；
> `attempts >= 5` 之后不再自动重试，标记 `escalated:true` 并写错题本。

### 2.4 数据文件

`state\delivery-failures.jsonl`（append-only，一次失败一行）：

```json
{"ts":1793290000000,"ticket":"WS-012","target":"07","attempt":2,"code":"rejected","error":"accepted=false"}
```

`state\delivery-retry.json`（当前未送达的排队表）：

```json
{"tickets":{"W-270":{"ticket":"WS-012","target":"07","attempts":2,"firstAt":...,"nextAt":...,"lastError":"...","escalated":false}}}
```

`state\mistakes.jsonl`（错题本，连续 5 次失败写一条）：

```json
{"ts":...,"kind":"delivery-failed","ticket":"WS-012","target":"07","attempts":5,"error":"...","suggestion":"..."}
```

## 3. 命令

```powershell
node scripts\worklist.mjs dispatch <票号> [--force] [--session-id <会话id>]   # 派发（含同步送达确认）
node scripts\worklist.mjs undelivered                                        # 列出未送达
node scripts\worklist.mjs retry                                              # 跑一轮到期的重试（守护/手工）
```

- `--session-id` 是**验收/排障口**：显式指定用哪个会话投递，用来复现 `accepted:false`（正常路径按标题选工号会话）。
- `undelivered` 输出：票号 / 单号 / 目标 / 失败原因 / 重试次数 / 下次重试时间 / 是否已放弃。

## 4. 接口（看板）

`GET /api/dispatch/status` →

```json
{ "delivered": 12,
  "undelivered": [ { "id":"W-270","ticket":"WS-012","target":"07","attempts":3,"error":"...","escalated":false } ],
  "retrying":    [ { "id":"W-270","ticket":"WS-012","target":"07","attempts":3,"nextAt":..., "nextAtText":"..." } ] }
```

- `delivered`：台账里 `deliveredAt` 有值（即收到过 accepted 回执）的票数；
- `undelivered`：**派了但没送到**的票（含还在重试的）——`escalated:true` 表示已放弃；
- `retrying`：其中还可自动重试的（`escalated:false` 且 `attempts < 5`）。

## 5. 状态机（一个字都没改）

- 未送达：票**留在 `queued`**，台账 `dispatchedAt` 不刷新（不进 doing，自然不算"已派"）；
- 送达：`setState(doing)` → 紧接一条 `op:'accepted'` 事件（`from:'dispatch'`）→ `deliveredAt` 有值；
- 为什么是两条事件：`setState(doing)` 会把 `deliveredAt` 归零（UG-007 语义），所以送达事实必须**后写**。

## 6. 回滚

`DELIVERY_CONFIRM=0`（环境变量）→ 退回旧行为（投了就算，不校验 accepted、不排队重试）。**默认开**。
另有 `DELIVERY_BACKOFF_MS`（逗号分隔，默认 `1000,5000,30000,120000,300000`）可调退避——只给验收用，生产别改。

## 7. 边界

- 只改 `dispatch-core.mjs`、`worklist.mjs` 的 dispatch 分支（+新增 `undelivered` / `retry`）、`workdesk-server.mjs` 加一条 GET；
- **不动** `build-exe`（04 在做）、不动状态机语义、不动 DSH 侧。
