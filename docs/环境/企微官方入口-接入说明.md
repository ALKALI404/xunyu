# 企微官方入口（AI Bot 长连接）· 接入说明

> 2026-10-30 02 装好待凭证｜插件：`sliverp/DeepSeek-harness-wecom` v0.1.5（git `e241355`）
> 与本目录旧方案的关系：`企微VM通道-现状与卡点.md` 走的是「VM 里跑企微客户端 + GUI 自动化」，脆在窗口枚举/键盘注入；**这条是官方长连接，不开 GUI、不要公网、不要 VM**。两套互不冲突，这条通了可以停掉分 VM。

## 1. 它怎么工作

企微后台开「智能机器人（AI Bot）」→ 选**长连接**模式 → 插件用官方 SDK `@wecom/aibot-node-sdk` 主动连出去，收消息转给 DSH agent，回复走同一连接。
凭证只有两个值：**Bot ID** 和 **Secret**。缺任一个，插件**休眠**（只打一行 inactive 日志），不影响 DSH 启动，也不影响网页会话。

## 3. Bot ID / Secret 从哪来

1. 打开企微管理后台（`https://work.weixin.qq.com`）→ **应用管理** → **智能机器人**（有的版本叫「AI 助手 / 机器人」）；
2. 新建或打开一个机器人 → 接收模式选 **长连接（WebSocket）**，不要选「回调 URL」；
3. 页面上直接给出 **Bot ID**，并生成/显示 **Secret**（Secret 只显示一次，随手存好）；
4. 把这个机器人**加进要用的群**，或允许单聊。

## 4. 填哪（两个值，别写进仓库）

- **Bot ID** → `C:\Users\Xuchi\.dsh\.env` 追加一行：
  ```ini
  WECOM_BOT_ID=你的botid
  ```
- **Secret** → 不要写进 `.env`；用 DSH 的凭据服务，存成引用名 `WECOM_BOT_SECRET`（插件按这个名字取）。若一时没有凭据界面，可临时在 `.env` 里写 `WECOM_BOT_SECRET=...`（插件支持环境注入，属开发用法）。
- 可选：`DSH_WECOM_CWD=E:\DeepFish\Xunyu`（agent 工作目录，默认取 DSH 启动目录）。

## 5. 接进 desktop profile（本机没有 `web` profile，只有 `desktop`）

任务书原命令 `pnpm dsh plugin --profile web add …` **在本机跑不了**：PATH 里没有 `dsh`，随包运行时只有 node/pnpm/python，`dsh` 本体在 `app.asar` 里。等价手工装法如下（三处改动，改完必须重启 dsh）：

1. `C:\Users\Xuchi\.dsh\profiles\desktop\package.json` → `dependencies` 加一行：
   ```json
   "deepseek-harness-wecom": "link:C:/Users/Xuchi/.dsh/plugins/deepseek-harness-wecom",
   ```
2. 同一文件 → `dsh.profile.bundles` 追加一项：`"deepseek-harness-wecom"`（它自带 `dsh.bundle.patch`，会自动插入 `wecom-channel` 行）；
3. 建 Junction（PowerShell，管理员）：
   ```powershell
   New-Item -ItemType Junction `
     -Path 'C:\Users\Xuchi\.dsh\profiles\desktop\node_modules\deepseek-harness-wecom' `
     -Target 'C:\Users\Xuchi\.dsh\plugins\deepseek-harness-wecom'
   ```
4. 重启 DSH（**这会断掉当前会话，动手前先报本体**）。

改前备份在 `E:\DSH_workspace\backup\WC006-20261030-001026\`（package.json / cordis.patch.yml / compatibility.json 三件）。

## 6. 怎么验

| 场景 | 期望 | 命令 |
|---|---|---|
| 没填凭证（当前状态） | DSH 正常起、网页会话正常，日志出现休眠行 | `Select-String C:\Users\Xuchi\.dsh\logs\desktop-next.log -Pattern 'WeCom channel is inactive'` |
| 填了凭证 | 日志出现连接/就绪，不再有 inactive 行 | 同上，换成 `-Pattern 'WeCom|wecom-channel'` |

| 网页回归 | 会话照常，无白屏 | 打开 `http://127.0.0.1:53389`（端口每轮可能变，看日志里的 URL） |

插件里休眠日志的三条原文（`dist/index.js` L776-790）：
`WeCom channel is inactive: configure botId or WECOM_BOT_ID to enable it` / `…secretRef is empty` / `…credential %s is not configured`

## 7. 怎么退（任一步都够用）

1. 只停用：从 `dsh.profile.bundles` 删掉 `"deepseek-harness-wecom"` → 重启；
2. 全退：删 `dependencies` 里那行 + 删 Junction + 删目录 `C:\Users\Xuchi\.dsh\plugins\deepseek-harness-wecom` → 重启；
3. 凭证泄露应急：企微后台**重置 Secret**，再清 `.env` 与凭据项；
4. 想整份回到装之前：用上面备份目录里的三件覆盖回 profile → 重启。

## 8. 已知限制

- 一个 DSH 进程只连一个机器人；多群靠同一个 Bot 的会话区分。
- 群消息默认策略要显式配（`singlePolicy` / `groupPolicy`），默认值见插件 README，不配就是最保守那档。
- 插件 0.1.5 的 peerDependencies 要求 `@deepseek-ai/dsh-* >= 0.1.0-rc.7`；本机 dsh 是 0.2.1-rc.2 一代，满足要求，但**升级 DSH 大版本后要复验**（尤其 `ctx.credentials` 接口）。
