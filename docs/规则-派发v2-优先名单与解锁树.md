# 派发规则 v2 · 优先名单 + 解锁树（2026-10-30 02:55 主人定）

> 主人原话：
> 「待办投送改成现在在优先投送名单的自动按照解锁树派发，这一类存在时先不做其他任务，这一类全部完成之后再按照之前的规则谁闲着谁开工。」
> 例子：程序化这一批任务，优先名单里有它就先把它们全做完，再回到"谁闲着谁开工"。

## 一、三条规则（按优先级从高到低执行）

### 规则 1：优先名单窗口（preemption window）
`state\priority-list.json` 里**非空**时，进入「优先窗口」：
- 只派名单内的票（及其解锁子票）；
- **不允许**任何工号领名单外的票（`claim` 与 `dispatch` 都拦）；
- 名单外的票保持 `queued`，不删不弃。

### 规则 2：按解锁树派发（unlock tree）
名单内的票组成**依赖图**（`state\worklist.jsonl` 已有 `blockedBy`/`dep` 关系）：
- **只派"依赖全清"的叶子票**，一次可并行派给多个**空闲**工号；
- 每完成一张，**立刻**重算可派集合（父票解锁子票）；
- **依赖成环 / 依赖指向已弃票** → 报错并停下，不许瞎派。

### 规则 3：名单清空后回落
优先名单里**所有票进入 `done`**（或明确 drop）后：
- 自动**关闭优先窗口**，回到旧规则：**谁闲着谁开工**（autoRelay 重新生效）。

## 二、数据结构

`state\priority-list.json`：
```json
{
  "active": true,
  "createdAt": "2026-10-30T02:55:00+08:00",
  "reason": "程序化：exe 化 + 71 脚本迁移",
  "tickets": ["UG-028", "UG-029", "UG-030"],
  "note": "tickets 支持项目/功能域简写，如 project:upgrade"
}
```

**字段规则**：
- `tickets` 可用 **单号**（`UG-028`）、**项目**（`project:upgrade`）、**功能域**（`feature:ug-gate`）；
- `active:false` 或 `tickets:[]` = 无优先窗口；
- 每次变更写 `state\priority-log.jsonl`（谁改的、为什么）。
