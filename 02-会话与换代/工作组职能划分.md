## 二、00 号（记录与交接）详细职责 ★ 主人点名要的

**职权（2026-10-26 主人明定）**：00 号对**工作组的交接记录、归档、职权划分**有**全权**——

- 谁负责哪块（职能划分与工号分配），它说了算，改完报本体与主人即可；
- 交接记录谁写、什么时候写、留多久，它定；
- 旧会话、旧工号、旧归档的处置（归档/保留/清理），它定；
- 与其它工号起冲突，先由 01 裁；裁不了，00 有最终裁定权，再上报主人。

它是**唯一有权改交接稿的人**，也是唯一维护名册的人：

1. **名册**：`<工作区>\ROSTER.md` + `state\roster.json`
   - 每个工号：职能、会话 id、标题、当前任务、最后活跃时间、负责的文件面；
   - 每次派活/收活都更新一行，别人一眼看得出「现在谁在干什么」。
2. **交接**：按 `docs\交接流程.md` 执行第 3–6 步（建会话 → 改名 → 换绑 → 复述验证 → 归档旧会话 → 日志留痕）；
3. **交接稿**：写、更新、归档；内容必须带「已完成/进行中/下一步/关键路径/未做完的坑」；
4. **工作日志**：`<工作区>\工作日志.md` 按天记，只记「做了什么、结论是什么、证据在哪」；
5. **周报**：每周一次，从日志和名册里压出来。

**它不做的**：不写代码、不装插件、不动系统配置——它只保证「有人做了、做得有记录」。

## 三、派活路由

```
本体（鲟鱼）派活
   │
   ├─ 明确属于某职能 → 直接投对应工号（按标题，如 "鲟鱼工作组工号04·代码"）
   │
   └─ 拿不准 → 投 01（总务），由它判断并转交，同时通知 00 记名册
```

任务单四要素（我派活时固定写）：

1. **目标**：一句话说清要什么；
2. **验收**：怎么算完成，可复现的用例；
3. **边界**：能碰什么、不能碰什么（文件/目录/进程）；
4. **回滚**：改坏了怎么退。

回报三行（固定格式，缺一行算没交付）：

```
改了什么：…
怎么验的：…（命令/返回/日志行）
怎么回滚：…
```

## 四、跨部门协同

**原则**：部门之间不直接互相派活，走「01 串线」或「00 记录」，避免口头交接丢信息。

**典型链路**（代码 → 插件 → 部署 → 记录）：

| 步骤 | 谁 | 产出 |
|---|---|---|
| 1. 写/改实现 | 04 代码 | 代码改动 + 自测结论 |
| 2. 打包/接进宿主 | 02 插件 | bundle 产物 + 兼容性状态 |
| 3. 部署与守护确认 | 03 维护 | 进程/端口/令牌状态 |
| 4. 记录与交接 | 00 记录 | 名册更新 + 日志条目 |
| 5. 验收（可选） | 06 | 用例结果 |

**协同通道**（三样，够用）：

1. **`shared` 作用域记忆**（engram）：规则、决定、验收标准——`engram_search(scope=shared)` 谁都能查；
2. **名册**（`records\ROSTER.md`）：谁在干什么，实时；
3. **交接稿/工作日志**：长周期上下文，00 维护。

**跨会话的实时协同**（我和 01 现在这样）：本体派活 → 对方回合处理 → `qq_dsh_wait` 取回 → 转述/继续。多部门时，由 01 在中间串，不让 02/03/04 直接互投（会互相打断回合）。

## 五、拆分时机与红线

**新增工号必须先经主人批准**（2026-10-26 定）：出现新需求时，由 **01 汇总提报 → 主人拍板 → 00 记录并执行命名/建会话**。01 和 00 都不许自行开新员工；00 只管把批下来的登记进名册。

**什么时候拆**（满足任一条）：

- 01 同时压着 ≥2 个不同职能的活，且互相阻塞；
- 某职能每周占用超过 10 次派活；
- 出现「改代码的和装插件的互相踩」这类事故。

**并行上限**：同时活跃的工号 ≤4 个（含 01），再多就没人看得住。

**红线（任何工号都不许碰）**：

- 人格与记忆（`<Xunyu根>` 下 `roles/`、`memory/`）——只有本体和主人能动；
- 交接稿的最终版本（只有 00 写，主人可改）；
- 审批与权限（谁批谁，走原流程，不因拆分改变）。

## 六、落地步骤（拆的时候照做）

1. 00 先建 `records\ROSTER.md`，把现有 01 登记进去；
2. 按需开 02/03/04：建会话 → 改名 `鲟鱼工作组工号NN·职能` → 写首条任务 → 00 登记；
3. 本体派活模板改成「按职能投递」，拿不准投 01；
4. 跑一周，看名册和日志是否对得上；对不上就说明 00 的职责没落地，先修流程再拆更多。
