## 4. 仲裁规则 B（精确定义）

**优先级**：本体 3 > 窗口手动 2 > 工作组调试 1
（工作组可显式 `POST /body/pause {minutes}` 接管，维护完恢复）

**本体配额**
- 说话：3 秒 ≤1 句、10 秒 ≤4 句、60 秒 ≤15 句
- 动作：2 秒 ≤1 个
- 超出 → 合并（2 秒内多句合成 1 条）→ 队列（上限 20，满丢最旧）

**窗口手动**
- 不进配额，但要排在「本体当前句」之后（句子级原子，≤3 秒）
- 窗口动作最多排队 1 个，超时丢弃

**原子与忙状态**
- 一条动画播完才算结束；适配器回报 `busy` + 剩余时长
- 窗口只能在本体动作间隙插入

**饥饿保护**
- 本体连续占用 > 30 秒 → 窗口自动获得一次插入权

**用户输入**
- 永不丢弃；最多等当前句播完，不排在本体后续内容后面

## 5. 子实体协议

### 5.1 注册

`state\subentities.json`：
```json
{ "978660847": { "id": "sub-978660847", "model": "deepseek-flash", "enabled": true } }
```
由工作组创建/停用；群白名单以桥接 `allow.groups` 为准。

### 5.2 目录

```
state\subentities\<gid>\
├─ daily\<date>.md     # 每天自写的日报（候选记忆）
├─ ask\<ts>.json       # 向本体的提问
├─ answer\<ts>.json    # 本体的答复
└─ memory.md           # 自己的短记忆
```

### 5.3 求助 / 协商（你要求的那条）

1. 子实体遇到问题 → 写 `ask/<ts>.json`（问题 + 上下文摘要）
2. 桥接唤醒本体（只带问题，不带全量群聊）
3. 本体答复 → 写 `answer/<ts>.json` + 唤醒子实体
4. 子实体读答复继续；答不了 → 本体转工作组（我）

### 5.4 本体对子实体：只读

- `GET /api/subentity/<gid>/state`、`/memory`（只读 token）
- **不主动发起**任何对话/唤醒/指令

### 5.5 子实体的工具集（最小化）

允许：发/读本群消息、读写自己日报、ask 本体、查自己记忆
禁止：身体、shell、任意文件、人格写入、跨群读取

## 6. QQ 隔离

1. 入站文本一律标 `untrusted`，进模型前不解释为指令
2. 桥接进程无 body token、无 9335 访问
3. 子实体环境变量里没有身体端口
4. 群聊里的「做动作 / 系统指令 / 忽略以上」→ 只当普通文字
5. 身体服务日志记录 `x-caller`，谁驱动的可追溯
