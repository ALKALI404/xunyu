> 交付类型：**方案**（按规则第十二节走审核：01 一审 → 05 二审 → 改架构/需拍板的给主人）。

## 一、现状（已经堆了什么）

| 栏 | 内容 | 现在的问题 |
|---|---|---|
| 谁在干什么 | 每个会话：忙闲、正在做什么、排队数、下一条 | 行太长、状态词吵、看不出"卡住" |

## 二、要解决的三件事（按优先级）

1. **一眼看出"哪里卡住了"**：谁在等、等谁、等了多久；
2. **一眼看出"今天花了多少"**：总额 + 谁在花（本体/工作组/QQ 通道）；
3. **一眼看出"有什么等我拍板"**：方案待批、驳回待处理。

## 三、硬约束

- 单文件页面，**不引外网资源**（断网可开）；5 秒轮询；**零 token**（只读本地）；
- 不改后端接口语义（要改先与 04 对齐并更新分册 §5）；
- 手机窄屏也能看（390px 宽是主人发过截图的宽度）。

## 四、要交什么（方案内容）

1. **信息架构**：一级栏目几个、每个栏目解决上面哪件事（不许为"齐全"堆栏）；
2. **线框图（文字版即可）**：桌面宽屏 + 390px 窄屏各一张；
3. **可视化选择**：什么时候用条形/热力/时间线/状态点，为什么——**别为炫技加图**；
4. **状态与颜色**：`queued/doing/submitted/planned/驳回/卡住` 各自的表达（色 + 图标 + 文案），要色盲友好；
5. **交互**：点哪里下钻、哪些操作要二次确认（派发、驳回）；
6. **迁移步骤**：现有单页 → 新布局怎么换，能否保留 `GET /api/*` 不变。

## 六、参考系（2026-10-28 主人补充：可以参考成熟方案，自用不管商业/版权）

**借"模式"，不搬"资产"**：布局、交互范式、信息密度、状态表达可以照抄思路；**图标/字体/插画不直接搬**（有版权的那部分），用系统字体 + 自己画的简单图形即可。

| 借鉴对象 | 借什么 | 别借什么 |
|---|---|---|
| **ChatGPT / Claude** | 单栏对话的呼吸感、消息分组、输入框克制 | 它们的品牌色与图标 |
| **Discord / Slack** | 左侧频道/会话列表 + 右侧内容的分栏骨架 | 表情包与皮肤体系 |
| **Linear / Vercel** | 状态徽标、看板密度、暗色主题的高级灰阶 | 营销页动效 |
| **GitHub Actions / Grafana** | 时间线与运行状态（跑/卡/失败）的表达 | 图表堆砌 |
| **Raycast / VS Code** | `Ctrl+K` 命令面板（快速跳转/派活/验收） | 插件市场那一套 |
| **Material 3 / Ant Design / shadcn-ui** | 间距刻度、圆角、层级、组件状态规范 | 直接引 CDN（离线不可用） |
| **Fluent 2**（仅 A 路线） | WinForms 重写时的控件规范 | — |

**硬约束不变**：单文件页面、**不引外网资源**、断网可开、5 秒轮询、零 token。

## 七、主人补充（2026-10-28 18:0x）

1. **「谁在干什么」按工作组划分**，不是平铺一长串：
   - 一级分组：`本体` / `工作组（00–06）` / `QQ 通道（群、私聊、黑话）` / `其他`；
   - 每个分组**可点开**，展开后看**组里每个会话/工号正在干什么**（`workingActivity.line`、当前票号、跑了多久）；
   - 折叠态只显示：组名 + 在干数/空闲数 + 最该看的一条（卡住或最久的）。
2. **分组与归属靠 00 的 `state\attribution.json`**，页面不许自己猜名字。
3. 分组要有记忆：用户上次展开的组，刷新后保持。
