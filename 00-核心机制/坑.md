# 坑清单（踩过的，别再踩）

> 交接必读。每条写清：**症状 / 根因 / 正确做法**。踩到新坑就往这儿加，别只写在工作日志里。

## 2026-10-28

### 1. 账本 `cacheHit` 是"读到多少"，不是"新增多少"
- **症状**：按行相加算花费，一天能算成 ¥430（实际 ¥30 级）。
- **根因**：每步都上报"该步读到的完整前缀"，同一次调用的前缀被重复计。
- **正确**：按 `(sessionId, turn)` 分组，`cacheMiss/output` 累加、**`cacheHit` 取 max**。见 `scripts\token-report.mjs`。

### 2. bridge 的 `relayReplies` 用数组下标当游标
- **症状**：QQ 侧反复收到"同一批回执"，一条回执循环四五遍。
- **根因**：`/api/dsh/wait` 的 `after` 是数组下标，而数组有 50 条上限、会 `shift()`；一裁剪，所有客户端游标错位。
- **正确**：游标改成**单调序号**（`relayReplySeq` + `pushRelayReply`），已修，见 `state\bridge-魔改清单.md`。

### 3. `paused` 有两份，改错那份不生效
- **症状**：`config.json` 里写了 `socialV2.paused=true`，QQ 照旧接话。
- **根因**：**运行态在 `state\social-v2.json`**，启动时从它读（`bridge.js` L10261）；`POST /api/socialV2/config` 也不改这个标志。
- **正确**：改 `state\social-v2.json` 的 `paused`，再重启桥接。

### 4. JSON 文件带 BOM，`require()` 直接炸
- **症状**：`SyntaxError: Unexpected token '﻿'`。
- **根因**：PowerShell 5.1 的 `Out-File -Encoding UTF8` **会加 BOM**；`require()`/`JSON.parse` 不认。
- **正确**：写 JSON 一律用 node（`fs.writeFileSync(p, JSON.stringify(x))`）；读时 `replace(/^\uFEFF/,'')`。已把 `state\` 下 26 个带 BOM 的 json 清掉。

### 5. `session/create` 不接受 `cwd` + `workspaceId` 同时给
- **症状**：新会话能建，但**不在工作区里**（侧栏看不到、`workspace.json` 的 sessionIds 没有它）。
- **根因**：错误写法 `{cwd, workspaceId}` → 报 `accepts workspaceId or cwd, not both`；只给 `cwd` 就落到默认区。
- **正确**：**只给 `{ workspaceId }`**（cwd 由工作区带）；或直接走 `handoff.mjs new`。

### 6. 状态机不许 `queued → submitted`
- **症状**：放个交付文件，任务没被认领，日志写「不允许 queued → submitted」。
- **根因**：设计如此——**必须先 `dispatch` 成 `doing`**，防止"没派就自己交"。
- **正确**：先派活再交文件；`queued` 阶段放文件会被忽略。

### 7. 目标在跑时派活会 409
- **症状**：`dispatch` 报 `409 target-busy`。
- **根因**：防堆积，故意拒绝。
- **正确**：等它 `running=false` 再派（自动接力会自己补上）；**不许绕过去硬塞**。

### 8. 交付文件名必须对得上票号
- **症状**：01 收作业时说"找不到能对上的交付"，实际文件在（只是名字不对）。
- **根因**：命名 `工号-日期-单号` 不统一，自动认领认不出来。
- **正确**：`records\交付\<工号>-<YYYYMMDD>-<单号>.md`；**名字不符或放错目录 = 视同未交**。

### 9. 方案 ≠ 做完
- **症状**：只交了设计稿的工单被标成 done，活就消失了。
- **根因**：验收只看"有没有文件"，没看交付类型。
- **正确**：交付第一行写类型（方案/实现/修复/文档）；方案通过记 `planned` 并**必须派生 `-impl` 实现单**。

### 10. PowerShell 改 UTF-8 脚本会把中文读成乱码
- **症状**：`Get-Content -Raw | Set-Content` 之后脚本语法报错，中文全成乱码。
- **根因**：PS 5.1 默认按 ANSI 读。
- **正确**：改脚本用 write 工具整体重写；或 `Get-Content -Encoding UTF8` 显式指定。
