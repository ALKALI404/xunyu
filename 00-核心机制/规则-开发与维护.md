## 十一、交付类型与「方案 ≠ 做完」（2026-10-28 主人指出 D14 被误标完成）

**事故**：D14 工单写「先出设计再动」，04 交了设计稿、**一行代码没改**，我却按「完成」验收 → 活消失了。
**根因**：验收只看「有没有文件」，没看「交付的是什么类型的活」。

**规矩**

1. **交付文件第一行必须写类型**：`方案` / `实现` / `修复` / `文档`。没写类型 → 01 直接 reject。
2. **验收按类型判**：

| 类型 | 验什么 | 通过后状态 |
|---|---|---|
| **方案** | 可行性、影响面、迁移步骤、风险 | **`planned`**（不是 done），**必须派生 `-impl` 实现单** |
| **实现** | 可复跑自测（命令+输出+退出码）、边界、与文档一致 | `done` |
| **修复** | 复现步骤 + 修前/修后对比 + 回归 | `done` |
| **文档** | 分册与代码一致、§8 演进写清 | `done` |

3. **状态机新增 `planned`**：`queued → doing → submitted → planned(方案通过)`，`planned` 必须挂着实现单，否则不算完。
4. **01 的对账义务**：工单要的是「实现」而交付是「设计稿」时，**不许标 done**——要么 reject，要么转 `planned` 并立刻建实现单。
5. **本体抽查也查这条**：看到 done 里混着"只出方案"的，视为验收事故，记日志。

## 十二、方案（设计稿）审核流程（2026-10-28 主人逐条定）

**1. 哪些算方案**：交付文件第一行标 `类型: 方案`。凡「先出设计再动代码」「可行性/迁移/架构调整」类工单都必须标；没标就直接 reject。

**2. 交给谁审**（两级，按风险定）：

| 级别 | 审核人 | 审什么 | 时限 |
|---|---|---|---|
| 一审 | **01** | 可行性、影响面、迁移步骤、回滚方案、四段式齐不齐 | 4 小时 |
| 二审 | **05** | 与现有分册是否冲突、§8 归属写清没有、会不会造成重复建设 | 8 小时 |
| 拍板 | **主人** | 改变架构/归属/花钱路径的（例：工作台并入 avatar、记忆库更换） | 等主人 |

**3. 审核进行到哪，要看得见**：状态字段 `planState = 待审 | 01审中 | 转05 | 待人工 | 通过 | 驳回`，带 `reviewer`、`reviewedAt`、`planNote`。页面一栏「方案审核」，每条显示当前卡在谁那、等了多久。

**4. 审核过了** → 状态 `plan-approved`，**自动派生 `-impl` 实现单进工作列表排队**（不是直接开工）。

**5. 审核没过** → 写清 `planNote`（缺什么，一句话），状态 `plan-rejected`，**放进「人工待审核箱」**，并**自动发邮件给提交工号 + 01**：「这条方案驳回，原因 X，该工作尚未开始」。页面待人工那栏标红，直到有人处理。

**一句底线**：**方案通过 ≠ 活干完；方案驳回 = 明确告知这项没做**，不许静默躺在 done 里。

## 十四、干活的依赖链（2026-10-28 主人要求）

**问题**：现在是"谁闲着就派谁"，不管前置做完没有。例：窗口 UI 要等 03 把 WebView2 装机验通，06 才能开工——没这条链，06 会对着装不了的壳子白干。

**规矩**

1. **任务可声明前置**：`blockedBy: [W-045, ...]`；前置未 `done`，本任务状态 `blocked`。
2. **`blocked` 不许派发**：`dispatch` 遇到 `blocked` 直接拒绝（`409 blocked`），自动接力也跳过。
3. **自动解锁**：前置转 `done` 后，本任务自动从 `blocked` 回 `queued`，并给目标工号发一封邮件「前置已完成，可以开工」。
4. **链要看得见**：页面显示「等 W-045（03·WebView2 验证）」，并且能点过去看前置进度；一条链最长三段，超过就是拆单没拆好。
5. **CLI**：`worklist.mjs dep W-046 --on W-045`（加）、`--off`（去）、`list --blocked`。

**当前已挂的链**：窗口实现（W1-impl）← 依赖 ← `W-045`（03 的 WebView2 可行性验证）。
**不挂的**：工作台 UI（W-046）不依赖安装，独立进行。
