## 1. 已实测的事实（照这个做，别再试错）

| 动作 | 可行做法 | 不可行 |
|---|---|---|
| 找窗口 | 按进程名 `WXWork.exe` + 标题「企业微信」动态查找（**pid 会变**：今晚从 37712 变成 32068） | 写死 pid / 窗口句柄 |
| 切会话 | 后台点击左侧列表项（坐标相对窗口，等比换算） | 搜索框输入（会抢焦点） |
| 输入文本 | **前台 `SendInput` 逐字**（`mode=keystrokes`） | 后台 PostMessage（**群聊输入框不接收**，文件传输助手可以） |
| 发送 | **前台按回车**（`press_key return`）；点击「发送(S)」按钮亦可 | 后台 PostMessage 回车（无效） |
| 成功后判据 | 输入框清空 + 左侧会话预览出现该文本前缀 | — |

## 2. 做什么

`scripts\wecom-hold.mjs`：

```
node scripts\wecom-hold.mjs send --chat "<群名或会话名>" --text "内容"
node scripts\wecom-hold.mjs send --chat "<群名>" --text-file <路径>
node scripts\wecom-hold.mjs list            # 列出左侧会话名（读屏辅助，可选）
```

要求：
1. **动态发现窗口**：`WXWork.exe` 全部窗口里找标题含「企业微信」且可见的那个；找不到 → 退出码 2 并提示"客户端没开/被最小化到托盘"；
2. **切会话**：在左侧列表里用**会话名匹配**（可按行高与序位估算，或维护 `state\wecom-hold.json` 的 `chat -> y 偏移` 映射，首次人工标定）；
3. **发送**：点输入框 → **前台**逐字输入 → 前台回车；整段不超过 2 秒抢焦点；
4. **发送后校验**：等 1.5 秒截图存 `logs\wecom-hold\<时间>.png`，并检查输入框区域是否变空（像素/文本变化均可），失败则退出码 3；
5. **不抢焦点时也要能读回**：`--verify-only` 只截图不发送。

## 3. 什么算过

- 往「文件传输助手」发一条 → 截图能看到（贴图路径）；
- 往「重庆自成一派网络科技有限公司」发一条带时间戳的文本 → 群里/截图能看到（**这条要先报本体确认再发**）；
- 客户端重启后（pid 变化）脚本仍能找到窗口并发送（贴两次不同 pid 的日志）；
- 输入框为空、客户端最小化时 → 退出码非 0 且有可读提示。
