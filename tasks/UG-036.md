## 0.5 预期结果

任何票被 `reject`（打回）时：
1. **项目栏**对应 feature 自动出现 **返工印记**（`rework: 次数`、`lastReworkAt`、`lastReason` 摘要）；
2. **项目的错题本**自动追加一条：时间 / 票号 / 第几次返工 / 打回原因（原话）/ 证据指针 / 怎么改；
3. 错题本可读（markdown，按项目一页），**人手改会被下一轮覆盖**。

## 接口契约

- `recordMistake({project, feature, ticket, attempt, rejector, reason, evidence, fix}) -> void`：追加写 `state\mistakes.jsonl`。
- `resolveMistake(ticket) -> void`：把该票最近一条标 `resolved:true`。
- `GET /api/projects`：feature 增加 `{rework, lastReworkAt, lastReason, openMistakes}`。

## 1. 做什么

### A. 数据
- `state\mistakes.jsonl`（append-only）字段：
  `{ts, project, feature, ticket, attempt, rejector, reason, evidence, fix, resolved}`
- `reason` **保留打回者的原话**（不许改写、不许摘要掉细节）；
- `attempt` = 该票第几次被打回（1、2、3…）。

### B. 触发（两处）
1. `worklist reject <id> --reason "..."` → **必须**要求 `--reason`（现在可空，改成必填）；
2. `accept` / `done` 时把该票最近一条 mistake 标 `resolved:true` + `resolvedAt`。

### C. 项目栏投影（`/api/projects`）
每个 feature 增加：
```
rework: 3,                 // 该 feature 下所有票的累计返工次数
lastReworkAt: "2026-10-30T00:20:00+08:00",
lastReason: "证据重复：两套关闭态是默认态拷贝",
openMistakes: 1            // 未 resolved 的条数
```

### D. 错题本渲染
- `scripts\mistakes-sync.mjs`：读 jsonl → 生成 `docs\projects\<project>-错题本.md`，标记区间 `<!-- mistakes:begin -->`；
- 每项目一页，按时间倒序，**每次返工一条**，含"原因 / 证据 / 怎么改"三列；
- **未解决的排最前**（红色标记 `⚠ 未解决`）。

## 2. 预期结果

- 打回一张票 → 项目栏 `rework` +1、错题本新增一条；
- 该票后来 accept → 那条 mistake 变 `resolved:true`，错题本里去掉 ⚠ 标记；
- 重复打回同一张票 → `attempt` 递增（1→2）。

## 3. 验收与判据

- ① `reject` 不带 `--reason` 被拒（贴）；
- ② 打回后 `mistakes.jsonl` 新增一条，`reason` 与打回原话**逐字一致**（贴）；
- ③ `/api/projects` 里该 feature 的 `rework/lastReason` 正确（贴）；
- ④ `docs\projects\auto-错题本.md` 里能看到这条且带 ⚠（贴）；
- ⑤ 同票二次打回 → `attempt=2`（贴）。

## 4. 边界

- 改 `worklist.mjs`（reject/accept）+ 新增 `mistakes-sync.mjs` + `/api/projects` 投影；
- **不改**历史 mistake 内容（只追加、只标 resolved）。

## 5. 回滚

- `--no-mistakes` 可关；错题本文件可整个删除再生。
