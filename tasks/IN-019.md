## 接口契约

1. 录入流程（个人页底部「＋ 录入保单」）里加一个**开关**：
   - 文案：**「只录关键信息（不解析条款）」**，**默认勾选**；
   - 勾着时：只要求读**保单资料页 / 缴费表 / 现金价值表**，**不调用条款解析**；
   - 取消勾选：才走 `IN-015` 的条款索引（慢，几十页）。
2. 传参：`POST /api/draft` body 增加 `parseClauses: false|true`（默认 `false`）；
   接口把该值写进草稿 `{parseClauses}`，**后续解析按它决定**。
3. 页面提示（说人话）：
   - 勾着：「只录关键信息，几十秒就好；条款以后要问再解析」；
   - 取消：「会读整份条款，可能要几分钟」。
4. **草稿要记这件事**：`parseClauses` 与 `pending` 一起存，**关闭再打开仍然记得勾没勾**。

## 0.5 预期结果

丢一份 40 页保单进来，默认只读 3 页关键信息，**几十秒出草稿**；只有主人主动取消勾选，才会去啃条款。

## 1. 做什么

1. `窗口\index.html`：录入区加开关 + 两段提示文案；
2. `窗口\server.mjs` 的 `/api/draft` 接收并保存 `parseClauses`；
3. 草稿卡上显示：「条款：未解析（要问再解析）/ 已解析」；
4. 与 `IN-018`（04 的草稿接口）对齐：字段名统一 `parseClauses`。

## 2. 可验方式

- ① 录入区截图：开关默认**勾选**，文案正确；
- ② 传一份 PDF（默认勾选）→ 贴草稿 JSON 里 `parseClauses: false`；
- ③ 取消勾选再传 → `parseClauses: true`；
- ④ 关闭页面重开 → 草稿卡的"条款未解析/已解析"提示仍正确（截图）。

## 3. 边界

只改 `index.html` 与 `server.mjs` 的 draft 相关字段；**不改条款解析本身**（那是 IN-015）。

## 4. 回滚

`index.html.bak-in019`、`server.mjs.bak-in019`。

## 5. 附加要求

- 默认值**必须是"不解析"**（省时间、省上下文）；
- 提示文案**说人话**，不出现"解析器/管道"这类词；
- 交付带证据（截图 + 草稿 JSON），没证据算没交。
