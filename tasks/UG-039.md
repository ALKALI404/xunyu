## 0.5 预期结果

**派发 = 送达才叫派**：`accepted:false` 时**不许把票标记为"已派"**，并**自动重试**（退避 1s/5s/30s/2min，最多 5 次），仍失败则**标 `undelivered` 并告警**，绝不假装送达。

## 1. 做什么

1. `dispatch-core.mjs` 里把"送达确认"变成**硬条件**：
   - `prompt()` 返回 `accepted:true` → 票置 `doing` + 记 `deliveredAt`；
   - `accepted:false` → 票**留在 `queued`**，写 `state\delivery-failures.jsonl`，**按退避重试**；
2. **未送达清单**：`node scripts\worklist.mjs undelivered` 列出来（票号/目标/失败原因/重试次数）；
3. **看板**：`/api/dispatch/status` 暴露 `{delivered, undelivered[], retrying[]}`；
4. **告警**：连续 5 次失败 → 记 `escalated`，进 `state\mistakes.jsonl`（错题本）。

## 2. 预期结果

- 人为让目标会话不可用 → `dispatch` **不把票标成已派**，进 `undelivered`；
- 恢复后重试成功 → 票自动转 `doing`。

## 3. 验收与判据

- ① 造一次 accepted=false（用一个已归档会话 id）→ 票仍 queued 且出现在 `undelivered`（贴）；
- ② 恢复正确 id 后重试 → 票转 doing 且 `deliveredAt` 有值（贴）；
- ③ 退避日志（1s/5s/30s…）可查（贴 3 行）；
- ④ `/api/dispatch/status` 三字段正确（贴）。

## 4. 边界

- 只改 `dispatch-core.mjs` + `worklist.mjs` 的 dispatch 分支 + 一个新的查询命令；
- 不改状态机语义（queued→doing 仍由"送达"驱动）。
