## 一、要什么（两半，同一张票的后端）

**① 后台监控（一个进程，管所有）**

现在的看护是散的：`services-guard.mjs`（5 分钟一拍）、`qq-bridge-watchdog`、`workdesk-guard`、`XunyuServicesGuard`……**谁也不知道谁在管什么。**

**要合成一个 supervisor**：
```
services.json（注册表，唯一真相）
{
  "services": [
    { "id": "workdesk", "name": "工作台", "port": 9340,
      "cmd": ["node","scripts\\workdesk-server.mjs"], "cwd": "E:\\DSH_workspace",
      "health": "http://127.1.1.2:9340/api/health", "deps": [],
      "restart": { "maxPerHour": 5, "backoffMs": 5000 },
      "log": "logs\\workdesk-out.log" }
  ]
}
```

**行为**：
1. **每 15 秒巡一次**（比现在 5 分钟快得多）；
2. **挂了 → 按依赖顺序拉起**（如：桥先起，再起依赖它的 relay）；
3. **拉起失败 → 退避重试**（5s / 15s / 60s，一小时最多 5 次，**超了不再硬拉，改为告警**）；
4. **每次动作写** `logs\supervisor.jsonl`（谁、什么时候、为什么、结果）；
5. **对外只暴露一个只读接口**：`GET /api/supervisor`（服务清单 + 状态 + 最近 20 条事件）；
6. **自我保护**：supervisor 自己也由计划任务每分钟拉一次（**单实例锁**，别起一堆）。

**② 台前调度（给窗口/工作台用的接口）**

```
GET  /api/supervisor                 → 全部服务状态（红绿灯 + 端口 + 上次动作）
POST /api/supervisor/restart {id}    → 手动重启某个（人审）
GET  /api/supervisor/events?limit=50 → 事件流（谁挂过、拉起了几次）
```

**这两个接口挂在工作台（9340）**，不另开端口（**少一个口少一份维护**）。

## 接口契约

```
GET  /api/supervisor
  → { ok, at, services:[{ id, name, port, up:true|false, since, restartsLastHour, lastAction }] }

POST /api/supervisor/restart  { id }
  → { ok, id, action:"restarted|already-up|failed", ms }

GET  /api/supervisor/events?limit=50
  → { ok, events:[{ at, id, action, detail }] }
```

**错误码**：404 未知服务 / 429 一小时内重启次数超限（**并说明超限，别静默**） / 500 拉起失败（附命令与退出码）。

## 0.5 预期结果

**手动杀掉 9351 或 9340 → 15 秒内自己回来**；**打开工作台「调度台」能看到所有服务的红绿灯和最近事件**；**一小时内反复挂会停下来告警，而不是无限重启**。

## 1. 做什么

1. 写 `tools\services.json`（**把现有 8 个服务全登记进来**：工作台 9340 / 窗口反代 9342 / 保险 9343 / QQ 桥 3100 / 学习区 9350 / 引擎 9351 / 临时考场 9352 / relay 9334）；
2. 写 `scripts\supervisor.mjs`（巡检 + 拉起 + 退避 + 事件 + 单实例锁）；
3. 工作台加三个只读/动作接口；
4. **把旧的散装守护停掉**（`services-guard` 等），**只留 supervisor**（**旧的先禁用，不删**）；
5. 计划任务 `XunyuSupervisor` 每分钟拉一次（**幂等，有锁**）。

## 2. 可验方式

- ① `GET /api/supervisor` 列出 8 个服务与状态（贴 JSON）；
- ② **杀掉 9351 → 15 秒内自动起来**（贴时间戳 + `supervisor.jsonl` 那行）；
- ③ **杀掉一个起不来的（故意给错命令）→ 三次退避后告警**（贴事件）；
- ④ `POST /api/supervisor/restart {id:"workdesk"}` → 成功（贴返回）；
- ⑤ 一小时重启超限 → 429（贴返回）；
- ⑥ **单实例**：连跑两次 supervisor，只有一个在跑（贴 pid 与锁）。

## 3. 边界

- **只管我们自己起的本地服务**（不管 DSH 本体、不管 SnowLuma 这种第三方）；
- **不改各服务自己的代码**；
- **不许无限重启**（必须退避 + 上限）。

## 4. 回滚

新增 `services.json` + `supervisor.mjs`；旧守护脚本只禁用不删，**回滚就是重新启用旧计划任务**。

## 5. 附加要求

- **拉起要脱离父进程**（`wscript`/`detached`），否则 supervisor 一死孩子跟着死；
- **事件要人能读懂**（"9351 挂了，15:03 拉起失败（端口占用）"），不要只写 exit code；
