## 0.5 预期结果

`projects.json` 成为**唯一派单源**：`dispatch` 不传单据号时，从项目栏按 **P0→P1→P2 + 依赖已清 + owner 空闲** 取票派发；票完成后项目栏自动出现进度行；票与项目栏不一致时**拒绝派发**。

## 1. 做什么

1. **schema 扩展**（`state\projects.json` 的每个 feature 增加）：`priority`（P0/P1/P2）、`owner`、`parallel`、`blockedByDomain`、`contract`、`tickets`、`note`；
2. **派发源**：`worklist dispatch --from-projects`（或默认行为）按上述规则选候选；**不传 ticket 时自动挑**；
3. **状态投影**：`/api/projects` 返回每个 feature 的 `{total, done, doing, queued, blocked, currentTicket, lastProgress}`（**运行时算，不写文件**）；
4. **回写**：票 `done` 时，feature 的 `note` 追加一行 `[2026-10-30 04:00] UG-029 done`（脚本生成，人去改会被下一轮覆盖）；
5. **一致性闸**：票的 `project/feature` 不在项目栏 → `dispatch` 拒绝（`409 not-in-project`）；
6. **看板/窗口**：项目页签一屏看到 **P? / owner / 完成 x/y / 卡点**。

## 2. 预期结果

- 项目栏里 P0 有未完成票时，P1 派不出去；P0 全完成后 P1 自动可派；
- done 一张票，项目栏 `note` 自动多一行；
- 造一张"项目栏里查不到"的票 → 派发被拒。

## 3. 验收与判据

- ⑤ 散票被拒（贴 409）。
