# 工单 D62 · 台账工具的 note 截断与「补证据」通道（派 04）

> 派单 2026-10-28 20:45 本体｜01 反馈：`--note` 被静默截断，且 `state` 不允许同态改写，补不了证据

## 1. 两个缺陷（01 实测）

1. **`--note` 静默截断**：`accept W-096 --note "…"` 落库只剩「01 亲手跑三条：①坏交付 」，后面证据全丢，**没有任何提示**；
2. **没有补证据通道**：`state` 不允许同态改写（`done → done`），于是"验收结论不完整"这件事**无法补救**，只能另存到 `收作业汇总`。

## 2. 做什么

1. **截断要显式**：`--note` 超上限时
   - 打印警告：`⚠ note 超 N 字，已截断（建议用 --note-file 传长文本）`；
   - 同时给出上限值；退出码仍 0（不算失败，但必须提示）；
2. **新增 `--note-file <路径>`**：从文件读长文本（≤ 8KB），避免 shell 截断与转义问题；
3. **新增 `comment` 事件**：`worklist.mjs comment W-096 --body "补充证据：…"`（或 `--body-file`）——
   - **不改状态**，只往台账追加一条 `op:"comment"`；
   - `list --detail W-096` 能按时间线看到该票全部 note/comment；
   - 回放兼容：老的 `state` 行不受影响。
4. **状态机不动**：`done → done` 仍然非法（这是对的），补证据走 `comment`。

## 3. 什么算过

- 传一条 2000 字 note → 有截断警告 + 上限值（贴输出）；用 `--note-file` 传同样内容 → 完整落库（贴 `list --detail` 前后对比）；
- 对一张 `done` 的票执行 `comment` → 成功、状态仍是 `done`、`list --detail` 能看到该 comment（贴）；
- 用 `04-20261028-D30.md` 的验收要求那条被截断的 note 做实测：**补一条 comment 把 01 的完整证据写进去**（就补 W-096 那条）。

## 4. 边界

- 只改 `scripts\worklist.mjs` 与 `scripts\worklist-core.mjs` 的事件写入/回放；
- 不改状态机合法边（`doing→queued` 由 D58 负责）、不动页面、不动 `state\projects.json`。
