## 一、对比表（它的 vs 我们的）——**这张表是这张票的核心**

| 诊断能力 | **whale_girl 有** | **鲟鱼现在有** | 差距 |
|---|---|---|---|
| **版本/运行时长/Node 版本** | `/api/status` 全给 | 无（只有 `/api/health` 粗粒度） | 🔴 缺 |
| **模型状态**（provider / model / baseUrl / key 掩码 / 是否 mock / temperature） | ✅ 全给，`keyMasked` 掩码 | 无 | 🔴 缺 |
| **记忆/存储用量** | `memory: storeSummary()` | 无 | 🔴 缺 |
| **花费/预算快照** | `budget: budgetSnapshot()` | `cost-core` 有，但**没进工作台** | 🟡 有数据没界面 |
| **渠道网关状态**（每个 gateway 的 status） | `gateways[].status()` + `webhookPaths` 列表 | 工作台只有 ports 存活探测 | 🟡 粗 |
| **微信账号/联系人** | `/api/wechat/accounts`、`/contacts`、`/contacts/sync` | 无 | 🔴 缺 |
| **桥心跳** | `/api/bridge/heartbeat` | 桥自己有，**没有聚合视图** | 🟡 散 |
| **会话/上下文快照** | `/api/debug/state`、`/debug/sessions` | 有 sessions 投影，但**没有调试入口** | 🟡 有数据没入口 |
| **提示词实时调试** | `/api/debug/prompt`（能直接试提示词） | 无 | 🔴 缺 |
| **最近发言者（填主人名单用）** | `recentSenders()` | 无 | 🟡 可要可不要 |
| **预算估算** | `/api/budget/estimate` | 无 | 🟡 缺 |
| **服务守护/重启** | 无（它不管服务） | **WS-016 在做**（比它强） | 🟢 我们强 |
| **票/工人/队列** | 无 | **我们有**（比它强） | 🟢 我们强 |
| **自检（selftest）** | 弱 | 无（散在脚本里） | 🔴 缺一个"一键自检"入口 |

**结论一句话**：**它强在"单个进程的自我透视"（模型/记忆/预算/网关/账号），我们强在"多进程与多工人"（服务、票、队列）。** 两边拼起来才完整。

## 二、集成目标（鲟鱼后台管理 = 工作台）

**工作台加「总控台」，一屏四栏**：

```
┌ ① 实体（进程/服务）────────────────────┐
│ 服务红绿灯（WS-016） + 一键重启         │
│ 桥/relay/引擎/工作台/学习区/保险        │
└───────────────────────────────────────┘
┌ ② 渠道（桥接）────────────────────────┐
│ QQ（SnowLuma）：在线/离线/最近一条      │
│ 微信（whale_girl）：小号在线/最近一条    │
│ 窗口：relay 绑定 2/2                    │
└───────────────────────────────────────┘
┌ ③ 脑子（模型/记忆/人设）───────────────┐
│ provider / model / key 掩码 / 是否 mock │
│ 记忆条数 / 库大小 / 人设文件与版本       │
│ 提示词试跑框（不落库，只回预览）         │
└───────────────────────────────────────┘
┌ ④ 花钱与票─────────────────────────────┐
│ 今日花费 / 轮次 / 命中量级               │
│ 票队列 / 工人压力 / 待验收               │
└───────────────────────────────────────┘
```

## 三、接口契约（**聚合，不新造数据源**）

```
GET /api/console          → 四栏一次给全（3–5 秒缓存；顶层 ok:true = "这份报告拿到了"）
  {
    ok, at, cached, degraded,
    services: [...],                                  // 透传 WS-016 supervisor
    channels: {
      qq:    { state:"ok|unreachable", online, lastAt, sentToday, recvToday, detail },
      relay: { state:"ok|unreachable", bound, total:2, lastAt, detail },
      files: { state:"not-implemented", detail }      // WS-028 之前固定这个
    },
    brain: { persona:{file,mtime,chars}, memory:{files,lines,bytes},
             model:{available:false, note:"经 DSH，无本地读数"} },
    cost: { today, turns, tokens },
    tickets: { queued, doing, submitted }, agents:[...]
  }
  // 错误语义（《开发规范》§四）：supervisor 不可用 → 503 {ok:false,error:"supervisor-unreachable"}
  // **渠道不可用不是接口错误**：200 + state:"unreachable"；不许 200 + ok:false

POST /api/console/restart  { id }          → 复用 WS-016（不重写）
GET  /api/console/selftest → { at, summary:{pass,fail,skipped}, checks:[{name,state:"pass|fail|skipped",detail}] }
                                             // 不吃缓存，5 秒限频
```
