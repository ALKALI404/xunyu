## 接口契约

**接口未变**：只改默认值语义与 CSS 规则，不改 URL、不改 JSON 结构、不改函数签名。

**唯一变化是「默认态」**：
```
工作台：html 上 data-glass 缺省 → 现在视为 1（开玻璃）
        改后 → 缺省视为 0（关玻璃，与窗口壳一致）
显式覆盖：data-glass=1 / data-glass=0 的行为不变
```

**判据要读的计算值**：`getComputedStyle(document.documentElement).getPropertyValue("--l1-blur")`（关玻璃应为 0px，开玻璃 24px）。

## 0.5 预期结果

默认状态下，工作台与窗口壳的 `--l1-blur` **都为 0px**（纯白外壳、可读优先）；需要磨砂时两边都得显式打开。

## 1. 做什么

把工作台的玻璃默认态从「开」改成「关」，与窗口壳 `tokens.css` 里 `html[data-glass="0"]` 的默认语义对齐；显式开关行为保持不变。

## 2. 预期结果

- 两个界面默认看起来一致（纯白外壳）；
- 开玻璃后两边仍然一致（令牌同源已在 WS-009 验证）；
- 正文卡在关玻璃状态下对比度更好（这本来就是窗口壳选「关」的理由）。

## 3. 验收与判据

- ① **默认一致**：不清 cookie、不加 query，打开工作台首页与窗口壳页，分别读 `--l1-blur` 计算值，**两者相等且为 0px**（贴两条取值）；
- ② **显式开关仍有效**：给工作台加 `data-glass="1"` → `--l1-blur` 变 `24px`；窗口壳同样操作 → 24px（贴第二组）；
- ③ **反例（必须做）**：删掉 `data-glass` 属性 → 工作台必须**回到 0px**（证明默认态真的改了，不是靠某个开关残留）；
- ④ **可读性回归**：关玻璃状态下贴一张正文卡截图，文字对比度明显（不要白底浅灰字）。

## 4. 边界

- 只改工作台自己的样式与默认值（workdesk 相关文件）；
- **不改窗口壳 tokens.css**（那是另一套，改动要 01 批）；
- 不改 `workdesk-server.mjs` 的令牌读取逻辑（WS-009 刚验证过，别动）；
- 要协调找 01。
