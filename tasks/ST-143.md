# ST-143 · 答题页：已回答 / 过往答案 / 分析 / 再次作答 + 状态徽标

> 建单 2026-11-07 22:35｜目标 **06（界面与交互）**｜项目 study / feature st-quiz-nav
> 主人口诉：「我进入答题做过题的位置是空的，应该是**已回答 + 过往答案 + 分析 + 再次作答**，保留每一次的作答结果，**已经完成的章节测试显示为已通过或待重做**」
> 前置：ST-142 的 `/quiz/history`、`/quiz/section/summary`、`/quiz` 的 `previous` 摘要（04 在做）

## 一、一道题进来该长什么样

```
┌ 题 1/2 · 边界题 ─────────────────────────────┐
│ 【题干】甲说「这本书肯定对，因为作者是院士」…      │
│                                                │
│ ● 已回答 2 次 · 最近：半对（11-07 07:07）        │
│   ┌ 我的答案（第 2 次 · 半对）─────────────┐    │
│   │ 逻辑学管的是推理……                     │    │
│   │ 漏了：诉诸权威不算论证                 │    │
│   └────────────────────────────────────────┘    │
│   ┌ 我的答案（第 1 次 · 半对 · 用过提示）──┐    │
│   │ 逻辑学管的是推理，只听过……             │    │
│   └────────────────────────────────────────┘    │
│                                                │
│ [再答一次]  ← 点开才是输入框 + 提交              │
└────────────────────────────────────────────────┘
```

**规则**：
1. **一进来先展示历史**（不默认给空输入框）——**这是主人抱怨的核心**；
2. **每次作答一条**：第 N 次、判定、时间、原话、漏了哪些要点；
3. **默认折叠最近 2 次**，「展开全部」看更多（最多 20）；
4. **「再答一次」按钮 → 展开输入框**；提交后**历史立刻多一条，旧的仍在**；
5. **没做过的题**：直接给输入框（跟现在一样）。

## 二、状态徽标（章节/小节上）

```
小节 chip：
  未作答       灰
  在做         浅蓝
  已通过       绿（浅）
  待重做       橙（浅）
  已读（无题） 灰蓝
```

**章节行**：`第2章 · 论证的分析  [在做 1/4]` 或 `[已通过]` 或 `[待重做]`。
**色盲友好**：chip 里必须有字，不能只有颜色。

## 接口契约（用 ST-142 的）

```
GET /quiz?bookId=&chapter=&section=     → questions[i].previous = {count,lastVerdict,lastAt,best}|null
GET /quiz/history?bookId=&chapter=&questionId=  → attempts[]
GET /quiz/section/summary?bookId=&chapter=&section= → {state:"todo|in_progress|passed|rework", answered, attempts}
```
