# 工单 D70 · 预检门分级放宽 + 单号查重（派 04）

> 派单 2026-10-28 21:45 本体｜01 实测：D57 的预检门过严——74 份交付里 47 份 FAIL，活干完了却卡在 `doing`（W-102/W-103 就是被它挡住的）
> 原编号与 `D67`（签收事件）撞号，重编为 **D70**

## 1. 根因（我设计过严，认）

`check-delivery.mjs` 把「修复类必须有 exit 码 + 命令代码块」当成**硬性 FAIL**，而验收规则（第十节判定 6）只要求**可观察证据**（截图 / 日志 / `200` / mtime）——**门比验收标准还严**，于是好活进不了待验收，票永远挂 `doing`。

## 2. 做什么

1. **门分两级**：
   - **硬性（FAIL，不许进 submitted）**：无类型行；无四段式；文件放错目录/名字不符；
   - **软性（WARN，仍进 submitted，由 01 判）**：修复类缺 `exit` 码；缺代码块；缺"回滚"小节；缺"已读规则 vX"确认行；
2. **区分新旧**：`--new-only`（默认）只对**本次认领的文件**报警，历史文件不重复刷；`--all` 才全量；
3. **失败要说清**：门拒绝时**自动给提交工号发邮件**，写明「缺哪几条、按第十节判定 6 可用什么替代证据」；
4. **单号查重**：`add` 时若 `--ticket` 已被别的票占用 → **拒绝**并列出占用者（今天 `D67` 撞号，两张票同号）。

## 3. 什么算过

- 拿 `06-20261028-D59.md`（修复类、只有截图与日志）跑 → **WARN 进 submitted**（贴输出）；
- 拿一个**没有类型行**的假文件跑 → **FAIL 且不进待验收**（贴）；
- `--all` 跑 74 份 → 列出 FAIL 清单（应只剩硬性缺项）；`--new-only` 只报新的（贴对比）；
- 门拒绝时邮件确实发出（贴 `mail.mjs tail` 或 seq）；
- `add --ticket D67`（已占用）→ 拒绝并列出占用者（贴）。
