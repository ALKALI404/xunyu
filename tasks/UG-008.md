## 1. 现状的问题
- `state\projects.json` 里功能域只有 `id / name / owner / parallel / tickets / note`；
- **没有领地边界**：没人能说清"这个功能域包含什么、不含什么、改它要不要问谁"；
- 结果：同一件事两个工号都碰（今天 wecom-relay 与 wecom-send 边界就模糊），记忆也散在会话里。

## 2. 做什么（六件套，但 v1 只强制 4 件）

对**每个**功能域（当前 `wecom-relay / wecom-send / wecom-cs / wecom-platform / ws-* / wg-* / ug-*` 等）：

| 件 | 落点 | 强制? |
|---|---|---|
| ① README（做什么/不做什么/边界） | `docs\projects\features\<域id>.md` | **强制** |
| ② 私有记忆（当前状态与卡点，≤2KB） | 同文件「当前状态」一节 | **强制** |
| ③ 归属与改动权（谁能改、改前问谁） | 同文件「谁说了算」一节 | **强制** |
| ④ 归档目录（只进不改） | `docs\projects\features\_archive\<域id>\` | **强制**（可为空目录） |
| ⑤ 专属脚本/面板（可空但要声明） | 同文件「实现」一节 | 建议 |
| ⑥ 验收要点（这域怎么算过） | 同文件「怎么算过」一节 | 建议 |

另外：
1. `projects.json` 每个 feature 加 `doc` 字段指向 ①；
2. `scripts\module-doctor.mjs` 加检查：**缺 ①②③④ 任何一件 ⇒ 报 ⚠ 并列出缺哪件**；
3. 先给 `upgrade` 项目的 4 个域做样板（今天正在做的这批），其余域**列出待补清单**即可，不必一次补完。

## 3. 验收与判据

- `upgrade` 的 4 个域（ug-gate/ug-rules/ug-state/ug-ref）四件齐全（贴目录与文件）；
- `module-doctor` 能报出**缺件**：故意删一个域的 README ⇒ 报 ⚠ 并指出缺"README"（贴）；
- 其余域有"待补清单"（贴数量：X 个域待补）；
- `projects.json` 的 feature 有 `doc` 字段（贴一条）。

## 4. 边界

- 只动 `docs\projects\features\*`、`state\projects.json`（加 doc 字段）、`scripts\module-doctor.mjs`；
- **不新建** 项目/功能域（那是另一个流程），只给现有的补件。

## 5. 回滚

- 全为新增文件 + 一个字段，删除/还原即回滚；`projects.json` 改前备份。
