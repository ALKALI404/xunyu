## 接口契约

**闸**：`config.chat.acceptGroups:false`（默认 false）；`src\pipeline\chat.js` 入口 `msg.chatType==='group'` → 记一条 debug `group-skip` 并直接 return（不触发、不记忆、不回）。

**待办 = 提醒队列的用户视图**（同一份存储，两个视角）：

```http
GET  /api/todo?due=1              → { ok, items:[{id,title,dueAt,status,createdAt,doneAt,repeat}] }
POST /api/todo { title, dueAt, repeat? }          → { ok, id }
POST /api/todo/{id}/done          → { ok, item }
POST /api/todo/{id}/cancel        → { ok, item }

# 不变（桥接仍读这两个）
GET  /api/reminders/due           → { ok, items, nextDueAt }
POST /api/reminders/ack           → { ok, item }
```

`status ∈ pending|done|cancelled`；`dueAt` 为 ISO；`repeat ∈ null|"daily"|"weekly"`。**发送仍由桥接做**（服务端只存状态）。

## 1. 做什么

1. 加 `acceptGroups` 闸 + `configSchema` 字段 + `config.example.json` 默认 `false`；
2. `reminderService` 增 `status/doneAt/repeat`；`done` 后不再进 `due()`；`repeat` 到点后自动排下一次（同 id 续期，不新建）；
3. `routes/todo.js` 四个接口；`routes/reminders.js` 不动（只共用服务）；
4. `config.care.enabled` 默认改 `false`（主动搭话对保险客户是打扰，要开由人开）。

## 2. 预期结果

群里 @ 她不再回（日志有 `group-skip`）；建一条"17:00 交保单"的待办 → 到点由桥发出去 → 勾 done 后不再发；重复待办自动排下一次。

## 3. 可验方式

- ① 群里发 `@鲸鲸 在吗` → 无回复 + `logs\` 有 `group-skip`（各一张截图/一行日志）；
- ② `POST /api/todo {title:"测", dueAt:<now+2min>}` → 2 分钟内桥发出（`ack` 行 + 微信实收）；
- ③ `POST /api/todo/{id}/done` → 之后 10 分钟不再发；
- **反例**：`dueAt` 早于现在 → 400 `past-due`（不许建成立即轰炸）；`title` 空 → 400；重复待办改系统时间跨天 → 只发一次、下一条按新时间排。
