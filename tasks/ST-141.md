# ST-141 · 解锁规则改成「小节级推进」（否则第 2 章永远点不动）

> 建单 2026-11-07 22:25｜目标 **04（代码）**｜项目 study / feature st-quiz-nav
> 起因：本体验 ST-140 时实测——**第 2 章目录已建好、小节可标记已读，但整章仍 `locked`**，因为它等「第 1 章 done」，而第 1 章要「正确率≥80% + 错题清零」才算 done。**结果：读了也推不动。**

## 一、现状（我实测）

```
outline ch2 → status=locked
  2.1 st=locked read=true  noQuestion=true   ← 标了已读，还是锁着
  2.2 st=locked read=false noQuestion=true
POST /quiz/section/read {ch2,2.1} → 200 · read:true    功能是好的
```

**根因**：`statusOf()` 只看「上一章是否 done」，不看「本章小节推进到哪」。

## 二、新规则（小节级推进）

```
① 小节状态：
   done      = 有题且答到达标（沿用现有判定）｜ 或 noQuestion 且 read=true
   learning  = 有题但没达标 ｜ 或 第一章
   locked    = 前一节未 done/read（第 1 节看上一章）

② 章状态：
   done      = **本章所有小节都 done（含已读的无题小节）**
   learning  = **任一前置小节已通，或有作答**
   locked    = 本章第 1 节还锁着

③ 跨章：**上一章最后一个节通 → 下一章第 1 节解锁**（不再要求整章 done）
```

**红线**：
1. **有题没做的小节，永远是 `learning`/`locked`，不许被"已读"跳过**（现有 `has-questions` 400 保护要保留）；
2. **不许改判分**（`grader`/`recheck` 不动）；
3. **`done` 的定义不许放松**（有题的节还是 80%/错题清零）。

## 接口契约

不用加新接口，只改 `/quiz/outline` 的计算：
```
GET /quiz/outline?bookId=logic-intro
  → 每个 section: { no, status, questions, read, noQuestion, unlocked:boolean }
  → 每个 chapter: { no, status, sections:[...], doneSections, totalSections }
```
**新增字段**：`section.unlocked`（前端用来画锁/可点）、`chapter.doneSections/totalSections`（进度条用）。

## 0.5 预期结果

**标记 2.1 已读 → 2.2 立刻从 locked 变 learning（可点）**；**2.1–2.4 全通 → 第 2 章 done，第 3 章第一节解锁。**

## 1. 做什么

1. `quiz-outline.mjs` 的 `statusOf`/`sectionStatus` 改成小节级判定（**纯函数，配单测**）；
2. `chapters` 输出加 `doneSections/totalSections`；
3. 页面（`web\index.html`）按 `section.unlocked` 画锁/可点，**别只靠 status**。

## 2. 可验方式

- ① 单测：`quiz-outline.test.mjs` 覆盖「小节推进解锁下一节」「整章 done 才算 done」「有题未答不许 unlocked」三条；
- ② 实测：`POST /quiz/section/read {ch2,2.1}` → 再取 outline，**2.2 变 `unlocked:true`**（贴 JSON 前后对比）；
- ③ 实测：把 2.1–2.4 全标已读 → 第 2 章 `status=done`、第 3 章第 1 节 `unlocked:true`（贴 JSON），**测完撤销**；
- ④ 反例：1.2 有题没答 → 仍是 `locked`（不许因 1.1 done 就放行，**1.1 有题时同理**）。

## 3. 边界

- **不改判分、不改题库、不改章节目录**；
- **不改"有题必答"的保护**。

## 4. 回滚

`quiz-outline.mjs.bak-st141`、`index.html.bak-st141`。

## 5. 附加要求

- **纯函数优先**（解锁判定抽成 `unlockOf(sections)`），**单测 ≥3 例**；
- **交付贴 JSON 前后对比**，不许只说"改了"。
