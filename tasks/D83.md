## 1. 背景（今晚已实测/已确认的事实，直接引用，不要再猜）

- **场景**：企业微信账号与**普通客户**（企微外部联系人/好友）聊天，不是"微信客服"通道；
- **官方能力边界**（已核实）：
  - **收**：只有「会话内容存档」能拿全量消息 → **客户自己付 900/年**；
  - **发**：官方**没有**会话式发送 API（只有限频的"群发"）→ 我们用**代持账号 + 客户端界面自动化**发送；
  - 应用回调只覆盖应用单聊；应用入群能力"无可选应用"（该企业无此能力）。
- **代持发送已实测可用**：Win32 点击 + 前台输入 + 回车，消息真送达（群「重庆自成一派网络科技有限公司」0:37 验证）；
- **部署形态**：客户一台 **Windows 服务器**（4C8G 起）同时跑：代持客户端 + 存档接入 + 工作台；
- **三个必须写进方案的坑**：①RDP 断开导致 GUI 会话锁屏/最小化 → 自动化失灵（需 tscon 切控制台/自动登录/保持会话）；②企微客户端要常驻且可能需要扫码登录；③发送必须走**队列**（工作台写队列 → 代持端轮询 → 回执），不能实时点击；
- **商业模型**：**买断 8000/套 + 建议 1500/年 维护**；存档费 900/年、服务器、AI token **全由客户承担**；
- 最终形态对标**网易七鱼**（多渠道接入 → 路由 → 坐席工作台 → 智能客服）。
