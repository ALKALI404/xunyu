## 1. 现状的问题
- 现在换代只核三样：`workspaceId` 对、标题字符串对、交接稿投递 `accepted`；
- 这三样**都能被"自己写的存储值"骗过**——今天就有实例：roster 里存着两个 `e7d2d95c`（新旧同前缀），我按 roster 发信直接 `session/not found`；
- 新会话如果没真的渲染出来、或窗口标题对但面板没加载，我们完全看不出来。

## 2. 做什么

1. `handoff.mjs new` / 交接流程加**一步截图**：
   - 投完接班包后，抓一次**该会话所在窗口**的截图（`logs\handoff\<旧id>→<新id>-<时间>.png`）；
   - 截图必须能看见：**会话标题 + 工作区名 + 至少一条交接包消息**；
2. 交付/回执里**必须贴这张图的路径**；没有图 ⇒ 视为换代未验完；
3. **识别"会话 id 前缀相同但已不是同一个"**：交接时记录 `previousSessionId`，读取名册时若发现同一前缀有多条，**报警**而不是随便取一条；
4. 图不能太大：截窗口区域即可（不要全屏）。
