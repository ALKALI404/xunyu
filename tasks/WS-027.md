## 接口契约

```http
GET  /api/console                  → 四栏一次给全（3–5 秒缓存，`cached` 标识；`degraded` 标"有渠道不可用"）
POST /api/console/restart { id }   → 直接转 WS-016 的 POST /api/supervisor/restart（不另写实现）
GET  /api/console/selftest         → { at, summary:{pass,fail,skipped}, checks:[{name,state:"pass|fail|skipped",detail}] }（不吃缓存，5 秒限频）
```

**错误语义（《开发规范》§四：不许 200 包错误）**：supervisor 不可用 → **503** `{ok:false,error:"supervisor-unreachable"}`；缺参 → **400**；内部异常 → **500**；**渠道不可用不是错误**，200 + `channels.*.state:"unreachable"`。

`channels.files` 本轮固定：`{ state:"not-implemented", detail:"未接入（网关有能力，本地没实现）" }`。
`brain.model` 本轮固定：`{ available:false, note:"经 DSH，无本地读数" }`。

## 2. 预期结果

打开总控台一次请求拿全四栏；杀掉 9351 后 `/api/console` 的 `services` 里它变 `up:false`；`/api/console/selftest` 一条命令看出 8 项红绿。

## 3. 可验方式

- ① `GET /api/console` → 200，含四栏；连打两次第二次 `cached:true`（贴两次返回的 `at`）；
- ② 杀掉一个服务 → 15 秒内 `services` 对应项 `up:false`（贴 JSON）；
- ③ `/api/console/selftest` → 8 条齐全，`qq-file` 为 `state:"fail"` 且 `detail` 写明"未接入"；`summary.fail>=1`；
- ④ 5 秒内连打 selftest 3 次 → 第 2、3 次 429（贴返回）；
- **反例**：把 QQ 桥停掉 → `/api/console` 仍 **200**、`ok:true`、`degraded:true`、`channels.qq.state:"unreachable"`（**不许 500**）；**把 supervisor 自己停掉 → 必须 503**（贴返回）；selftest 第 2 条变 `state:"fail"`。
