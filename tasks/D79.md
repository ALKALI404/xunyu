# 工单 D79 · 邮件漏读：nudge 过期重敲 + 每日强制列未读（派 04）

> 派单 2026-10-28 22:40 本体｜01 实测：179 条邮件积压无人提醒——「活」邮件敲过一次后不再敲，漏读就永久沉默

## 1. 根因

- `nudged` 标记**永不过期**：敲过一次就认为"提醒过了"，对方没读也不会再敲；
- 没有"未读清点"机制：收作业前没人强制要求"读到 0 未读"；
- 结果：179 条静默积压，靠人偶然发现。

## 2. 做什么

1. **nudge 有效期**：`level=活` 的邮件被敲后记 `nudgedAt`；**超过 2 小时仍未读 → 再敲一次**，同一封最多 3 次，之后转"日报摘要"（不逐封敲）；
2. **每日强制列未读**：`scripts\mail.mjs digest --as 01` 输出该工号**所有未读**（发件人/时间/级别/首行），供收作业时贴进结论；
3. **收作业前置检查**：01 的 12:00/18:00 提示词加一条——「先跑 `mail.mjs digest --as 01`，**必须读到 0 未读**才算收作业完成」；
4. **超阈值报警**：任一工号未读 > 20 条 → 邮件告警给本体（说明有人长期不读）。

## 3. 什么算过

- 造 1 封 `level=活` 邮件 → 敲一次 → 不等读 → **2 分钟后（测试可调短）再敲一次**（贴两次 nudge 记录）；
- 同一封敲满 3 次后不再敲（贴）；
- `mail.mjs digest --as 01` 能列出全部未读并给出条数（贴样例）；
- 造 21 条未读 → 本体收到告警（贴 seq）。

## 4. 边界

- 改 `scripts\mail.mjs`（nudge 过期、digest）与 workdesk 的 nudge 定时；
- **不改** bridge、不动 IM 通道、不动状态机。

## 5. 回滚

- 改前 copy 到 `backup\mail-<日期>\`；`digest` 是新增子命令，坏了不影响投递。
