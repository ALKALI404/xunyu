# 工单 D66 · 票归属自动化：add 带 project/feature + projects-sync（派 04）

> 派单 2026-10-28 21:10 本体｜主人：项目模块更新跟谁走得弄明白（结论见规则第二十节）

## 1. 要解决的问题

`state\projects.json` 的 `tickets[]` 现在是 **05 手工填**，而票是**天天新派**的 → 永远对不上，项目视图因此落后（"验收完还显示在做"的一半原因）。

## 2. 做什么

1. **`worklist.mjs add` 增加两个必填参数**：`--project <项目id>`、`--feature <功能域id>`（从 `projects.json` 校验存在性，不存在就报错列出可选值）；写进台账的 `add` 事件；
2. **`dispatch` 无需变更**（归属在建单时已定），但 `list` 输出加上 `项目/功能域` 两列；
3. **新脚本 `scripts\projects-sync.mjs`**：
   - 读台账 → 按 `project/feature` 归组 → **重建** `projects.json` 每个 feature 的 `tickets[]`（标 `generated:true`、写 `generatedAt`）；
   - **保留** 05 定义的字段（`id/name/domain/owner/summary/doc/state`）；
   - **幂等**：连着跑两次结果相同；
   - `--dry-run` 打印将要改的差异；
4. **接入调用**：workdesk 在「认领/派发/验收」后各调一次（或每次扫描时调一次，幂等即可）。

## 3. 什么算过

- 建一张不带 `--project/--feature` 的票 → **报错**并列出可选项目/功能域（贴输出）；
- 带参数建票 → `list` 能看到归属（贴）；
- 造 2 张票归到同一 feature → 跑 `projects-sync` → `projects.json` 该 feature 的 `tickets[]` 含这 2 张（贴差异）；
- **连跑两次无变化**（幂等证据：第二次 `--dry-run` 输出"无变化"）；
- 05 定义的字段没被覆盖（贴改前/改后 diff）。

## 4. 边界

- 改 `worklist.mjs`、`worklist-core.mjs`（事件字段）、新增 `projects-sync.mjs`、workdesk 里加调用；
- **不改** `projects.json` 的定义字段（05 的），只在同步时重写 `tickets[]` 与 `generatedAt`；
- 不动状态机合法边（D58 负责）。

## 5. 回滚

- 改前 copy 到 `backup\proj-sync-<日期>\`；`projects-sync` 可 `--restore <备份文件>` 还原 `tickets[]`。
