## 接口契约

- 目录：`档案\草稿\`；文件：`<YYYYMMDD-HHmmss>-<文件hash前8>.json`
- 草稿结构：
  ```json
  {
    "id": "草稿-0001",
    "status": "draft",                 // draft → confirmed / discarded
    "createdAt": "2026-11-05T22:45:00+08:00",
    "updatedAt": "...",
    "sourceFile": "收件箱\\xxx.pdf",
    "personId": "人-0002",             // 挂在谁名下（可空）
    "fields": { "policyNo": null, "insurer": null, "product": null,
                "holders": [], "insured": [], "sumInsured": null,
                "premium": null, "payTerm": null, "effectiveAt": null },
    "confidence": { "policyNo": "low", "insurer": "low" },
    "pending": ["保单号","被保险人"]
  }
  ```
- 接口：
  - `POST /api/draft` —— 上传后建草稿（body: `{sourceFile, personId?}`），返回草稿 id；
  - `PATCH /api/draft/:id` —— 改字段（只允许改 `fields`/`pending`）；
  - `POST /api/draft/:id/confirm` —— **确认入档**：校验通过后写 `policies.jsonl`，草稿标 `confirmed`；
  - `DELETE /api/draft/:id` —— 只标 `discarded`，**不物理删**。
- 校验（confirm 时）：
  1. `policyNo` 必填且**不能与已有保单重复**（重复 → 409 + 提示"已有这张单"）；
  2. `holders`/`insured` 里的 id **必须在 people.json 存在**（不存在 → 400 "先建人"）；
  3. `sumInsured`/`premium` 必须是数字或 null（**不许空字符串**）。
- **重复保单号检查（主人 2026-11-05 补）**：
  1. **建草稿时就查重**（判定键 = 保险公司 + 保单号，规范化后比）：发现已存在 → 返回 duplicate 提示「已录过：单-000x」，**草稿仍可建**；
  2. **确认入档时硬拦**：同号 → 409，给「去补那张 / 确认是另一张(force)」，force 写审计；
  3. 同号但属于批单/续期 → 不算重复，挂同一 Policy 做 Document。
- 保留策略：草稿 **7 天**后由定时任务归档到 `档案\_备份\草稿\`（本轮只需写清规则，**不必实现定时器**）。

## 0.5 预期结果

传一份保单 → 有草稿 id → 关闭页面再打开，**草稿还在**（能接着改）→ 确认后 `policies.jsonl` +1、草稿状态变 confirmed。

## 1. 做什么

1. 建 `档案\草稿\` 与三个接口；
2. 草稿读写用**原子写**（先写 .tmp 再 rename）；
3. confirm 时按上面三条校验，**任何一条不过就 400/409 并说明缺什么**；
4. 每次 confirm 写一条审计（`logs\draft.jsonl`：草稿 id、票/保单号、时间）。

## 2. 可验方式

- ① 传一份 PDF → 贴返回的草稿 id 与 `档案\草稿\` 下的文件名；
- ② 重启服务（模拟关页面）→ `GET /api/draft/<id>` 仍能取到，贴输出；
- ③ 把必填字段补全 → confirm → 贴 `policies.jsonl` 新增行 + 草稿 status；
- ④ 用**重复保单号**再 confirm → 贴 409 与提示语；
- ⑤ 用**不存在的 personId** confirm → 贴 400 与提示语。

## 3. 边界
