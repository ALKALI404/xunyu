**判定流程（改后）**：
1. **规则先判**（保持现在的速度）；
2. **只有 `fail` 或 `half` 才复核**：把「题干 + keyPoints + 你的答案」交给 S03 批改专员，问一句：
   > 「这句话在语义上有没有命中这条要点？只回 JSON：`{"hit":["kp-id",...],"note":"为什么"}`
3. **复核只允许"上调"，不允许下调**（`rule:pass` 直接信，不花 token）；
4. **复核结果合并**：命中数变了就重算 verdict，并标 `engine:"llm"`、`rechecked:true`；
5. **复核失败/超时（>8s）→ 退回规则结果**，并标 `recheckFailed:true`（**不许让判分卡住**）。

**成本红线**：**每道题最多一次复核**；`usedHint:true` 时**不复核**（已经降级了，别浪费）。

## 6. 追加（主人 2026-11-06 22:10）：加第三层「句式模板」匹配，仍然不用模型

**背景**：主人答「所以**后面是已知信息**，因为**后面是原因的补充**」——判据其实讲对了，但字面命中不了关键词。
**原则**：**能免费用规则解决的，绝不叫模型。**

### 6.1 在题库里加 `patterns`（正则，可选字段）

```json
{
  "id": "kp-criterion",
  "any": [["判据"], ["已知"]],
  "patterns": [
    "(后面|后者|结论侧)[^。；]{0,12}(已知|不需要|不用|无需)",
    "(前面|前者)[^。；]{0,12}(需要|要)[^。；]{0,8}(确立|证明|说服)"
  ]
}
```

- `patterns` 里任一条命中 → **等同于命中该 keyPoint**（与 `any` 并列，取或);
- 正则**必须宽松**（允许中间夹 12 个字符），**不许写成原文照抄**；
- 命中要在返回里标 `matchedBy:"pattern"`（便于以后调）。

### 6.2 判定优先级（三层，从便宜到贵）

```
1) any（词组合匹配）        ← 0ms
2) patterns（句式正则）     ← 0ms
3) LLM 复核（S03）          ← 300–1500ms，只在 1+2 之后仍 fail/half 才走
```

### 6.3 这批题先补两条模板（照抄）

- `kp-jia-arg`：`"甲[^。；]{0,24}(论述|论证|论辩)"`
- `kp-yi-exp`：`"乙[^。；]{0,24}(说明|解释|交代)"`

### 6.4 验收补充

- ① 用主人原文回放 → `pass`，且 `matchedBy:"pattern"` 至少出现一次；
- ② 写一段完全跑偏的答案 → 仍然 `fail`（模板不许把错的判对）；
- ③ 贴 `patterns` 生效前后的对照（同一答案，前后判定不同）。

## 9. 根因诊断（本体 2026-11-07 00:35 补，照着修）

**现象（可复现两次）**：
- 第一次提交：`verdict=half/fail, ms=8010, rechecked=false` → **超时后退回规则**；
- 立刻再提交：`ms=1614, rechecked=true` → **正常**。

**已排除**：
- 不是模型慢——单独调 `rechecker.recheck()` **1.5 秒返回**；
- 不是会话不存在——`recheckReady()` 返回 `ok:true`；
- 不是网络——`feynman/say` 端到端 **2.7 秒**。

**结论：冷启动开销**。第一次调用要完成：**取 DSH 凭据 → 建连 → 发 prompt → 等 session/follow 的第一个事件**；这段在服务刚起来时占满 8 秒预算。

### 要改三处（缺一不可）

1. **启动预热**：`server.listen()` 成功后立刻发一次**极短**的 recheck 探针（例：`q: "热身", answer: "ok"`），**预热结果只记日志、不影响用户**；失败也不阻塞启动。
2. **超时提到 20000ms**（`RECHECK_TIMEOUT_MS`），并且**只对"首调"放宽**——首调 20s，之后回到 8s。
3. **失败自动重试一次**：`recheckFailed:true` 时**再调一次**（第二次通常 1.5s），重试成功则把 `rechecked:true` 与结果合并；**仍失败才退回规则**，并保留 `recheckFailed:true`。

### 验收（新）

- ① 重启服务后**立刻**打第一发 → `rechecked:true`（贴日志）；
- ② 连打三发，`ms` 分别为「首调 ≤8000」「其后 ≤3000」（贴三行）；
- ③ 故意把 `RECHECK_TIMEOUT_MS=500` → 应走重试 → 仍失败则 `recheckFailed:true` 且**判分不卡住**（贴返回）。
