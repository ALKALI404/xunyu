> 派单 2026-10-29 00:28 本体｜企微回调已打通，但隧道目前是**临时 ssh 进程**，一断全断

## 1. 现状（已验证）

```
企微 → https://theglobalscm.top/wecom
     → nginx(115.191.6.89)
     → 服务器 127.0.0.1:18788
     → SSH 反向隧道 → 本机 127.0.0.1:8788 (E:\DSH-WeCom\bridge, src/server.mjs)
```
- 实测 `https://theglobalscm.top/wecom` 返回 **400**（本地服务应答缺 echostar，链路通）
- 隧道进程：`ssh -N -R 127.0.0.1:18788:127.0.0.1:8788 root@115.191.6.89`（**临时起在后台，无守护**）

## 2. 做什么

1. **做成受守护的常驻**（与 relay/body 同级，纳入现有 supervisor 或单独计划任务）：
   - 开机自启（用户登录或系统启动，**不弹黑窗**，沿用 wscript 方式）；
   - 掉线自愈：探针每 30 秒请求 `https://theglobalscm.top/wecom` —— **返回 400/403 都算通**（说明本地服务在应答），超时/502/000 判死 → 重启隧道；
   - 连续失败 5 次 → 邮件报本体，但**继续重试（拉长间隔）**，不许 give-up；
2. **日志**：`logs\wecom-tunnel.log` 记每次连/断/重启（含时间与原因）；
3. **状态可见**：工作台「谁在干什么」能显示隧道状态（可先只写日志，页面后补）；
4. **端口冲突处理**：重启前先杀残留 `ssh` 反向隧道进程，避免 `remote port forwarding failed`。

## 3. 什么算过

- 杀掉隧道进程 → **60 秒内**自动恢复，`https://theglobalscm.top/wecom` 重新回 400（贴日志与时间）；
- 重启机器（或重跑启动脚本）→ 隧道自动在，回调通（贴证据）；
- 连续杀 6 次 → 第 6 次后仍会重试（间隔拉长），并发出邮件（贴 seq）；
- `logs\wecom-tunnel.log` 有连/断记录。

## 4. 边界

- 只做本机侧的守护进程/计划任务与日志；
- **不改服务器 nginx**（要改先报本体）、不动 `DSH-WeCom\bridge` 的业务代码。

## 5. 回滚
