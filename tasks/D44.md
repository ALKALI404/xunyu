# 工单 D44 · 花费统计虚高 13 倍：计价把 base 快照也算进去了（派 04，P0）

> 派单 2026-10-28 19:10 本体｜主人报：每日花费显示 ¥396，明显不对

## 1. 现象与根因（已定位）

- 现在 `token-report --day` 与 `/api/cost` 都给 **¥396.89**（433 轮 / 3801 步 / 命中 37.1 亿）；
- 早上同一脚本给的是 **¥30.84**（命中 2.04 亿）——**虚高约 13 倍**；
- **根因**：账本里有两种记录 `k='turn'`（3430 条，单步真实增量）与 **`k='base'`（93 条，会话累计快照）**。现在的计价把 `base` 也当一步累加了：
  - 例：`sid=7e839b73, k=base, hit=139,048,576`（1.39 亿，单个会话的累计值）；
  - 93 条 base 合计贡献了绝大部分虚高。

## 2. 做什么

1. **计价只算 `k='turn'`**；`k='base'` 单独当"会话基线"处理（必要时只用于判断覆盖，不进金额）；
2. 同一 `(sid, turn, step, model, provider)` 重复行**去重**（各取一次，不许相加）；
3. `cacheHit` 仍按 `(sid, turn)` 取 **max**，`cacheMiss/output` 按 turn 累加（原有口径不变）；
4. **`token-report.mjs`、`/api/cost`、页面、`cost-report.mjs` 四处共用同一个计价函数**（`scripts\cost-core.mjs`）。

## 3. 什么算过

- 修后 `--day 2026-10-28` 结果应回到 **¥30–¥45 区间**（与 18:00 前后一致）；
- 四处入口在同一天同一区间**数字完全一致**（贴四组输出）；
- 给一条命令证明 `base` 行未被计入（例：临时统计 k 分布 + 各自贡献金额）；
- **回归**：昨天（10-27）数字也重算一遍，与桥接预算告警同量级。

## 4. 边界

- 只改计价与聚合：`token-report.mjs`、`cost-core.mjs`、`workdesk-server.mjs` 的 `/api/cost`、`cost-report.mjs`；
- **不改** `state\token-usage.jsonl`（历史账本原样保留）、不改 bridge 的写入逻辑。
