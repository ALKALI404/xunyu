## 接口契约

```http
POST /api/files/qq/send    { chatId, path }   → { ok, fileId }
GET  /api/files/qq/status                     → { ok, implemented:true, lastAt, sentToday, recvToday, lastError }
GET  /api/files/qq/received?limit=20          → { ok, items:[{id,name,bytes,savedAs,at,from}] }
```

Console 侧只读 `status`（WS-027 的 `channels.files` 改成它；`implemented:false` → `true`）。

## 1. 做什么

1. **白名单**：只许从 `收件箱\`（收）与 `输出\`（发）进出——`path.resolve` 后必须在根内；**禁发** `.exe .bat .cmd .ps1 .js .vbs .lnk .scr .msi`；单文件 ≤ 4 GB（网关上限），默认建议 ≤ 200 MB 给个提示；
2. **发**：调网关 `upload_private_file`（群聊不做，群文件接口保留不接）；成功记 `fileId`，失败把网关原文错误写进 `lastError`；
3. **收**：监听 QQ 文件消息 → 落 `收件箱\`（重名加 `-1`）→ 算 sha256 → 记一条 received；
4. **状态**：`sentToday/recvToday/lastAt/lastError` 落 `state\qq-files.json`（别每请求扫盘）。

## 2. 预期结果

能发一个 PDF 给指定 QQ 好友，对方收到；对方发来的文件出现在 `收件箱\`；总控台②栏第三行从「未接入」变「最近一次 14:3x · 成功 3 / 失败 0」。

## 3. 可验方式

- ① 发 183 KB PDF → 对方真的收到 + `status.sentToday` +1（截图 + `state\qq-files.json`）；
- ② 收：对方发一个文件 → `收件箱\` 落盘、sha256 一致、`received` 列表有它；
- ③ 网关停掉 → `send` 返回 502 + 网关原文错误，**不重试不刷屏**；
- **反例**：`path` 指 `C:\Windows\win.ini` → 400 `path-outside`；发 `.exe` → 400 `blocked-type`；5 GB → 400 `too-large`。

## 4. 边界

不接群聊文件（接口留注释，不调用）；不改 SnowLuma 本体；不动 QQ 文本通道；收件只落 `收件箱\`。

## 5. 回滚

`GET /api/files/qq/status` 回 `implemented:false`（总控台自动退回"未接入"）；删 `state\qq-files.json` + 路由挂载行。
