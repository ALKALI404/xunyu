## 接口契约

**数据结构（规格先定，实现照这个走）**

```json
{
  "policyId": "单-0001",
  "clauseId": "cp-000001",
  "items": [
    {
      "itemId": "TPL-3-2",
      "clauseNo": "第三条",

      "plain": "人话，≤80 字，说清对投保人意味着什么",
      "boundary": "什么情况下不适用 / 常见误解",
      "uncertain": null,
      "sourceUrl": "…"
    }
  ],
  "uncertainKinds": ["version-unconfirmed", "ambiguous", "need-insurer-confirm"]

```

**HTTP 路由（给 04 的实现票用）**

```
GET  /api/clause/explain?policyId=<id>                → items 全量
GET  /api/clause/explain?clauseId=<id>&item=<itemId>  → 单条（页面展开）
POST /api/clause/explain/refresh {policyId}           → 人工触发重生成
```

**错误码**：`404` 无条款 / `422` 条款解析失败（**保留原文返回**）/ `501` 解读服务不可用（**诚实报错，不编内容**）。

## 要出的文档（`docs\产品\保险-条款解读L3-2026-11-07.md`）

1. **解读粒度**：按「条 → 段」两层（沿用 L2 已建的索引结构），**每条给三样**：
   - **原文**（一字不改，带页码/条款号）
   - **人话**（≤80 字，说清"这条对投保人意味着什么"）
   - **边界**（什么情况下这条不适用 / 常见误解）
2. **不确定标注**：三类标出来（**条款版本未确认 / 原文有歧义 / 需要保险公司确认**），**不许猜**；
3. **红线（写进规格）**：
   - **不做收益/赔付预测**（让主人自己去问客服）；
   - **不做"买/不买"建议**；
   - **每条解读必须能点回原文**；
4. **评测口径**：怎么算"解读对"——**三个判据**（原文引用准确 / 人话不含新信息 / 边界说得对），**每条抽 20% 人工核**；
5. **失败处理**：条款抓不到 → 显示"无条款"而不是空白；解析失败 → 保留原文不让用户以为没内容。
