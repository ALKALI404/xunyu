# 工单 D75 · 自动接力死循环：跳过无任务书的票 + 按工号轮询（派 06）

> 派单 2026-10-28 21:00 本体｜现象：05/06 派了任务却"在等"，而 04 那边每 60 秒重试同一张派不出去的票

## 1. 现象与根因（workdesk.run.log 实证）

```
12:57:51 [relay] 工号04 挑 W-047（rank 3：返工优先）→ 派：失败 undefined-task
12:58:51 [relay] 工号04 挑 W-047（rank 3：返工优先）→ 派：失败 undefined-task
```
- **W-047 没有任务书** → `dispatch` 返回 `409 undefined-task` → 接力**每 60 秒重试同一张**，永远派不出去；
- 与此同时 **W-110（D65，06 的）一直 `queued`**，06 空闲却没被派到；
- 结论：**接力只挑到第一张挑不动的票就卡住，其他工号的活全被饿着**。

## 2. 做什么

1. **跳过派不动的票**：接力挑票时先自检"任务书是否合格"（可复用 `dispatch` 的校验），不合格就**跳过并标记** `needs-task-doc`（页面标红），**不许死循环重试**；
2. **按工号轮询**：每个 tick 对**每个空闲工号**各挑一次（而不是所有工号抢同一张），互不阻塞；
3. **失败退避升级**：同一张票连续失败 3 次 → 不再自动挑它，改成给本体发邮件「这张票派不出去：缺任务书 / 缺边界」；
4. **日志写清**：`[relay] 工号X 跳过 W-yyy（reason）` / `[relay] 工号X 挑 W-zzz → 派：OK`。

## 3. 什么算过

- 造一张**没有任务书**的票 + 一张正常票：接力跳过前者、派后者（贴日志两行）；
- 两个工号同时空闲、各有一张可派的票 → **同一 tick 内都派出去**（贴日志）；
- 同一张失败 3 次后不再重试（贴 3 行失败 + 第 4 次无尝试）；
- 页面对 `needs-task-doc` 的票标红（截图）。

## 4. 边界

- 只改 `scripts\workdesk-server.mjs` 的接力循环与页面标记；
- **不改** `dispatch-core.mjs` 的校验逻辑（那是 04 的）、不改状态机。
