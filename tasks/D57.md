## 1. 做什么

**A. 预检脚本** `scripts\check-delivery.mjs <文件|--all>`：
- 检查第 1~3 行内是否有 **`类型:`**（方案/实现/修复/文档）；
- 检查是否含四要素小节（做到哪 / 改了什么 / 怎么验的 / 卡在哪）；
- **修复类**额外要求：出现 `exit` 或 `退出码` 字样，且至少一个 ``` 代码块含「命令」；
- **方案类**额外要求：含「回滚」；
- 输出 `OK` / `FAIL: <缺什么>`，退出码 0/1。

**B. 接进认领流程**：`workdesk-server.mjs` 扫到交付文件时先跑预检——
- 通过 → 照旧 `submitted` + 通知 01；
- **不通过 → 不进 submitted**，标 `bad`（页面「卡点」里单列），并邮件通知提交工号与 01，写明缺什么。

**C. 停用旧口径**：`token-report.mjs` 若仍存在 D44 那套（含 base 行或取 max）的入口/开关，**删掉或改为调用 D45 的实现**；交付里给出「两套数不再并存」的证据。
