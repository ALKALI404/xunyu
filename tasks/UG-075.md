## 接口契约

**沿用 `logs\archive.jsonl` 的行 schema（UG-074 已建），本单只新增一种 op 值**：

```
op: "skipped-already-archived"   已经在 UG-074 用了（single archive 时命中已归档）
本单新增语义：**--pending 批量时对每条 pending 也走同一个判定**
  已归档 → 记 {op:"skipped-already-archived", by:"pending", sessionId, before, after(=before), ok:true}
  未归档 → 正常归档，记 {op:"pending-archive", by:"pending", ...}

CLI 行为约定（契约本体）：
  `archive --pending`
    ① 读 state\handoff.json 的 pendingArchive
    ② 每条按 id 查 workspace.json 的 global.archivedSessionIds
    ③ 已归档的 **从 pendingArchive 里摘掉**（写回 handoff.json），并记一行 skipped
    ④ 未归档的正常归档
    ⑤ 跑完 pendingArchive 里**不应再残留已归档的 id**
```

## 0.5 预期结果

`archive --pending` 跑完后，`state\handoff.json` 的 `pendingArchive` 里**没有任何已归档的 id**，且 `logs\archive.jsonl` 里能看到 `by:"pending"` 的 skipped 行。

## 1. 做什么

改 `scripts\handoff.mjs` 的 `--pending` 分支：归档前对每条 pending 按 id 校验 `archivedSessionIds`，已归档的摘掉并记 skipped，未归档的正常归。

## 2. 预期结果

- 不再重复归档/报错；
- pending 列表会自我清理（不再积累已归档的僵尸 id）；
- 日志能看出「这条 pending 是跳过还是真归档」。

## 3. 验收与判据

- ① **造一条已归档 id 进 pending**（把已归档的 `session-2ece2a18…` 写回 `pendingArchive`），跑 `archive --pending`：**不报错**、**pendingArchive 里该 id 消失**、`logs\archive.jsonl` 新增一行 `op:"skipped-already-archived", by:"pending"`（贴三样）；
- ② **反例（必须做）**：造一条**未归档**的真实会话进 pending，跑 `--pending` → 正常归档（`op:"pending-archive"`、before/after 差 1），且 pending 里也摘掉；
- ③ **幂等**：连跑两次 `--pending`，第二次**零新增归档行、零报错**（只有 skipped 或什么都不写）。
