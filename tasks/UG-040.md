## 0.5 预期结果
**任何脚本读 JSON 都不受 BOM 影响**；**任何脚本写 JSON 一律无 BOM**；这一条有全局工具函数 + 检查脚本，不靠人记。

## 接口契约

- `readJson(path) -> object`：读文件、去 BOM、解析；失败抛错（含路径与首 40 字）。
- `writeJson(path, obj) -> void`：`JSON.stringify(obj, null, 2)`，**UTF-8 无 BOM**。
- `node scripts\check-json-bom.mjs [--fix]`：扫 `state\*.json`、`config\*.json`，退出码 1=有 BOM。

## 1. 做什么

1. 新增 `scripts\json-io.mjs`：
   - `readJson(p)`：读文件 → `replace(/^\uFEFF/, '')` → `JSON.parse`，解析失败抛出**带文件路径与首 40 字**的错误；
   - `writeJson(p, obj)`：`JSON.stringify(obj, null, 2)` + **UTF-8 无 BOM** 写入；
2. **替换**所有 `JSON.parse(fs.readFileSync(...))` 直接用法（`workdesk-server.mjs`、`worklist.mjs`、`dispatch-core.mjs`、`acceptance-watch.mjs`、`mistakes*`、`relay04` 等，用 grep 找全）；
3. 新增 `scripts\check-json-bom.mjs`：扫 `state\*.json`、`config\*.json`，**有 BOM 就报并自动去掉**（`--fix`）；
4. 挂进健康检查清单（`state\health-components.json` 加一项 `json-bom`）。

## 2. 预期结果
- 把一个 json 手工写成带 BOM → `check-json-bom` 报出来，`--fix` 后正常；
- `workdesk-server` 的优先队列诊断行永远 `active=true`（文件存在时）。

## 3. 验收与判据
