## 接口契约

```http
POST /api/files/send    { chatId, path }          → { ok, jobId, bytes, sha256 }
POST /api/files/receive { chatId, kind:"file" }   → { ok, savedAs, bytes, sha256 }
GET  /api/files/status  ?jobId=                   → { ok, job, queue:{queued,sending,unconfirmed} }
POST /api/files/cancel  { jobId }                 → { ok }

# 桥接专用（BRIDGE_ONLY：仅本机 + 必须带 gateway token）
GET  /api/files/pending                            → { ok, items:[] }
POST /api/files/claim  { id }                      → { ok, item }
POST /api/files/ack    { id, status, error }       → { ok, item }
POST /api/files/incoming { chatId, savedAs, bytes, sha256 } → { ok, id }
```

job 行：`{id, dir:"out|in", chatId, chatName, path, name, bytes, sha256, mime, status, attempts, createdAt, error}`；
状态机照抄 `stickerService`：`queued→reserved→sending→confirmed|unconfirmed|failed`。

## 1. 做什么

1. `src\adapters\files.js`（由 `stickers.js` 改写）：白名单根 `data\files\{outbox,inbox}\`、类型黑名单（`.exe .bat .cmd .ps1 .js .vbs .lnk .scr .msi`）、大小上限（50 MB；图片 20 MB）、`sha256`、同名同哈希复用；
2. `src\services\fileService.js`：租约 + 5 分钟重试一次 + 过期 24h 不补发；
3. `src\http\routes\files.js`：8 个路由；`/api/stickers/*` **只关不删**（`features.files` 切换）；
4. `bridge\engine.py`：抄表情的三处轮询（`:4113` pending / `:3306` claim / `:3331` ack）给 files；发送走 `sticker_transport.guarded_send`，`_verify_image` → `_verify_file`（大小/类型/哈希）；收件走 `msg_pipeline` → `POST /api/files/incoming`。

## 2. 预期结果

启动器选 PDF → 2 秒内「发送中」→ 微信实收 → 「已发送（确认）」；对方发来文件 → 「收件」可见可打开。

## 3. 可验方式

- ① 发 183 KB PDF 到「文件传输助手」→ `ack confirmed` + 微信实收（截图 + `data\files\queue.jsonl` 那行）；
- ② 收：自己发文件回来 → `inbox\` 落盘、sha256 一致；
- **反例**：`path` 指 `C:\Windows\win.ini` → 400 `path-outside`；发 `.exe` → 400 `blocked-type`；60 MB → 400 `too-large`；发送中 kill 桥接 → 租约到期回 `queued`，**不自动重发**（重试要人点）；
- **零焦点回归**：前台开记事本再发 → 照样发出。
