## 0.5 预期结果
一条命令能查出并**自动修复**"台账 ↔ 项目栏"的不一致；派发前不再靠人肉对齐。

## 接口契约
- `node scripts\pr-reconcile.mjs --check` → `{ok, count, mismatches:[{ticket, kind:'feature-mismatch'|'not-in-project'|'no-contract', ledger:{project,feature}, board:{project,feature}}]}`，退出码 1=有不一致；
- `node scripts\pr-reconcile.mjs --fix` → 按规则修正并写审计 `state\pr-reconcile.jsonl`：
  - 单号前缀决定 project：`UG→upgrade`、`WS→workdesk`、`AV→avatar`、`WC→wecom`；
  - feature **以项目栏为准**回写台账（项目栏是唯一派单源，规则 §32）；
  - 项目栏缺票 → 补进对应 feature 的 `tickets`；
  - feature `contract` 为空 → **不臆造**，列进 `remaining` 交人定；
- 输出 `{fixed:number, remaining:[]}`。

## 2. 做什么
1. 读 `state\worklist.jsonl`（末态）与 `state\projects.json`，按契约算差异；
2. `--check` 只报不改；`--fix` 只改**能确定的**，不确定的留给人；
3. 把 `--check` 接进 `worklist.mjs dispatch` 前置（不一致就拒派并提示 `--fix`，替代散落的 409）；
4. 单测：造三种不一致各一条，`--fix` 后 `--check` 退出码 0。

## 3. 验收判据
- ① `--check` 在现有数据跑一次，输出清单（贴前 5 条）；
- ② `--fix` 后 `--check` 退出码 0（贴）；
- ③ 审计文件有对应行（贴）；
- ④ 派一张原本 `feature-mismatch` 的票能直接派出去（贴 dispatch 输出）。

## 4. 边界
只做对账与修复；**不改 ticket 状态机**，不动 dispatch 其它闸门。
