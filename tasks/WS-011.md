## 0.5 预期结果

`GET /api/health/components` 返回**所有关键组件的存活状态**：每个组件 `{name, kind, ok, pid, uptimeSec, port, lastError, detail}`；工作台能一屏看出"谁挂了"。

## 1. 做什么

要盯的组件（先按现有清单，可配置化）：

| 组件 | 判定方式 |
|---|---|
| DSH daemon | `DSH_WEB_URL` 端口在听 + `/api/sessions` 可达 |
| QQ 桥 3100 | 端口在听 + 进程存在 |
| relay 9334 / body 9335 / pain-bus 9339 | 端口在听 |
| 工作台 9340 | 自身（恒 ok，写版本与启动时间） |
| 窗口页面服务 9342 | 端口在听 + `GET /` 200 |
| 窗口壳 `XunyuWebWindow.exe` | 进程存在 + 主窗口标题 |
| **VM 企微** | SSH 可达 + `WXWork.exe` 进程 + 主窗口 hwnd 非空 |
| 企微隧道 8788 | 端口在听（挂了要标红，回调会失败） |

要求：
1. **超时 800ms**，单个组件卡住不许拖垮整个接口；
2. 结果缓存 **10 秒**（同一秒内多次请求不打爆探针）；
3. 每个组件的历史状态写 `state\health-history.jsonl`（append-only，便于看"什么时候挂的"）；
4. 组件清单放 `state\health-components.json`，**加组件不用改代码**。

## 2. 预期结果

- 接口返回 8 个组件；**故意杀掉 8788** → 该组件 `ok:false` 且 `lastError` 有原因（贴前后两次输出）；
- 单组件超时不拖垮：给一个不存在的端口，接口仍在 1.5 秒内返回。

## 3. 验收与判据

- ① `curl /api/health/components` 合法 JSON，8 项齐全（贴）；
- ② kill 8788 前后对比（贴，`ok` 由 true→false）；
- ③ 恢复后 10 秒内回到 true（贴时间戳）；
- ④ `health-history.jsonl` 有状态变更行（贴 2 行）。
