## 0.5 预期结果
桥梁重启、DSH 重启、cookie 过期之后，**QQ 侧调 DSH 一律能通**；失败时给出明确 code（`dsh-unauthorized` / `dsh-timeout`），不再静默超时。

## 接口契约
- `ensureDshAuth({ force }) -> {ok, source:'cookie'|'minted'|'env', at}`：内存缓存，**401/超时后强制重签一次**；
- 所有 DSH 调用统一走 `dshFetch(path, body)`：**401 → 重签 → 重试 1 次**；仍失败抛 `{code:'dsh-unauthorized'}`；
- 超时统一 15 秒，超时抛 `{code:'dsh-timeout', ms}`；
- 观测：`state\dsh-auth.jsonl` 每次重签一行 `{at, reason:'401'|'timeout'|'startup'}`。

## 2. 做什么
1. 在 `src\dsh-client.js` 里加 `ensureDshAuth` + `dshFetch`，替换散落的直接 fetch；
2. 启动时预签一次；收到 401 或超时**重签后重试一次**；
3. `qq_dsh_sessions` / `qq_dsh_say` / `qq_dsh_wait` 三个工具全部走 `dshFetch`；
4. 失败时把 code 原样返回给 QQ 侧（**不许变成"超时"**）。

## 3. 验收判据
- ① 正常态：`qq_dsh_sessions` 返回会话列表，`state\dsh-auth.jsonl` 无新增（贴）；
- ② 人为改坏 cookie（或重启 DSH）→ 再调 → 自动重签并成功，日志有 `reason:"401"`（贴）；
- ③ 把 DSH 停掉 → 调用 15 秒内返回 `{code:'dsh-timeout'}`，**不是无限等**（贴）；
- ④ 三项工具（sessions/say/wait）各跑一次（贴 code）。

## 4. 边界
只改桥的 DSH 调用层；不动消息路由、不动 SnowLuma 侧。
