## 接口契约

- `resolveSessionByTitle(key, title) -> sessionId|null`：读 `api.sessions.list`，按标题精确匹配（`群聊·<群名>（<群号>）` / `鲟鱼QQ（<昵称> <QQ号>）`），**跳过已归档**，多个命中取 `updatedAt` 最大。
- `ensureSession(key)` 新流程：映射在且有效 → 复用；**映射丢了 → 先 `resolveSessionByTitle` 找回 → 再决定是否新建**；只有「首次 / 会话确实不在 DSH 列表 / 主人手动重来」才 `sessions.create`。
- `retireSession(key, reason)` 之后：**10 分钟内**调用一次归档（可用定时器或延迟任务），并把 sessionId 记入待归档队列 `state\pending-archive.json`（进程重启后能续上）。
- **上限守卫**：每次新建成功后，若同 key 未归档会话数 > 2，**立即归档最老的**。
- **外部归档检测**：`ensureSession` 发现映射指向的会话**不在列表或已归档**时，除重建外必须 `log('[会话] 被外部归档，已重开')` 并通过 QQ 给 owner 发一句人话。
- 保号失败时的上下文接力：新建后把旧会话**最后 20 条消息摘要**拼进第一条 prompt（摘要在 `state\social-v2.json` 的 `recentMessages` 里取）。

## 0.5 预期结果

重启不换号、旧会话 10 分钟内消失、一个群最多 2 个、会话被外部归档会被告知——**不再出现“一堆同名会话”**。

## 1. 做什么

1. 加 `resolveSessionByTitle`（现在**完全没有**按标题找回的能力）；
2. 改 `ensureSession`（9912–9937）的判定顺序：映射 → 标题找回 → 新建；
3. `retireSession`（3343）加“10 分钟后归档”的收尾（写待归档队列 + 到点真归档）；
4. 新建后做“同 key 上限 2”守卫；
5. 外部归档时发提示（日志 + QQ 私聊给 owner）。

## 2. 可验方式

- ① 重启桥 3 次，贴 `state\sessions.json` 三个 key 的 id **前后对比**（应不变）；
- ② 用一个测试群：删掉它的映射行 → 发一条消息 → 贴日志，证明**走的是“标题找回”而不是 create**；
- ③ 手动归档某群会话 → 贴 QQ 收到的提示文字 + 10 分钟后 `logs\archive.jsonl` 的归档行；
- ④ 连开 3 次新会话（测试 key）→ 贴 DSH 列表里该 key 未归档数 = 2；
- ⑤ `Select-String -Path src\bridge.js -Pattern 'delete state.sessions'` 贴结果（本轮不要求清零，但要列出清单）。

## 3. 边界

只改 `src\bridge.js`（必要时加一个 `src\session-lifecycle.js`）；**不动 QQ 发送、不动 social-v2 结构**。
