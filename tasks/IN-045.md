## 一、现在断在哪（本体 17:30 实测，三条）

**① 桥的 `/api/dsh/say` 把消息投给了「本体会话」，不是 P05**
```
POST /api/dsh/say {sessionId: P05, message: …}
→ 200 {"ok":true,"sessionId":"session-b6eb5c94…","title":"鲟鱼—本体"}
```
**桥忽略 body.sessionId，按"绑定"投递。**

**② `/api/dsh/wait` 直接 404**
```
{"ok":false,"error":"会话 session-4c58cb00… 没有活跃的中继绑定（先喊话一次，或绑定已超时）"}
```
**绑定是 relay 建的，不是我们建的** → shim 拿不到回复。

**③ DSH 自己的 history 接口在现版本 404**
```
api.sessions.history({sessionId}) → HTTP 404 /api/session/history
api.sessions.list() → items 0（形状也变了）
```
**`scripts\dsh-base.mjs` 报的 base（60901）是对的，但我们的 dsh-client 是旧版绑定的方法名。**

## 二、要做的事（三条路，按优先级）

**路线 A（推荐）：shim 直连 DSH，不经过 QQ 桥**
1. **实测出当前 DSH 的「发消息 + 取回复」正确接口**（在 `E:\DSH_Desktop\resources\app.asar` 里找 api 路由，或用 GUI 的 network 面板思路——**这是你这次的主要工作量**）；
2. 在 `脚本\wg-dsh.mjs`（本体已写好骨架，`health/say/waitForReply`）里接上正确接口；
3. **验证**：给 P05 发一句 → 20 秒内拿到它的回复文本。

**路线 B（兜底）：给桥加"按会话投递"**
- 让 `/api/dsh/say` 尊重 `body.sessionId`（不经绑定）；
- 并在 say 之后**直接把 DSH 的回复作为 HTTP 响应返回**（不靠 wait）。
- **代价**：改第三方桥的核心路由，**要写清回归测试**。

**路线 C（最后手段）：relay 复用**

## 接口契约

```
POST /v1/chat/completions   { model, messages:[{role,content}] }  → OpenAI 形状，非流式
POST /api/chat              { text, mode, sessionId, senderName }  → { ok, action:"say", text }
GET  /health                → { ok, model, session:{id,title,found}, bridge:{ok,latencyMs} }
```

**红线**：
1. **只允许一个微信会话**：`文件传输助手`（chatId `filehelper`）；
   —— **其它任何会话一律不读、不回**（主号是你本人的微信）；
2. 回复超过 60 秒没拿到 → **回一句人话**（"我卡住了，稍等"），**不许静默**；
3. **不许把微信消息写进任何别的项目目录**（只落 `收件箱\`）；
4. 令牌一律掩码。
