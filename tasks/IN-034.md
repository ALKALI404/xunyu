## 接口契约

```
POST /api/clause/fetch   {policyId}   → {status:"ok"|"missing"|"failed", clausePath, matchReason, sourceUrl, needsReview:true}
GET  /api/clause/match?policyId=      → {clause:{path,product,version,sourceUrl}, versions:[], matchReason}
GET  /api/clause/file?path=           → PDF 流（预览/下载）
```

**已定覆盖（主人 20:00 定）**：
| 公司 | 适配器 |
|---|---|
| 太平 / 友邦 / 百年 / 富德 / 华贵 | **官网 PDF 直链**（05 已实测 200 + `%PDF`） |
| 阳光 | 条款 **HTML 转 PDF**（或先存 HTML + 转档） |
| **横琴** | **试一次**（银行镜像也可以），**失败就标 missing，不重试** |
| **中保** | **不抓**，直接 `missing` + `reason:"no-adapter"` |

**硬约束**：
- 同域 **≤1 请求/秒、并发 ≤2**；**不绕验证码**；
- 先写 `.part` 再改名，校验 `%PDF` 头；**非 PDF 不落盘**；
- 三键去重：`公司+产品+版本`，已有复用（记录 `reusedFrom`）；
- 每份记 `sourceUrl / fetchedAt / sha256 / bytes`；
- **所有抓取/匹配结果标 `needsReview:true`**（**待人工校验，不得直接入档**）；
- 失败标签：`no-adapter` / `http-412` / `dns` / `timeout` / `bad-file` / `no-match` / `write`；**同域每天 ≤3 次重试**。

## 0.5 预期结果

对一个已有保单（先太平 单-0001）跑 `POST /api/clause/fetch` → 返回 `status:"ok"`，本地出现 PDF，`matchReason` 写明靠哪一级命中，`needsReview:true`。

## 1. 做什么

1. `脚本\clause-fetcher.mjs`（适配器表 + 限速 + 落盘）；
2. `脚本\clause-lib.mjs`（库存、索引、去重、sha256）；
3. `脚本\clause-matcher.mjs`（三级降级 + `matchReason`）；
4. `server.mjs` 挂三个路由。

## 2. 可验方式

- ① 太平单跑通的返回 JSON（含 `status/clausePath/matchReason/sourceUrl/needsReview`）；
- ② 本地 PDF 的 `sha256` 与 `bytes`；
- ③ **同产品第二张单**再跑 → `reusedFrom` 命中（不重复下载）；
- ④ 横琴试一次 → 贴真实结果（成功或 `dns/timeout`，**不许编**）；
- ⑤ 中保单 → `missing/no-adapter`；
- ⑥ 用 `tdd`：匹配器至少 6 个用例（含"版本未知"不许选最新版）。
