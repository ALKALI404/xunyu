## 接口契约

**接口有变更（新增参数，向后兼容）**：

```
scripts\capture-window.ps1
  现有参数：-Out <路径> -Process <进程名>
  新增参数：-Session <sessionId 或短 id>   # 目标会话，按窗口标题里的页签/标题精确匹配
             -ListCandidates             # 只列出候选窗口（标题 + 坐标 + 进程），不截图，用于排错

退出码：0 成功（文件已落且 >50KB）
        1 参数错
        2 找不到目标会话窗口（必须把**所有候选窗口标题**打到 stderr，一行一个）
        3 截图失败（窗口存在但 GDI/PrintWindow 失败）
```

**不变的部分**：`-Out` 的文件格式（PNG）、`-Process` 语义、现有的「前台窗口截图」行为（不传 `-Session` 时完全等同于今天）。

## 0.5 预期结果

桌面被别的应用占着前台（例如游戏、浏览器全屏）时，**仍能截到指定会话的窗口**，且截图里能看到该会话的页签标题。

## 1. 做什么

1. `scripts\capture-window.ps1` 增加 `-Session <id>`：先 `sessions.list` 拿到该会话的标题（如「鲟鱼工作组工号06·界面与交互」），再**枚举该进程（DSH NEXT）的所有顶层窗口**，按标题匹配挑出目标窗口；
2. 对目标窗口用 **PrintWindow(PW_RENDERFULLCONTENT)** 或等效离屏方式截图，**不调用 SetForegroundWindow、不抢焦点**；
3. 匹配不到就 exit 2，并把**全部候选窗口标题**打出来（排错关键，别再让人靠猜）；
4. 增加 `-ListCandidates` 只读模式，方便手工核对；
5. 保持向后兼容：不传 `-Session` 时行为与今天一致。

## 2. 预期结果

- `capture-window.ps1 -Session <id> -Out <png>` 在**前台是别的应用**时也能 exit 0；
- PNG 里能看见目标会话标题；
- 传不存在 id 时 exit 2 且 stderr 列出候选标题。

## 3. 验收与判据

- ① **不依赖前台**：先用别的全屏应用/游戏占前台，再跑 `capture-window.ps1 -Session <当前 06 会话 id> -Out tmp\x.png` → **exit 0 且文件 >50KB**；贴 `Get-Item tmp\x.png | Select Length` 与当时 `GetForegroundWindow` 的进程名（证明前台不是 DSH）；
- ② **截图内容对得上**：打开该 PNG 能看到目标会话的页签标题（贴路径，01 自己看）；
- ③ **反例（必须做）**：传一个不存在的 session id → **exit 2**，stderr 里至少列出 2 行候选窗口标题；
- ④ **向后兼容**：不传 `-Session` 跑一次，exit 0、文件落盘。

## 4. 边界

- **只改 `scripts\capture-window.ps1`**（以及必要时它依赖的 helper）。不动 `handoff.mjs`、不动 `rotate.mjs`、不动会话配置；
- **绝对禁止**为截图去 `SetForegroundWindow` / `ShowWindow` / `Alt+Tab`——抢焦点是这条单要**消灭**的行为，不是它的手段；
- 不改 DSH 本体；不改 `logs\handoff` 的文件名规则（`<旧>-<新>-<YYYYMMDDHHMM>-winNN.png`）；
- 窗口最小化时允许 `PrintWindow` 截最小化窗口，**但不许为了截图把它还原**；
- 要协调找 01（`capture-window.ps1` 的调用方是 `handoff.mjs` 的 rotate 流程，改参数只加不减，不需要 00 改调用）。
