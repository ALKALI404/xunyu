## 1. 定位

主人真正读字的界面（窗口）+ 会说话会动作的外壳（身体）。**窗口是一等公民，莉莉丝是可选外设**：外设没开是预期状态，不是故障。

## 2. 边界

- **属于我**：`E:\DeepFish\avatar\`（`relay.mjs`、`body-service.mjs`、`window\`、`mod\`、`state\`、`chat-window.ps1` 旧版）、端口 9334 / 9335 / 9333。
- **不碰**：`bridge.js`（本体）、`supervisor.ps1`（03）、`workdesk*`（04）。要改走工单。

## 3. 架构

```
本体/DSH
  ↕ relay 9334（relay.mjs，本地环形缓冲 + 行号持久化）
窗口 window\XunyuChatWindow.exe（C#，主界面）
  ↕ body 9335（body-service.mjs：适配器 + 能力表 + 单飞队列 + 令牌鉴权）
     └ adapter: lilith → 游戏 mod 9333（Lilith.exe；或 noop 适配器）
```

- **窗口不直连 DSH**，一律经 relay；**上层动身体一律走 9335**，不直连 mod（换身体只换适配器）。
- 单飞队列：同一时刻只让一个动作进去，`QUEUE_LIMIT` 满就排队；`/health` 里能看到 `queue.depth / byRole / arb`。

## 4. 数据流

| 方向 | 路径 | 花钱 |
|---|---|---|
| 窗口读 | 窗口 → `GET 9334/lines?after=<lineSeq>` → 增量行 | 否 |
| 主人说话 | 窗口 → `POST 9334/chat` → relay → bridge / body | 起回合才花 |
| 审批卡 | 窗口 → `GET 9334/pending` → 9335…… → bridge `/api/dsh/pending` | 否 |
| 身体动作 | relay → `POST 9335/say|anim|emotion|dialogue` → adapter → mod 9333 | 否 |

**游标必须是行号 seq**：`lineSeq` 落 `state\relay-lines.json`，跨重启只增不减（D9 修）；窗口手里攥着旧游标，服务端重启不许从 0 重开。

## 5. 接口

**relay 9334**（`relay.mjs`）

| 接口 | 方法 | 用途 |
|---|---|---|
| `/lines` | GET | 取增量行（`after`=行号） |
| `/chat` | POST | 窗口发一句给本体 |
| `/pending` · `/approve` | GET / POST | 审批与提问卡片、代批 |
| `/window` · `/window-presence` | GET/POST | 窗口在场登记 |
| `/rebind` | POST | 重绑会话 |
| `/health` · `/capabilities` · `/notice` | GET/POST | 自检、能力表、零 token 气泡 |
| `/pain/selftest` | POST | 疼痛链路演练口 |

> **窗口第三个页签「工作台」（2026-10-28 W-031 / D14i）**：只读看板，**直连 9340**（消费 `/api/agents`、`/api/worklist`、`/api/mail`），不经过 relay——上表**没有新增也没有改动**。实现见 `window\ChatWindow.cs`（`DeskBase` / `RefreshDesk` / `FillDeskAgents|Tasks|Mail` / `SetTarget("desk")`）。

**body 9335**（`body-service.mjs`）
| 接口 | 方法 | 说明 | 花钱 |
|---|---|---|---|
| `/health` `/capabilities` `/notice` | GET | 自检、契约能力数组、气泡 | 否 |
| `/state` | GET | 当前动画/情绪/队列（**需令牌**，历史里有对话原文） | 否 |
| `/say` `/anim` `/emotion` `/dialogue` `/notice` `/chatpanel` `/timer` `/cancelalarm` | POST | 动作；需 `x-body-token`，且按角色白名单（`state\body-tokens.json`）放行 | 否 |

**降级契约**（详见 `架构-窗口与身体.md`）：适配器掉线 → `200 {ok:true, degraded:true, spoke:false}`，**不许吐 502**。

## 9. 排障

| 症状 | 先看 | 命令 |
|---|---|---|
| 窗口白屏/不刷新 | relay 在不在、行号对不对 | `curl 127.0.0.1:9334/health`；看 `relay-lines.json` 是否倒退 |
| 窗口有字但不出声 | 身体与适配器 | `curl 127.0.0.1:9335/health` 看 `adapterOk / adapterDetail` |
| 动作被拒 403 | 令牌与角色白名单 | 日志 `[403]` 行；`body-tokens.json` |
| 动作排队不动 | 队列堵住 | `/health` 的 `queue.depth`、`/state` |
| 502 冒到对话上 | 违反降级契约（BUG） | 查 body 的 catch 分支是否漏了 health 探测 |

## 11. 视觉约定（2026-10-28 主人定）

### 11.1 主人原话（本节唯一依据）

> 「之后窗口非必要都做成暖白色加浅蓝和浅灰的主配色」
> —— 主人 2026-10-28 定；记录见 `records\工作日志.md` 18:20 条、06 邮件 seq=123。

拆成三条硬约定（拆解可以争，原话不能改）：

1. **主配色是三色一组**：暖白 + 浅蓝 + 浅灰，构成窗口整套主色，不是「暖白底随便点两笔」；
2. **分工**：暖白＝默认底，浅蓝＝强调（选中/按钮/链接），浅灰＝次级（次文字/分隔/排队态）；
3. **「非必要」**＝深色只在确有必要时才做；说不出必要在哪，就不做深色。
