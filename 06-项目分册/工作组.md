# 项目：工作组（workgroup）

> 状态：**稳定运行**（工号 00–05 + 本体）｜负责人：00（名册与交接）/ 01（调度）｜文档：05
> 职能划分口径在 `docs\工作组职能划分.md`，交接步骤在 `docs\交接流程.md`——**本文只引用不复写**。
> 任务状态机与派发细节在 `工作台-workdesk.md`，不在本文重复。

## 1. 定位

一群人（会话）替主人维护、开发本体，并且**出了事还找得到人**。
不是项目组、不是外包队：**工作组为本体服务，不是本体属于工作组**。

## 2. 边界

- **属于我**：`state\roster.json` + `records\ROSTER.md`（名册）、`state\worklist.jsonl`（台账）、`records\交付\`（交付物）、`records\工作日志.md`、`records\交接簿.md`、邮件池。
- **不碰**：业务代码（谁的地盘谁改）、`roles\`（人格，任何工号都不动）、系统配置（00 不动）。

## 3. 架构（谁在干什么）

| 工号 | 职能 | 主要产出 | 不碰 |
|---|---|---|---|
| 00 | 记录与交接 | 名册、交接稿、工作日志、周报、**执行换代** | 不写代码、不动配置 |
| 01 | 总务 / 调度 | 接活、路由、收作业（12:00 / 18:00）、跨部门串线 | 不做专业活 |
| 02 | 插件 | 装/升/卸、审源码、兼容性 | 不改插件业务代码 |
| 03 | 维护 | 守护、桥接侧、中继、窗口、端口、计划任务、备份 | 不改业务代码 |
| 04 | 代码 | 改 bridge/窗口/脚本、写工具、单测 | 不碰人格记忆 |
| **05** | **文档与架构**（2026-10-28 新设） | `docs\开发文档-运行逻辑.md` + `docs\projects\*`、校核 | **不改业务代码** |
| 06 | 验收（预留，未启用） | 按用例真跑、贴证据 | 不写实现 |

**并行上限 4**（01–04 计入，00/06 是支撑位不占）：见 `roster.json` → `parallelLimit`。
**cwd 一律 `<工作区>`**（本体用 `<Xunyu根>`）；动 `E:\DeepFish\*` 用绝对路径。

## 4. 数据流

```
主人 ──派单──▶ 本体 ──▶ 01（判断归谁 / 建台账 queued）
                          │  派发（唯一花钱：一次 session/prompt）
                          ▼
                       工号 doing ──交付 records\交付\<工号>-<日期>-<单号>.md──▶ 01 ──▶ 本体验收
                          │                                                      │
                          └─ 邮件池（默认通道，不花钱）                            └─ done
换代：到线（70 万）→ 00 建新会话/改名/投接班包/同步名册/归档旧会话
```

- **花钱**：只有 `dispatch`（起一轮 DSH 回合）。通知、催办、汇报一律走邮件池。
- 每个动作留痕：`state\worklist.jsonl`（台账）、`logs\dispatch.jsonl`（派发审计）、`records\工作日志.md`（人事）。

## 5. 接口（人怎么跟系统说话）

| 我想干的事 | 用什么 | 花钱 |
|---|---|---|
| 发通知 / 催办 / 汇报 | `node scripts\mail.mjs post --to NN --from XX --body "…"` | 否 |
| 看台账 | `node scripts\worklist.mjs list [--by 05] [--state queued]` | 否 |
| 起一件活 | `node scripts\worklist.mjs dispatch W-0xx`（**唯一花钱**） | **是** |
| 验收 / 退回 | `accept` / `reject` | 否 |
| 看谁在忙 | `http://127.0.0.1:9340/` | 否 |
| 换代 | `handoff.mjs`（00 专用，见 `交接流程.md`） | 否 |

## 6. 状态与存储

| 文件 | 是什么 | 谁改 |
|---|---|---|
| `state\roster.json` | 名册机器可读镜像 | 00 |
| `records\ROSTER.md` | 名册人读版，**冲突以它为准** | 00 |
| `state\worklist.jsonl` | 台账，append-only，回放得当前状态 | 01 / 系统 |
| `records\交付\` | 交付物，命名 `<工号>-<YYYYMMDD>-<单号>.md`，四段式 | 各工号 |
| `records\工作日志.md` | 六字段工作日志 + 每日团队日结 | 00 |
| `<Xunyu根>\memory\mail\mailbox.jsonl` | 邮件池（通道不是账本） | 全体 |

**不可逆**：归档会话（`handoff.mjs archive`）、改 `ROSTER.md` 历史段。归档前必须 `scan-stale-bindings`，活绑定非 0 不许归。

## 7. 依赖

- 依赖 DSH 的 `sessions.prompt`（派发）与 `sessions/list`（工作台投影）；DSH 挂 = 派不出去、看不到谁在忙（台账仍可读写）。
- 依赖邮件池文件可写；`worklist.jsonl` 损坏 = 回放失败（append-only 保证最多坏最后一行）。
- 被依赖：主人看进度靠工作台与日结。

## 8. 演进（归属要说清）

- **现在**：稳定，六工号 + 本体，并行上限 4 已满（`parallelLimit.atCap=true`）。
- **05 尚未进名册**：2026-10-28 新设，`state\roster.json` 与 `records\ROSTER.md` 里还没有 05 这一行——**这是 00 的活**，05 只报告不自改（已报 01 转 00）。
- **06 预留不启用**：现阶段本体验收 + 01 贴证据已够，启用条件由主人定。
- **换代线**：工作组提醒 50 万 / 换代 **70 万**；本体 80 万 / **95 万**（`state\context-budget.json`）。换代一律 00 执行，本体只验收（规则第七节）。
- 迁移/改动时要动：`roster.json` + `ROSTER.md`（两边同时）、`工作组职能划分.md`、`工作组必读.md` 的「谁读什么」。

## 9. 排障

| 症状 | 先看 | 命令 |
|---|---|---|
| 派活被拒 409 | 看码：`not-queued` 状态不对 / **`blocked` 前置没完成** / `target-busy` 目标在跑 | `worklist.mjs list --state queued` 看 `⏸ ← 等 W-xxx` |
| 派活被拒 429 | 今日配额（默认 20） | `worklist.mjs list` 首行配额 |
| 排队却不干 | 自动接力开关 / 退避 | `curl 127.0.0.1:9340/api/relay` |
| 交付没被认领 | 文件名不合规 → `unlinked` | 页面黄条；`records\交付\` 命名 |
| 名册与实际不符 | 两份名册是否同步 | 对比 `roster.json` 与 `ROSTER.md` |
| 到线没换代 | 谁该换 | `state\context-budget.json` 阈值；换代找 00 |

## 10. 维护

名册与交接：00。调度与收作业：01。文档：05。
**新工号/职能变更/换代 → 00 改名册并通知 05 同步本文 §3**；本文 §3 与 `roster.json` 冲突时以名册为准，05 立刻改本文。
