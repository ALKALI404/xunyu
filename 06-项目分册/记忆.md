# 项目：记忆（memory）

> 状态：**五套并存 · 收敛方案已交、数据未动**（D18 交付的是方案 + 实测盘点，一步没改库）｜负责人：04（实现）· 本体（内容）｜文档：05
> 归属目标（主人认可的方向）：**engram 主库 + markdown 摘要**，其余降为派生。
> 本文只写「记忆怎么流」，不写记忆里有什么（那是本体的私事）。

## 1. 定位

让鲟鱼记得住人：QQ/窗口的对话 → 归档 → 蒸馏 → 长期记忆；**人格与记忆属于本体，不属于任何工号**。
「规矩」不进记忆（只进 `rules\`），因为规矩是用来执行的，不是用来回忆的。

## 2. 边界

- **属于我（数据面）**：`<Xunyu根>\memory\`、`<Xunyu根>\daily\`、`E:\DeepFish\History\qq-memory\`、`E:\DeepFish\avatar\memory-pipeline\`、三个计划任务（`XunyuMemoryDaily/Catchup/Backup`）。
- **不碰**：`roles\`（人格）——**任何工号都不许改**；`long-term.md` 的结论性内容（由管线+本体定）。
- **不做**：不替主人决定记什么、不把私事拿去当谈资（底线见人格块）。

## 3. 架构（五套，各管一段）

| # | 那一套 | 落盘 | 谁写 | 频率 |
|---|---|---|---|---|
| 1 | **engram**（MCP 记忆库） | `Xunyu\memory\engram\*.db`（user / project×2 / shared + wal） | DSH 的 engram MCP（`engram_save/search/…`） | 实时，按需 |
| 2 | **markdown 主档** | `Xunyu\memory\`：`long-term.md`、`diary-*.md`、`digest.md`、`snapshot.md`；子目录 `inbox/ distill/ diff/ weekly/ topics/ archive/ rules/ state/ mirror/` | `memory-pipeline.mjs` | daily / weekly / catchup |
| 3 | **QQ 归档喂料** | `History\qq-memory\`（`feed-state.json` 存水位，`archive\` 存 messages） | bridge 的 `memory-feed.js` | **每分钟** |
| 4 | **每日总结** | `Xunyu\daily\YYYY-MM-DD.md` | `XunyuMemoryDaily`（23:30） | 每天 |
| 5 | **管线本体** | `avatar\memory-pipeline\memory-pipeline.mjs` | 04 | 被 3/4 调用 |

**管线四个阶段**（源码头部注释即文档，`memory-pipeline.mjs:4-12`）：
`ingest`（把 QQ/窗口两条来源按天搬进 `inbox`，带水位、幂等）→ `daily`（distill 带原文指针 → diff 只出增删 → 日记 ≤10 行）→ `weekly`（周蒸馏 ≤50 行 → 合并进 `long-term.md` ≤200 行，超限归档最不影响的）→ `catchup`（今天没跑过就补跑）。

**三档标记**：你说的（逐字）/ 我说的（判断）/ 规矩（只进 `rules\`，永不进记忆）。

## 4. 数据流

```
QQ/窗口对话 ──每分钟──▶ History\qq-memory（feed-state 水位）
History\chats\*.jsonl ──ingest──▶ memory\inbox
       └─ daily ─▶ distill（带原文指针）+ diff ─▶ Xunyu\daily\*.md
       └─ weekly ─▶ long-term.md（≤200 行，旧的进 archive）
DSH 会话 ──engram MCP──▶ memory\engram\*.db（实时，与上面并行）
备份：XunyuMemoryBackup（00:10）→ memory-backup\
```

**花钱**：蒸馏允许调模型，单次上限 **¥0.5**（`DISTILL_BUDGET_CNY`）；超预算降级为纯规则抽取（0 成本，但会失真）。**保真优先**——省钱的代价是失真。

## 5. 接口

| 入口 | 形态 | 说明 | 花钱 |
|---|---|---|---|
| `memory-pipeline.mjs --stage=daily\|weekly\|ingest\|catchup [--date=] [--dbg]` | CLI | 管线唯一入口 | 可能（蒸馏） |
| `bridge GET /api/memory/feed` | HTTP | 触发一次 QQ 归档喂料 | 否 |
| engram MCP（`engram_*`） | MCP 工具 | 实时读写记忆库 | 否（本地） |
| 邮件池 `scripts\mail.mjs` | CLI | 通道，不是记忆 | 否 |

## 6. 状态与存储

- **水位**：`History\qq-memory\feed-state.json`（喂到哪条）、`memory\state\`（管线进度）。水位丢了会重复 ingest（幂等，不会重复写内容）。
- **不可逆**：`weekly` 合并进 `long-term.md` 时超 200 行会**归档删除**「最不影响判断的」——这是设计，不是 bug，但改动阈值要报主人。
- 备份：`Xunyu\scripts\memory-backup.ps1`（00:10，`XunyuMemoryBackup`）→ `memory-backup\`。

## 7. 依赖

- 依赖 `History\chats\*.jsonl`（bridge 落盘）；bridge 停 = 没有新料，管线空转不报错。
- 依赖计划任务活着（`XunyuMemoryDaily/Catchup/Backup`）；计划任务挂了 → `memory\state` 里的日期会露馅。
- 被依赖：本体每次开场的记忆注入（profile + 检索）；`qq-extras` 的记忆通道。
- **五套并存 = 已知债**：同一条事实可能三处不同版本，冲突时以 `long-term.md` 与 engram `user` 库为准，其余是派生。
