## 写分册的硬要求

1. 用 `_模板.md` 的十节，**§8 演进必填**：现在独立还是隶属、将来归谁、迁移动哪些文件；
2. **归属变化是最大的债**：工作台→avatar、桥接守护→疼痛，这类变化必须当天写进对应分册；
3. 分册之间只许互相引用，不许复制内容（复制就会分叉）；
4. 改代码不改分册 = 没交付。

## 项目台账（机器可读，2026-10-28 D42）

`state\projects.json` 是「项目 → 子功能 → 单号」的**唯一真相**，05 维护，工作台项目视图（D43）消费。

**登记规则**：新增项目/子功能**当天**登记；一个分册 = 一个项目；`features[].tickets` 存单号（`D41`/`W1`），不存 `W-xxx`；`state` 只许 `active|planned|paused|done`；**进度不写进 json**（由 worklist 现算）。
**自检**：`node tmp\projects-check.mjs`（查 JSON 合法、单号在台账里查得到、单号不跨 feature 重复、每份分册都有对应项目、doc 路径存在），退出码 0 才算登记有效。
